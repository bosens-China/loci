# 页面发现与抓取优先级

Loci 接受任意一个公开文档页面作为入口。同步时，它会优先采用站点提供的结构化信息，让收录结果更接近文档站本身的组织方式。

## 识别顺序

| 优先级 | 识别结果                | 收录方式                                            |
| ------ | ----------------------- | --------------------------------------------------- |
| 1      | 公开 GitHub 仓库        | 收录默认分支中的 Markdown。                         |
| 2      | 有效的 `llms.txt`       | 只收录清单列出的页面。                              |
| 3      | OpenAPI 或 Swagger 文档 | 将接口说明整理为 Markdown。                         |
| 4      | 普通文档站              | 优先读取 Sitemap；没有可用 Sitemap 时跟随文档链接。 |

例如，站点同时提供 `llms.txt` 和 Sitemap 时，Loci 只使用 `llms.txt`。接口文档没有可用的 OpenAPI 规范时，会继续按普通网页收录。

## 可收录的文档来源

### GitHub 仓库

将公开仓库地址作为入口时，Loci 会保留 Markdown 的目录结构，并改写相对文档和图片链接，使它们可以继续访问对应版本的仓库内容。

当前只支持公开仓库的默认分支。不支持私有仓库、Git LFS、Git clone、子目录范围和 MDX。每次成功同步会更新为仓库当前的 Markdown 快照；同步失败时保留已有内容。

### `llms.txt`

非 GitHub 仓库会优先检查站点根目录的 `/llms.txt`。命中有效清单后，Loci 只收录清单中的同站页面，不再从 Sitemap 或页面链接扩展范围。

### OpenAPI 与 Swagger

输入 Swagger UI、Knife4j、ReDoc、FastAPI `/docs` 或常见 OpenAPI 地址时，Loci 会尝试发现同站规范，并将接口、参数、请求体、响应和数据模型整理为 Markdown。

## 控制收录范围

文档源的入口 URL 决定站点。创建时可通过以下参数控制收录量：

| 参数                     | 用途                                            |
| ------------------------ | ----------------------------------------------- |
| `--scope <path>`         | 只收录指定路径，例如 `/guide`。                 |
| `--page-limit <number>`  | 限制最多收录的页面数。                          |
| `--exclude-path <regex>` | 排除 URL 路径匹配的页面，例如不需要的语言目录。 |

范围同时适用于清单、Sitemap 和页面链接。缩小范围或启用排除规则后，已不在范围内的文档会在同步时移除。

## 选择抓取方式

默认的 `auto` 模式会根据页面是否需要 JavaScript 渲染选择 HTTP 或浏览器。普通文档站通常不需要额外安装浏览器；遇到渲染不完整的页面时，运行：

```bash
loci browser install
```

也可以在创建或更新文档源时，显式选择 `http` 或 `browser`。

## 同步结果

同步会更新仍在范围内的已有页面，并收录新发现的页面。页面明确返回 404 或 410 时，Loci 会移除对应的旧文档；图片、视频、字体等二进制资源不会作为独立文档保存。

需要设置范围、页面上限或抓取方式时，请查看[本地文档库](/cli/commands/local-library)。
