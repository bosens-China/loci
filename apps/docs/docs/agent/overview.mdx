# 接入 Agent

Loci 为 Agent 提供本地技术文档的查询能力。MCP 用于直接调用工具，`use-loci` Skill 用于选择通道并执行检索流程，全局规则用于在每个项目中保持相同的来源优先级。

## 能力分工

| 能力             | 解决的问题                                       | 是否必需 | 推荐用途                                       |
| ---------------- | ------------------------------------------------ | -------- | ---------------------------------------------- |
| MCP              | 让 Agent 发现和调用 Loci 工具。                  | 可选     | 支持 MCP 的客户端首选，调用最直接。            |
| `use-loci` Skill | 选择 MCP 或 CLI 通道，并组合检索步骤和安全边界。 | 可选     | 需要稳定技术文档工作流，或客户端只支持 Skill。 |
| 全局规则         | 为 Agent 设置跨项目持续生效的文档查询顺序。      | 可选     | 规定 Loci 与其他文档来源的优先级。             |

MCP 和 `loci mcp call` 提供相同的 Loci 能力，只是调用方式不同。只配置 MCP 也可以正常使用；只有 Skill 时，Agent 会先判断 MCP 工具是否存在，不存在才按需安装和调用 CLI。全局规则本身不会安装 CLI。

Skill 与全局规则不互相依赖。Skill 根据任务匹配按需加载，适合封装具体工作流；全局规则在 Agent 会话中持续生效，适合表达稳定优先级。两者同时存在时，由全局规则统一规定文档来源顺序；Skill 被匹配或加载不代表其中的查询工具可以立即执行。

## 选择接入方式

- 客户端支持 MCP：安装 Loci CLI，并配置一个名为 `loci` 的 stdio MCP。
- 客户端只支持 Skill：安装 `use-loci`。Skill 会在技术文档任务中检测 MCP；缺少工具时，它会在取得许可后安装 CLI，并通过 `loci mcp call` 直接调用工具。
- 希望每个项目遵循同一来源优先级：在前两种方式的基础上，再配置用户级全局规则。

CLI 的 stdio MCP 是推荐入口。客户端会按需启动进程，无需维护常驻服务。同一个客户端只应保留一个名为 `loci` 的 MCP；如果改用 HTTP，先移除已有的 stdio 配置。

## 推荐配置

个人开发者通常按以下顺序接入：

1. 安装 CLI，并配置 stdio MCP。
2. 安装或引用 `use-loci` Skill，让 Agent 获得完整检索流程和 CLI 兜底能力。
3. 需要跨项目保持同一优先级时，再配置用户级全局规则。

```bash
npm install --global @boses/cli
loci mcp configure codex
loci skills add
loci mcp rules codex
```

上例以 Codex 为例。其他客户端的 MCP 写入方式请查看[通过 MCP 接入](/agent/mcp)，Skill 的安装目录和管理命令请查看[使用 use-loci Skill](/agent/skill)，全局规则的客户端差异请查看[配置全局规则](/agent/global-rules)。

## 一次典型查询

配置完成后，Agent 会先判断任务是否依赖开发者技术文档。新闻、价格、人物或公司信息、购物旅行、法律医疗和普通网页内容等非文档任务直接使用对应来源，不先查询 Loci。技术文档任务通常按以下流程执行：

1. 列出本地文档库，确认目标技术和版本。
2. 本地存在可用文档时，查看一至两层目录，了解主题结构和文档语言。
3. 直接读取明确文件，或使用准确关键词搜索，再根据完整小节回答。
4. 本地没有可用文档时，查询只读的云端公开目录。
5. 云端存在可用快照时，说明来源并询问用户是否拉取。
6. 云端没有可用快照、用户不选择拉取或拉取失败时，确认官方入口并另行询问是否抓取。
7. 只有用户拒绝官方抓取、已授权获取失败或获得的证据仍不足时，才切换到 Context7、定向网页检索或允许的其他文档来源。

查看目录后再搜索，可以减少无关结果。API 名称、配置键、命令和错误原文应保持原样；概念性关键词则使用文档本身的语言。

## 写操作边界

列出本地文档库、查询云端公开目录、搜索和读取文档属于只读操作。云端拉取、新增文档源、主动同步和删除会修改本地状态。Skill 或全局规则应要求 Agent 在执行写操作前取得用户授权；用户当前请求已经明确要求该操作时，无需重复确认。

用户拒绝云端拉取不代表已经授权抓取官网，两个操作需要分别确认。同一文档库被多个 Agent 或 CLI 进程同时同步时，Loci 会复用已有任务和进度；不同文档库仍可独立执行。
