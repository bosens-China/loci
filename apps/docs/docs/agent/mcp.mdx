# 通过 MCP 接入

模型上下文协议（Model Context Protocol，MCP）让 Agent 直接使用 Loci 的文档发现、搜索、阅读和管理工具。Loci 面向本机 Agent 统一使用 CLI stdio：客户端按需启动进程，不需要维护常驻 MCP 服务或固定端口。

## 快速配置

先安装 CLI：

```bash
npm install --global @boses/cli
```

交互终端可以选择客户端并预览写入内容：

```bash
loci agent configure
```

Codex、Cursor、VS Code、Claude Code 和 Google Antigravity 都使用同一个 stdio 命令。可信的自动化环境需要显式指定客户端并传入 `--yes`：

```bash
loci agent configure codex --yes
loci agent configure cursor --yes
loci agent configure vscode --yes
loci agent configure claude-code --yes
loci agent configure antigravity --yes
```

写入后，新建一个 Agent 会话，使客户端重新加载 MCP 配置。

## 手动配置

未内置的客户端可以打印通用配置：

```bash
loci agent print-config generic
```

目标文件已有其他 MCP 服务时，只添加 `loci`，不要覆盖整个文件：

```json
{
  "mcpServers": {
    "loci": {
      "command": "loci",
      "args": ["mcp", "stdio"]
    }
  }
}
```

Google Antigravity 的本地 MCP 配置同样使用 `command` 和 `args`。Loci 会把配置合并到 `~/.gemini/config/mcp_config.json`；也可以先运行下面的命令查看待复制内容：

```bash
loci agent print-config antigravity
```

项目级 MCP 配置会启动本地命令，只应在信任项目时使用。

## 运行语义

Agent 调用 Loci 工具时，客户端启动 `loci mcp stdio`；会话结束后 stdio 进程随之退出。同步写操作进入共享的 SQLite 持久任务队列，并由该进程的轻量 worker 执行；如果后台服务已经认领同一来源，当前进程会等待并读取同一任务的最终结果。

`loci service start` 启动的是不监听 HTTP、也不承载 MCP 的常驻 worker。定时计划和云端每日同步在开启时会自动准备它；普通后台同步使用队列空闲后自动退出的按需 worker。

## 排查连接

如果客户端没有显示 Loci 工具：

1. 运行 `loci agent print-config <client>`，确认客户端格式和配置路径。
2. 确认 `loci` 在客户端进程的 `PATH` 中。
3. 在终端运行 `loci mcp stdio`，确认没有启动错误；测试结束后按 `Ctrl+C`。
4. 重新运行 `loci agent configure <client> --yes`，替换旧配置并新建 Agent 会话。
