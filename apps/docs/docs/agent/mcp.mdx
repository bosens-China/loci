# 配置 MCP

模型上下文协议（Model Context Protocol，MCP）让 AI 客户端调用 Loci 工具。配置完成后，AI 可以发现文档库、查看目录、搜索正文、读取小节，并在获得授权后拉取、添加或同步内容。

## 选择连接方式

| 入口      | 适用场景                                         | 运行方式                   |
| --------- | ------------------------------------------------ | -------------------------- |
| CLI stdio | Codex、Cursor、VS Code、Claude Code 等本机客户端 | 客户端按需启动，推荐使用。 |
| 桌面 HTTP | 已经常驻运行 Loci 桌面应用                       | 连接本机 HTTP 地址。       |
| CLI HTTP  | 没有桌面应用的服务器或前台服务环境               | 先运行 `loci mcp serve`。  |

传输方式不会改变工具名称和能力。个人开发环境优先选择 stdio，因为它不需要管理常驻端口。

## 配置客户端

先安装 Loci CLI：

```bash
npm install --global @boses/cli
```

Codex、Cursor、VS Code、Claude Code 和 Google Antigravity 都可以自动写入配置。以下命令以 Codex 为例：

```bash
loci mcp configure codex
loci mcp status
```

交互终端会在写入前展示目标客户端、传输方式、首选命令和回退文件。可信的自动化环境可以使用 `--yes` 跳过确认。

一键配置默认先调用客户端命令。命令未安装、超时、执行异常或返回失败状态时，Loci 会读取对应用户级配置，只新增或替换名为 `loci` 的服务；Antigravity 没有对应命令，因此直接写文件。

| 客户端             | 用户级回退文件                     | 服务位置             | HTTP 地址字段 |
| ------------------ | ---------------------------------- | -------------------- | ------------- |
| Codex              | `~/.codex/config.toml`             | `[mcp_servers.loci]` | `url`         |
| Cursor             | `~/.cursor/mcp.json`               | `mcpServers.loci`    | `url`         |
| VS Code            | 默认用户 Profile 的 `mcp.json`     | `servers.loci`       | `url`         |
| Claude Code        | `~/.claude.json`                   | `mcpServers.loci`    | `url`         |
| Google Antigravity | `~/.gemini/config/mcp_config.json` | `mcpServers.loci`    | `serverUrl`   |

文件不存在时会创建父目录与配置文件。文件存在时，JSON/JSONC 合并会保留注释、尾逗号、其他服务和顶层设置；Codex 只替换 `[mcp_servers.loci]` 及其子表。原文件无法解析、目标容器不是对象、Codex 存在重复或冲突定义时会停止并保留原文件。VS Code 使用多个 Profile 时，命令仍是首选；只有命令失败后才写入默认用户 Profile。

MCP 配置只负责连接工具。需要让 Agent 在所有项目中优先使用 Loci 时，还应[配置客户端全局规则](/agent/global-rules)。

Google Antigravity 仅支持 HTTP，可以一键写入：

```bash
loci mcp configure antigravity
```

Kimi Code 或其他未内置的客户端可以打印通用 `mcpServers` 配置：

```bash
loci mcp config
```

通用 stdio 配置如下：

```json
{
  "mcpServers": {
    "loci": {
      "command": "loci",
      "args": ["mcp", "stdio"]
    }
  }
}
```

如果目标配置已经包含其他 MCP 服务，只合并 `mcpServers.loci`，不要覆盖整个文件。项目级配置可以启动本地命令，只应在信任该项目时使用。

## 使用 HTTP

桌面应用运行期间会自动提供本机 HTTP MCP。没有桌面应用时，可以在一个终端启动 CLI 服务：

```bash
loci mcp serve
```

再在另一个终端配置客户端：

```bash
loci mcp configure codex --transport http
```

默认服务地址为 `http://127.0.0.1:<mcp-port>/mcp`。该地址只供本机客户端使用；停止桌面应用或按 `Ctrl+C` 结束 CLI 服务后，HTTP MCP 将不可用。

## MCP 提供的能力

Loci 工具可以分为四组：

- 发现：列出本地文档库和云端公开库。
- 定位：查看目录树，或按一组关键词搜索正文；严格搜索无结果时自动放宽。
- 阅读：批量读取 Markdown 文件或搜索命中的完整小节。
- 管理：添加、拉取、同步、查询同步状态、分页查看失败详情和删除文档库。

列出本地文档库、查询云端公开目录、查看目录、搜索和读取都可以直接调用。云端拉取、新增抓取、主动同步和删除可能访问网络或修改本地状态，应由用户当前请求或明确确认分别授权；用户拒绝云端拉取不等于授权或拒绝抓取官网。

### 添加范围与抓取上限

`loci_add_library` 使用与 CLI、桌面相同的产品基础默认值：`mode: auto`、`page_limit: 1000`、`scope_path: /`，HTTP 与浏览器并发以及 GitHub 大小上限默认继承全局设置。Agent 知道目标文档路径或任务规模时，可以在本次调用中覆盖名称、抓取方式、页面上限、路径范围、两种并发和 GitHub ZIP/Markdown 大小上限。

CLI 可以记住用户上次创建时的安全偏好，MCP 不读取这些交互偏好。MCP 省略参数时始终使用上述产品基础值，避免 Agent 行为受到上一次终端操作影响。两种入口共享业务字段的含义、边界、继承方式和最终规范化；CLI 的确认与前台/后台选项、MCP 的批量、分页、结构化输出和等待开关可以不同。

GitHub 仓库从任何入口创建或更新时，输入都会统一按 `auto` 和根路径规范化；页面并发和网页路径范围不参与 GitHub 同步。

网页库按“域名 + 收录路径”复用。同一域名和同一路径不会重复建库；同一站点的 `/router/latest/docs` 与 `/query/latest/docs` 可以分别建立文档库，避免一次抓取整个站点。

### 搜索放宽与路径过滤

`loci_search_files` 先要求全部词命中；没有结果时自动改为任意词命中，仍无结果时再匹配标题和 URL 路径。每组结果通过 `retrieval_mode` 和 `fallback_used` 说明是否发生放宽。`path_prefix` 可以只保留某个 URL 路径下的文件，标题、路径和与建库入口相近的页面会得到轻量排序加权。

这套放宽使用 SQLite 全文索引和普通字符串匹配，不依赖嵌入模型。准确的 API 名、配置键和错误原文仍然是最有效的搜索词。

### 同步状态与渐进失败详情

文档库的 `availability` 只表示当前是否有可读文件：`usable` 或 `empty`；同步过程单独使用 `sync_status`。同步先返回失败总数、按原因统计和最多 5 条样例，不会把全部失败 URL 塞进一次响应。

需要完整详情时，使用同步状态中的 `run_id` 调用 `loci_list_sync_failures`，并通过 `offset`、`limit` 分页读取。实时进度仍用 `library_id` 调用 `loci_get_sync_status`；`run_id` 用于一次已经建立的同步记录和失败历史，不需要额外的 `sync_id`。

## 检查配置

写入配置后，新建 AI 会话，使客户端重新加载 MCP。然后执行：

```bash
loci mcp status
```

如果客户端没有显示 Loci 工具，继续运行：

```bash
loci doctor
```

重点检查 CLI 是否位于客户端的 `PATH`、配置中是否存在名为 `loci` 的服务，以及 HTTP 模式对应的宿主是否正在运行。

同一个客户端不要同时保留 stdio 和 HTTP 两个 Loci 入口。两种入口共享能力，重复注册只会让 AI 看到重名或重复工具。

## 重复调用与并发安全

`loci_sync_libraries` 会去重同一次请求中的文档库 ID。目标文档库正在同步时，后发调用会复用已有任务和进度。传入 `wait_for_completion: true` 可以等待该任务；无需等待时，使用文档库 ID 调用 `loci_get_sync_status` 查询状态。

桌面应用、CLI 和 MCP 共享数据目录时，跨进程锁和持久抓取记录会保护同一文档源。重复调用不会同时写入 SQLite；不同文档源仍可独立执行。

## CLI 命令速查

| 命令                          | 用途                                |
| ----------------------------- | ----------------------------------- |
| `loci mcp stdio`              | 通过标准输入输出启动 MCP。          |
| `loci mcp serve`              | 在前台启动本机 HTTP MCP。           |
| `loci mcp status`             | 显示传输方式、HTTP 地址和当前宿主。 |
| `loci mcp config [client]`    | 打印客户端配置，不修改文件。        |
| `loci mcp configure [client]` | 命令优先，失败时回退用户配置文件。  |
| `loci mcp rules [client]`     | 写入全局规则；Cursor 输出复制内容。 |

需要让 AI 遵循固定检索流程时，继续阅读[使用 Loci Skill](/agent/skill)。CLI 数据导入、导出和清理命令请查看[数据备份与运行环境](/cli/commands/integrations)。
