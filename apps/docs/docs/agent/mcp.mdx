# 通过 MCP 接入

模型上下文协议（Model Context Protocol，MCP）让 Agent 直接使用 Loci 的文档发现、搜索、阅读和管理工具。个人开发环境推荐使用 CLI stdio：客户端会按需启动进程，不需要维护常驻服务。

## 选择连接方式

| 入口      | 适用场景                                         | 运行方式                   |
| --------- | ------------------------------------------------ | -------------------------- |
| CLI stdio | Codex、Cursor、VS Code、Claude Code 等本机客户端 | 客户端按需启动，推荐使用。 |
| 本机 HTTP | 需要固定回环地址或多个客户端共享常驻入口的环境   | 由用户级后台服务提供。     |

两种方式提供相同工具。同一个客户端只保留一个名为 `loci` 的入口。

## 快速配置

先安装 CLI：

```bash
npm install --global @boses/cli
```

以下示例进入 Codex 配置子菜单；交互终端会继续询问传输方式并在写入前预览：

```bash
loci agent configure codex
loci mcp status
```

Codex、Cursor、VS Code、Claude Code 和 Google Antigravity 都支持一键配置。可信的自动化环境必须同时显式指定客户端、传输方式和 `--yes`：

```bash
loci agent configure cursor --transport stdio --yes
loci agent configure vscode --transport stdio --yes
loci agent configure claude-code --transport stdio --yes
loci agent configure antigravity --transport http --yes
```

写入后，新建一个 Agent 会话，使客户端重新加载 MCP 配置。

## 手动配置其他客户端

未内置的客户端可以先进入交互子菜单选择目标和传输方式：

```bash
loci agent config
```

非交互调用需要完整参数，例如 `loci agent config generic --transport stdio`。

通用 stdio 配置如下。目标文件已有其他 MCP 服务时，只添加 `loci`，不要覆盖整个文件。

```json
{
  "mcpServers": {
    "loci": {
      "command": "loci",
      "args": ["mcp", "stdio"]
    }
  }
}
```

项目级 MCP 配置会启动本地命令，只应在信任项目时使用。

## 使用 HTTP

需要 HTTP 入口时，先启用后台服务：

```bash
loci ui
```

再在另一个终端写入 HTTP 配置：

```bash
loci agent configure codex --transport http
```

默认服务地址为 `http://127.0.0.1:<mcp-port>/mcp`，只供本机客户端使用。HTTP MCP 与 Web UI、调度器共享同一个 runtime；浏览器关闭后仍可用。需要前台调试或容器运行时也可以执行 `loci service run`；`loci mcp serve` 作为独立兼容入口保留。

stdio、独立 HTTP MCP 和后台服务 MCP 的同步写操作都会进入同一持久任务队列。stdio/独立 HTTP 进程会同时启动轻量 worker，因此没有登录服务时也能完成任务；若后台服务已经认领同一来源，它们会等待并读取该任务保存的最终结果。

## 检查配置

如果客户端没有显示 Loci 工具，先执行：

```bash
loci mcp status
loci doctor
```

重点检查 CLI 是否在客户端的 `PATH` 中，以及后台服务是否仍在运行。同一个客户端不要同时注册 stdio 和 HTTP 两个 Loci 入口。
