# 通过 MCP 接入

模型上下文协议（Model Context Protocol，MCP）让 Agent 直接使用 Loci 的文档发现、搜索、阅读和管理工具。个人开发环境推荐使用 CLI stdio：客户端会按需启动进程，不需要维护常驻服务。

## 选择连接方式

| 入口      | 适用场景                                         | 运行方式                   |
| --------- | ------------------------------------------------ | -------------------------- |
| CLI stdio | Codex、Cursor、VS Code、Claude Code 等本机客户端 | 客户端按需启动，推荐使用。 |
| CLI HTTP  | 需要由本机前台服务提供 MCP 的环境                | 先运行 `loci mcp serve`。  |

两种方式提供相同工具。同一个客户端只保留一个名为 `loci` 的入口。

## 快速配置

先安装 CLI：

```bash
npm install --global @boses/cli
```

以下示例为 Codex 写入推荐的 stdio 配置：

```bash
loci agent configure codex
loci mcp status
```

Codex、Cursor、VS Code、Claude Code 和 Google Antigravity 都支持一键配置。可信的自动化环境可以添加 `--yes` 跳过确认。

```bash
loci agent configure cursor
loci agent configure vscode
loci agent configure claude-code
loci agent configure antigravity
```

写入后，新建一个 Agent 会话，使客户端重新加载 MCP 配置。

## 手动配置其他客户端

未内置的客户端可以先打印通用配置：

```bash
loci agent config
```

通用 stdio 配置如下。目标文件已有其他 MCP 服务时，只添加 `loci`，不要覆盖整个文件。

```json
{
  "mcpServers": {
    "loci": {
      "command": "loci",
      "args": ["mcp", "stdio"]
    }
  }
}
```

项目级 MCP 配置会启动本地命令，只应在信任项目时使用。

## 使用 HTTP

需要 HTTP 入口时，在一个终端启动服务：

```bash
loci mcp serve
```

再在另一个终端写入 HTTP 配置：

```bash
loci agent configure codex --transport http
```

默认服务地址为 `http://127.0.0.1:<mcp-port>/mcp`，只供本机客户端使用。按 `Ctrl+C` 结束服务后，HTTP MCP 将不可用。

## 检查配置

如果客户端没有显示 Loci 工具，先执行：

```bash
loci mcp status
loci doctor
```

重点检查 CLI 是否在客户端的 `PATH` 中，以及 HTTP 服务是否仍在运行。同一个客户端不要同时注册 stdio 和 HTTP 两个 Loci 入口。
