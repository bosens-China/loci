# 使用 Loci Skill

`use-loci` Skill 为支持 Agent Skills 的 AI 客户端提供一套技术文档检索流程。它不会启动服务，也不会替代 MCP；运行时仍通过名为 `loci` 的 MCP 调用真实工具。

## 适用场景

当问题依赖程序库、框架、SDK、API、CLI 或配置项的准确文档时，Skill 会指导 AI：

- 先确认当前项目使用的技术和版本；
- 优先查询已有本地文档库；
- 先看目录和语言，再直接读取或搜索；
- 本地缺失时，先查询只读的云端公开目录；
- 云端没有可用内容、用户不选择拉取或拉取失败时，再确认官方入口并询问是否抓取；
- 回答时附上文档的来源 URL，并区分文档事实与推断。

普通业务逻辑修改、通用编程概念和不依赖外部技术行为的代码审查，不需要触发该 Skill。

## MCP 与 Skill 的分工

MCP 提供可执行能力，Skill 提供使用方法。只有 MCP 时，AI 已经可以调用全部 Loci 工具；加入 Skill 后，AI 会采用更稳定的检索顺序，并遵守写操作确认、版本核对和来源判断等边界。

Skill 不保存文档，也不维护第二份同步状态。CLI、桌面应用、MCP 和 Skill 最终使用同一个本地知识库。

## 获取 Skill

Loci 仓库内的 Skill 位于 `.agents/skills/use-loci/`。将整个 `use-loci` 目录安装到 AI 客户端支持的 Skills 目录，并保留其中的 `SKILL.md`。

不同客户端的安装方式可能不同。安装后应确认客户端能够发现名为 `use-loci` 的 Skill；配置 MCP 的方法请查看[配置 MCP](/agent/mcp)。

## 如何触发

支持自动匹配的客户端会根据 Skill 描述，在技术文档任务中加载它。也可以在请求中显式指定：

```text
请使用 use-loci 查询当前项目版本对应的路由配置。
```

Skill 只影响当前匹配的任务，不会自动成为所有会话的全局规则。如果希望 Codex 在每个项目中都优先查询 Loci，应继续配置用户级 `AGENTS.md`。

## 检索与写操作

Skill 会优先执行只读步骤：列出文档库、查看目录、搜索和读取。以下操作会访问网络或修改本地数据库：

- 从云端拉取公开文档库；
- 添加并首次抓取官方文档源；
- 主动同步已有文档库；
- 删除本地文档库。

AI 应在执行这些操作前说明目标并取得确认。用户当前请求已经明确要求相同操作时，可以直接执行。云端拉取和官方抓取是两个独立选择；用户拒绝拉取不代表已经授权或拒绝抓取，AI 应另行询问。

## 与 AGENTS.md 配合

Skill 适合封装详细工作流，`AGENTS.md` 适合声明长期优先级。两者可以同时存在：

- `AGENTS.md` 规定何时优先使用 Loci，以及何时切换到其他来源。
- `use-loci` Skill 在具体任务中提供目录、搜索、阅读和同步步骤。

第三方文档 Skill 被匹配或加载不代表其中的查询工具可以立即执行。除非用户明确指定来源，否则应先完成 `AGENTS.md` 规定的 Loci 本地查询、云端发现和官方抓取询问；等待用户确认期间不调用其他来源。本地或云端未命中本身不构成兜底条件，只有用户拒绝官方抓取、已授权获取失败或所得证据仍不足时，才执行第三方 Skill 中的查询步骤。

Loci 不修改、删除或覆盖用户安装的第三方 Skill。两者出现冲突时，应由一套明确的 `AGENTS.md` 来源优先级统一编排，避免让 AI 同时执行互相矛盾的流程。Codex 用户可以直接使用[全局 AGENTS.md 模板](/agent/codex)。
