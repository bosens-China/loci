# 使用 Loci Skill

`use-loci` Skill 为支持 Agent Skills 的 AI 客户端提供一套技术文档检索流程。它不会启动服务，也不会替代 MCP；运行时仍通过名为 `loci` 的 MCP 调用真实工具。

## 适用场景

当问题依赖程序库、框架、SDK、API、CLI 或配置项的准确文档时，Skill 会指导 AI：

- 先确认当前项目使用的技术和版本；
- 优先查询已有本地文档库；
- 先看目录和语言，再直接读取或搜索；
- 本地缺失时，先查询只读的云端公开目录；
- 云端没有可用内容、用户不选择拉取或拉取失败时，再确认官方入口并询问是否抓取；
- 回答时附上文档的来源 URL，并区分文档事实与推断。

普通业务逻辑修改、通用编程概念和不依赖外部技术行为的代码审查，不需要触发该 Skill。新闻、价格、人物或公司信息、购物旅行、法律医疗和普通网页内容也不属于技术文档任务，应直接使用网页或对应领域来源。仅仅提到软件、公司或网页，不足以触发 Loci。

## MCP 与 Skill 的分工

MCP 提供可执行能力，Skill 提供使用方法。只有 MCP 时，AI 已经可以调用全部 Loci 工具；加入 Skill 后，AI 会采用更稳定的检索顺序，并遵守写操作确认、版本核对和来源判断等边界。

Skill 不保存文档，也不维护第二份同步状态。CLI、桌面应用、MCP 和 Skill 最终使用同一个本地知识库。

## 使用 CLI 管理 Skill

Loci CLI 内置完整的 `use-loci`，无需额外下载。最简命令会安装到用户级通用目录 `~/.agents/skills/use-loci`：

```bash
loci skills add
```

`add` 同时负责安装和更新。目录不存在时创建，已是最新时保持不变，由 Loci 管理但版本过期或有本地修改时，会在确认后整目录重新安装。它不会覆盖没有 Loci 所有权标记的第三方目录。

指定 Agent 客户端：

```bash
loci skills add --agent cursor
loci skills add --agent claude-code
loci skills add --agent all
```

项目级操作必须显式提供项目根目录，不会推断当前文件夹：

```bash
loci skills add --agent all --project /absolute/path/to/project
```

查看、删除和批量清理：

```bash
loci skills list
loci skills list --json
loci skills remove --agent cursor
loci skills remove --agent cursor --project /absolute/path/to/project
loci skills clear --agent all --yes
```

`remove` 和 `clear` 未传 `--project` 时只操作用户级全局安装。删除项目 Skill 必须始终指定项目路径。

## Agent 与安装路径

| Agent 参数    | 用户级全局目录            | 项目级目录                 |
| ------------- | ------------------------- | -------------------------- |
| `universal`   | `~/.agents/skills`        | `<project>/.agents/skills` |
| `codex`       | `~/.agents/skills`        | `<project>/.agents/skills` |
| `cursor`      | `~/.cursor/skills`        | `<project>/.cursor/skills` |
| `claude-code` | `~/.claude/skills`        | `<project>/.claude/skills` |
| `vscode`      | `~/.copilot/skills`       | `<project>/.github/skills` |
| `antigravity` | `~/.gemini/config/skills` | `<project>/.agents/skills` |
| `all`         | 上述目录去重后全部写入    | 上述目录去重后全部写入     |

Codex、通用目录和 Antigravity 项目目录可能指向相同物理路径。Loci 会自动去重，只保留一条安装记录。

## 在桌面应用中管理

桌面应用侧边栏的“Skills 管理”提供与 CLI 相同的安装台账和文件状态：

- 添加或重新安装 `use-loci`；
- 选择通用、Codex、Cursor、Claude Code、VS Code、Antigravity 或全部客户端；
- 默认安装到全局，项目安装通过目录选择器明确选择根目录；
- 查看最新、过期、修改、缺失和冲突状态；
- 删除单条安装，或清空所有 Loci 管理的全局 Skill。

CLI 与桌面使用同一个 SQLite 台账。手工删除目录后，列表会显示缺失；再次删除可清理失效记录。Loci 不会扫描、接管或删除第三方 Skill。

安装完成后还需要配置名为 `loci` 的 MCP，具体方法请查看[配置 MCP](/agent/mcp)。

## 如何触发

支持自动匹配的客户端会根据 Skill 描述，在技术文档任务中加载它。也可以在请求中显式指定：

```text
请使用 use-loci 查询当前项目版本对应的路由配置。
```

Skill 只影响当前匹配的任务，不会自动成为所有会话的全局规则。如果希望每个项目都优先查询 Loci，应继续[配置客户端全局规则](/agent/global-rules)。

## 检索与写操作

Skill 会优先执行只读步骤：列出文档库、查看目录、搜索和读取。以下操作会访问网络或修改本地数据库：

- 从云端拉取公开文档库；
- 添加并首次抓取官方文档源；
- 主动同步已有文档库；
- 删除本地文档库。

AI 应在执行这些操作前说明目标并取得确认。用户当前请求已经明确要求相同操作时，可以直接执行。云端拉取和官方抓取是两个独立选择；用户拒绝拉取不代表已经授权或拒绝抓取，AI 应另行询问。

## 与全局规则配合

Skill 适合封装详细工作流，全局规则适合声明长期优先级。两者可以同时存在：

- 全局规则规定何时优先使用 Loci，以及何时切换到其他来源。
- `use-loci` Skill 在具体任务中提供目录、搜索、阅读和同步步骤。

第三方文档 Skill 被匹配或加载不代表其中的查询工具可以立即执行。对于技术文档问题，除非用户明确指定来源，否则应先完成全局或项目规则规定的 Loci 本地查询、云端发现和官方抓取询问；等待用户确认期间不调用其他来源。本地或云端未命中本身不构成兜底条件，只有用户拒绝官方抓取、已授权获取失败或所得证据仍不足时，才执行 Context7、定向网页检索或其他文档来源。非文档任务不经过这条顺序。

Loci 不修改、删除或覆盖用户安装的第三方 Skill。两者出现冲突时，应由一套明确的全局规则统一编排来源优先级，避免让 AI 同时执行互相矛盾的流程。具体路径和一键写入方式请查看[配置客户端全局规则](/agent/global-rules)。
