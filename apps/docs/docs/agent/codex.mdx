# Codex 规则设置

Codex 会把用户级规则与项目规则合并。Loci 可以把跨项目检索流程写入 Codex Home，同时保留用户已有的其他规则。

如果还不熟悉 MCP、Skill 和全局规则的分工，请先阅读 [接入 Agent](/agent/overview)。其他客户端的路径请查看[配置 Agent 全局规则](/agent/global-rules)。

## 一键配置

先配置 MCP，再写入全局规则：

```bash
npm install --global @boses/cli
loci mcp configure codex
loci mcp rules codex
```

自动化环境可以跳过两次确认：

```bash
loci mcp configure codex --yes
loci mcp rules codex --yes
```

## 什么时候使用 Loci

全局规则只让开发者技术文档问题优先使用 Loci，例如库、框架、SDK、API、CLI、配置、迁移、版本差异、安装过程和技术专属错误。普通重构、业务逻辑调试和不依赖外部技术当前行为的代码审查不使用 Loci。

新闻、价格、人物或公司信息、购物旅行、法律医疗以及普通网页内容等非文档任务，直接使用适合该领域的网页或专业来源，不需要先经过 Loci。只有进入技术文档范围后，Context7、定向网页检索或其他文档来源才作为 Loci 流程满足兜底条件后的选择。

## 文件选择与升级

默认目标是 `~/.codex/AGENTS.md`。如果 `~/.codex/AGENTS.override.md` 已存在，Codex 会忽略同目录的普通文件，因此 Loci 会改为写入 override 文件。

Loci 只新增或替换下面两个标记之间的内容：

```md
<!-- loci:start -->

Loci 管理的规则
<!-- loci:end -->
```

区块之外的个人规则保持不变。

## 已有 Context7

如果 Codex 全局规则已经包含 Context7，运行下面的命令即可让 Loci 重新整理规则优先级：

```bash
loci mcp rules codex
```

Loci 会优先使用本地和官方技术文档，并只在需要时切换到 Context7。它只修改自己识别到的完整规则区块；无法安全合并时会停止写入，并提示你先手动整理规则。项目级 `AGENTS.md`、Context7 Skill 和其他个人规则不会被修改。

## 项目级规则

仓库根目录的 `AGENTS.md` 适合保存团队共享的构建、测试和代码规范。子目录可以继续放置 `AGENTS.md` 或 `AGENTS.override.md`，为局部模块提供更具体的规则。

Codex 启动时依次读取用户级文件、项目根目录以及当前工作目录路径上的规则。更靠近当前目录的内容后合并，因此可以覆盖更宽泛的指令。

## 检查结果

新建 Codex 会话后运行：

```bash
codex --ask-for-approval never "说明技术文档的查询流程，以及什么情况下切换到其他来源。"
```

预期回答会先判断问题是否属于开发者技术文档范围。属于时先查询 Loci 本地库，再查询云端公开目录，并在获得授权后拉取或抓取官方文档；只有 Loci 不可用、用户拒绝官方抓取、获取失败或证据仍不足时，才切换到 Context7、定向网页检索或其他文档来源。非文档任务应直接使用对应来源。
