# 配置 Agent 全局规则

MCP 让 Agent 调用 Loci 工具，全局规则则规定什么时候优先使用这些工具。Loci 为支持本机用户级文件的客户端一键写入规则；Cursor 使用 `~/.cursor/rules/loci.mdc`，不读取、修改或同步云端 User Rules。

## 职责边界

Loci 优先只适用于依赖开发者技术文档事实的问题，包括库、框架、SDK、API、CLI、配置、迁移、版本差异、安装过程和技术专属错误。进入这个范围后，Agent 才按本地文档库、云端公开目录、用户确认后的官方文档抓取顺序执行；满足明确兜底条件后，可以切换 Context7、定向网页检索或其他文档来源。

Loci 不是通用网页搜索的前置步骤。新闻与时效事件、价格、人物或公司信息、购物、旅行、法律、医疗以及普通网页内容等任务，应从一开始就使用适合该领域的网页或专业来源。仅仅提到软件、公司或网页，不代表任务属于技术文档范围。

## 客户端对照

| 客户端             | MCP 配置                            | 用户级全局规则                                 | 项目级规则                                     |
| ------------------ | ----------------------------------- | ---------------------------------------------- | ---------------------------------------------- |
| Codex              | `loci agent setup codex`            | `~/.codex/AGENTS.md`                           | 项目根目录或子目录的 `AGENTS.md`               |
| Cursor             | `loci agent setup cursor`           | `~/.cursor/rules/loci.mdc`                     | 项目根目录或子目录的 `AGENTS.md`               |
| VS Code            | `loci agent setup vscode`           | `~/.copilot/instructions/loci.instructions.md` | `AGENTS.md`、`.github/copilot-instructions.md` |
| Claude Code        | `loci agent setup claude-code`      | `~/.claude/CLAUDE.md`                          | `CLAUDE.md` 或 `.claude/CLAUDE.md`             |
| Google Antigravity | `loci agent setup antigravity`      | `~/.gemini/GEMINI.md`                          | `.agents/rules/`                               |
| Kimi Code          | `loci agent print-config`，手动复制 | `~/.kimi-code/AGENTS.md`                       | 由 Kimi Code 配置决定                          |
| 其他客户端         | `loci agent print-config`，手动复制 | 由目标客户端决定                               | 由目标客户端决定                               |

同一个客户端只保留一个名为 `loci` 的 stdio MCP。

## 使用 CLI 写入

运行对应命令：

```bash
loci agent rules codex
loci agent rules cursor
loci agent rules vscode
loci agent rules claude-code
loci agent rules antigravity
```

交互终端会先展示客户端和目标路径。可信的自动化环境可以添加 `--yes`：

```bash
loci agent rules codex --yes
```

Cursor 命令创建带 MDC frontmatter 的本机规则文件。该文件不会同步到 Cursor 账号，也不会修改 `Customize → Rules → User Rules` 中的云端内容。Kimi Code 或其他没有纳入一键接入的客户端，仍可复制客户端中立规则并粘贴到自己的用户级入口。

## 受管区块

Loci 写入的内容使用固定标记。中间内容由 Loci 自动生成，不需要手动复制：

```md
<!-- loci:start -->

...
<!-- loci:end -->
```

首次配置会创建文件或追加区块。再次配置只更新标记之间的内容，并保留区块之外的个人设置。标记缺失、重复或顺序错误时，Loci 会停止写入，请先手动修复文件。Cursor 的专用文件还必须包含合法 MDC frontmatter 和 `alwaysApply: true`。

重复运行同一命令是安全的。Codex 已经使用 Context7 时，Loci 也会按下文说明整理规则优先级。

## 验证与移除

配置完成后，新建 AI 会话，使客户端重新加载全局规则。确认客户端能够列出 Loci MCP 工具，再询问：

```text
请说明技术文档的查询顺序，以及什么情况下切换到其他来源。
```

预期回答会先查询 Loci 本地文档库，再查询云端公开目录，并在获得授权后拉取或抓取官方文档。如果回答没有采用该顺序，请检查目标文件中是否存在一组完整的 Loci 标记；Cursor 还应检查 `~/.cursor/rules/loci.mdc` 的 frontmatter。

还可以询问“搜索今天的行业新闻是否需要先查询 Loci”。预期回答应直接使用网页新闻来源，不查询或抓取 Loci。

需要同时移除 MCP、全局 Skill 和规则时，运行 `loci agent remove <client>`。命令只删除包括 `<!-- loci:start -->` 和 `<!-- loci:end -->` 在内的 Loci 受管区块，保留文件中的其他内容；标记异常时拒绝修改。Cursor 专用文件只剩 Loci 创建的标准 frontmatter 时会删除整文件，云端 User Rules 不会被修改。

## 各客户端注意事项

### Codex

先配置 MCP，再写入全局规则：

```bash
npm install --global @boses/cli
loci agent setup codex
```

默认目标是 `~/.codex/AGENTS.md`。如果 `~/.codex/AGENTS.override.md` 已存在，Codex 会忽略同目录的普通文件，因此 Loci 会改为写入 override 文件。

写入时，Loci 会检测成对的 Context7 标记和旧版 `loci-context7` 标记，并替换为“Loci 优先、Context7 兜底”的组合规则。无法安全识别边界时，Loci 会停止修改并提示手动整理。项目级 `AGENTS.md`、Context7 Skill 和其他个人规则不会被修改。

仓库根目录的 `AGENTS.md` 适合保存团队共享的构建、测试和代码规范。子目录可以继续放置 `AGENTS.md` 或 `AGENTS.override.md`，为局部模块提供更具体的规则。Codex 会依次合并用户级文件、项目根目录和当前工作目录路径上的规则；更靠近当前目录的内容优先级更高。

新建 Codex 会话后，可以运行以下命令检查结果：

```bash
codex --ask-for-approval never "说明技术文档的查询流程，以及什么情况下切换到其他来源。"
```

预期回答会先判断任务是否依赖开发者技术文档。属于该范围时，先查询 Loci 本地库，再查询云端公开目录，并在获得授权后拉取或抓取官方文档。只有 Loci 不可用、用户拒绝官方抓取、获取失败或证据仍不足时，才切换到其他来源。

### Cursor

Cursor 2.1 及以上版本会把用户主目录下的 `.cursor/rules` 纳入 Agent 上下文。Loci 创建 `~/.cursor/rules/loci.mdc`，写入 `alwaysApply: true` 和受管区块；重复配置保持幂等。如果已有专用文件缺少合法 frontmatter 或没有启用 `alwaysApply: true`，Loci 会报告冲突而不是猜测修改。

该入口只面向本机 Cursor Agent，不同步账号，也不覆盖云端 User Rules。Cursor 当前从工作区向父目录发现主目录规则，项目位于用户主目录之外时可能无法加载；Cloud Agent、Tab、Inline Edit 和 Bugbot 也不在本机规则承诺范围内。项目根目录和任意子目录仍可放置 `AGENTS.md`，用于项目级或目录级约束。

检测到 `~/.cursor/rules/context7.mdc` 或 Cursor Context7 Skill 时，Loci 会在自己的规则中加入“Loci 优先、Context7 兜底”的协调说明，但不会修改第三方文件。

### VS Code

Loci 创建专用的 `loci.instructions.md`，并写入 `applyTo: "**"`，使规则在所有工作区自动应用。VS Code 仍可通过 Settings Sync 同步用户指令文件。

### Claude Code 与 Antigravity

Claude Code 的 `~/.claude/CLAUDE.md` 和 Antigravity 的 `~/.gemini/GEMINI.md` 都会跨项目加载。Loci 只管理其中自己的标记区块。
