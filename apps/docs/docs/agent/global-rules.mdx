# 配置 Agent 全局规则

全局规则让 Agent 在具体 API、配置或迁移问题上先确认项目版本，再查询匹配的本地资料；报错排查、Issue、博客等非文档需求直接走搜索工具。Agent 通过 `loci read <targets...> --library <lib> --json` 核实正文后引用来源。缺库时核实官方文档 URL 后可直接运行 `loci fetch <url>` 抓取，已有库过时可直接运行 `loci update <lib>` 更新。`fetch` 和 `update` 默认异步返回，Agent 轮询 `loci status <lib> --json` 至终态，从 `error` 与 `failures` 查看原因。需要前台等待时加 `--wait`，需要取消时使用 `loci cancel <lib>`。完整流程见 [接入 Agent](/agent/overview)。

## 写入与检查

`loci setup <client>` 同步全局 Skill 和 Rules。只需规则时使用 `loci setup rules [client]`。此命令会请求确认，非交互运行时传入客户端和 `--yes`。

```bash
loci setup rules codex --yes
loci setup status codex --json
```

| 客户端             | 参数          | 全局规则文件                                                   |
| ------------------ | ------------- | -------------------------------------------------------------- |
| Codex              | `codex`       | `~/.codex/AGENTS.md`，已有 `AGENTS.override.md` 时优先写入后者 |
| Cursor             | `cursor`      | `~/.cursor/rules/loci.mdc`                                     |
| VS Code            | `vscode`      | `~/.copilot/instructions/loci.instructions.md`                 |
| Claude Code        | `claude-code` | `~/.claude/CLAUDE.md`                                          |
| Google Antigravity | `antigravity` | `~/.gemini/GEMINI.md`                                          |
| Pi                 | `pi`          | 默认 `~/.pi/agent/AGENTS.md`，优先写入 Pi 当前使用的规则文件   |

如用 `PI_CODING_AGENT_DIR` 指定了 Pi 的配置目录，请从设置了同一变量的环境启动 Loci CLI 或 Web。Loci 会按 Pi 的顺序选择已有的 `AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、`CLAUDE.md` 或 `CLAUDE.MD`。找不到规则文件时创建 `AGENTS.md`。 [Pi 配置文档](https://docs.pi.dev/latest/configuration#context-files)

## 更新与移除

规则区块以 `<!-- loci:start -->` 开始、`<!-- loci:end -->` 结束。重复同步会更新区块并保留个人指令；边界残缺、重复或逆序时，先修复标记再同步。Cursor 的规则文件需要有效的 MDC frontmatter 和 `alwaysApply: true`。Codex 和 Cursor 检测到受支持的 Context7 配置时，生成的规则会说明何时用它补查。

重新打开 Agent 会话后，可请求它查阅当前项目所用框架的某个 API，并检查回答引用的原文。需要移除该客户端的全局 Skill 与受管规则时执行以下命令。

```bash
loci setup remove codex
```
