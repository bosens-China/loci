# 基础命令与运行设置

本页介绍通用命令、浏览器运行时、共享设置和脚本运行环境。日常使用可以保留默认设置；遇到网站限流、抓取量较大或需要隔离数据时，再按需调整。

## 参数约定

命令用法中的 `<参数>` 为必填参数，`[参数]` 为可选参数。例如，`loci source sync [source]` 可以指定文档源，也可以省略后在终端中选择。

`[source]` 可以使用文档源名称、完整 ID 或唯一的短 ID。`[document]` 还可以使用文档标题或文档 URL。涉及删除、导入或清空数据的命令会要求确认；仅在自动化脚本中确认目标无误后，才使用 `--yes` 跳过确认。

## 基础命令

### `loci --help`

显示 CLI 的总帮助和可用命令分类。要查看某个子命令的参数，可在命令后追加 `--help`。

示例：

```bash
loci source add --help
```

### `loci --version`

显示当前安装的 CLI 版本。`-V` 是它的简写。

示例：

```bash
loci --version
```

### `loci status`

汇总本地文档源、云端副本、已收录文档、最近同步记录、MCP 状态和 Loci Server 地址。

示例：

```bash
loci status
```

### `loci update`

立即检查 npm 上是否存在更新的 Loci CLI 稳定版本，并显示当前版本和最新版本。

示例：

```bash
loci update
```

### `loci doctor`

检查 Loci 运行环境，并在发现问题时给出修复建议。

示例：

```bash
loci doctor
```

## 无头浏览器

当文档站需要 JavaScript 渲染时，CLI 会在 `auto` 检测或 `browser` 抓取前检查 Chromium headless shell。交互终端中可以确认并自动安装；非交互环境需要提前运行安装命令。

### `loci browser status`

检查无头浏览器是否已安装且可以启动。

示例：

```bash
loci browser status
```

### `loci browser install`

安装与当前 CLI 版本匹配的 Chromium headless shell。

示例：

```bash
loci browser install
```

### `loci browser uninstall`

删除由 CLI 管理的无头浏览器。默认会要求确认；`--yes` 可跳过确认。

示例：

```bash
loci browser uninstall
```

## 管理运行设置

设置保存在 Loci 本地数据目录中。CLI、stdio MCP 和 HTTP MCP 都会读取这些设置。

### `loci config list`

显示当前设置，包括云端文档库地址、抓取资源限制和 HTTP MCP 端口。

示例：

```bash
loci config list
```

### `loci config set [key] [value]`

修改一个设置。省略参数时，CLI 会在交互终端中选择设置项，并要求输入新值。

```bash
loci config set server-url https://your-loci.example.com
```

常用设置如下：

| 设置项                     | 用途                                   |
| -------------------------- | -------------------------------------- |
| `server-url`               | 指定云端文档库和 Admin API 的 Server。 |
| `mcp-port`                 | 指定本机 HTTP MCP 端口。               |
| `http-concurrency`         | 调整普通网页抓取的并发数。             |
| `browser-concurrency`      | 调整浏览器渲染页面的并发数。           |
| `max-retries`              | 调整页面抓取失败后的重试次数。         |
| `batch-interval-seconds`   | 降低连续抓取对目标站点的压力。         |
| `github-archive-limit-mb`  | 调整 GitHub 仓库下载大小上限。         |
| `github-markdown-limit-mb` | 调整 GitHub Markdown 文件的总量上限。  |

例如，遇到网站限流时，可以降低并发数或增加批次间隔：

```bash
loci config set http-concurrency 4
loci config set batch-interval-seconds 2
```

云端文档库地址的作用范围请查看[云端文档库](/cli/commands/cloud-library)。HTTP MCP 的启动方式请查看[通过 MCP 接入](/agent/mcp)。

## 隔离数据目录

测试、演示或自动化任务可以设置 `LOCI_DATA_DIR`，让当前命令使用独立的数据目录：

```bash
LOCI_DATA_DIR=./.loci-test loci status
```

日常使用不建议设置此变量，否则 CLI 与 MCP 可能读取不同的文档库。同一套自动化流程需要在每条相关命令中使用相同的数据目录。

## 处理脚本退出码

自动化脚本可以根据退出码判断结果：

| 退出码 | 含义                                 |
| ------ | ------------------------------------ |
| `0`    | 操作成功或用户主动取消。             |
| `1`    | 认证、网络或运行时错误。             |
| `2`    | 参数或用户输入错误。                 |
| `3`    | 操作完成，但存在页面失败或诊断异常。 |

涉及删除、导入或清空数据的非交互命令还必须显式传入 `--yes`。具体数据维护命令请查看[数据备份与清理](/cli/commands/data)。
