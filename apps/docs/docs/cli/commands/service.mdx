# 后台服务与 Web UI

`loci ui` 在当前终端启动前台服务，适合一次 Web 使用会话；用户级后台服务负责脱离终端执行定时计划、显式后台任务和云端副本检查。CLI 开启持久能力时会自动确保后台服务可用，Web UI 则在前台会话结束后按需交接。两种模式复用相同的本地数据库、任务队列和安全边界，同一数据目录同时只运行一个完整服务。

## 打开 Web UI

```bash
loci ui
```

命令会在当前进程启动完整本地服务，创建一次性浏览器会话，先打印带启动令牌的回环地址，再默认尝试打开一次系统浏览器。服务只监听 `127.0.0.1`，不会开放局域网访问。

命令会一直保持前台运行。关闭浏览器页面不会停止服务；在终端按 `Ctrl+C` 或向进程发送 `SIGINT`、`SIGTERM` 会关闭服务并使本次浏览器会话失效。浏览器启动器不可用或返回失败时，Loci 不会退出服务，可直接复制已经打印的地址手动打开。

Web UI 面向 PC / 笔记本浏览器，目前覆盖文档工作区（来源管理、搜索与阅读）、后台任务、公开云端目录、运行设置和备份恢复。依赖机器路径或敏感凭据的 Agent 配置、Skill 安装、服务治理、浏览器运行时安装和 Server 管理继续使用 CLI。

只需要输出访问地址而不尝试自动打开浏览器时：

```bash
loci ui --no-open
```

`--no-open` 只改变浏览器启动行为，服务仍会在前台保持运行直到用户终止。

同一数据目录已有用户级后台服务时，新的前台服务不会重复启动。先运行 `loci service stop`，再运行 `loci ui`；如果仍有定时抓取或云端每日同步，正常结束 Web 会话后会自动恢复已安装的服务。

## 管理服务

```bash
loci service status
loci service start
loci service stop
loci service restart
loci service logs
loci service logs --lines 100
loci service logs --follow
loci service disable
```

`start` 会安装并启动当前用户的登录自启动服务，适合手动恢复或提前准备后台环境。`loci schedule set`、`loci cloud pull --auto-sync`、`loci cloud auto-sync ... on` 和 Web UI 中新开启的持久能力都会自动完成对应激活。`stop` 停止当前登录会话中的服务但保留登录自启动定义；`disable` 同时移除登录自启动。已保存的计划和自动同步开关仍会保留，但服务停用期间不会执行；再次通过 CLI 开启持久能力会重新激活服务。Agent 的 stdio MCP 不依赖该服务。

`loci status` 会区分“无需运行”和“需要启动”，`loci doctor` 在持久能力缺少宿主时给出 `loci service start` 修复建议。自动激活失败时，原命令不会保存新的启用状态；Web UI 退出交接失败时已保存设置会保留，并在终端提示重试和日志命令。

`loci service logs` 默认显示每个后台日志文件最近 50 行；`--lines <number>` 调整行数，`--follow` 持续输出新增内容并在 `Ctrl+C` 后退出。日志尚未生成时会直接显示预期路径，方便检查服务配置和权限。

容器、临时数据目录或调试环境可以以前台方式运行：

```bash
loci service run
```

## 任务与计划语义

- CLI 前台/后台同步、前台 Web UI、用户级后台服务、stdio MCP 和定时计划都会写入同一个 SQLite 任务队列。
- 同一来源同时触发只保留一个活动任务并复用进度；不同来源可以并行。
- 终止 `loci ui` 时，运行中任务会释放或在租约过期后由后续 worker 恢复；连续中断达到上限后转为失败。
- 机器休眠、关机或服务停用期间不能按时执行。恢复后，同一计划错过的多个时间点合并为一次补跑。
- 后台 `auto` 或 `browser` 抓取需要 Chromium；缺少时先运行 `loci browser install`。

Web UI 使用一次性启动令牌交换 HttpOnly 会话，不把控制凭据写入浏览器存储。业务 API 校验本机 Host 与 Origin。
