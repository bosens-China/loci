# 本地文档库

以下示例中的尖括号需要替换为实际值。`<lib>` 可用库 ID、唯一短 ID 或名称。先用 `loci list --json` 找库，它会返回名称、ID、来源 URL、页数、语言和 `readOnly`。`loci list <lib> --json` 列出单库内的文档 ID、路径和标题。列表支持 `--offset <n>` 和 `--limit <n>`，查库时也可以用 `--query <kw>` 筛选。

## 分类与版本

`fetch`、`update` 支持 `--category <name>` 和 `--version <ver>`。新库默认使用 `未分类` 和 `latest`。更新已有库时保留未显式指定的分类和版本。同一来源的不同版本可以并存，相同来源与版本会复用。首次使用新分类名会自动创建分类。`list` 可组合使用名称搜索、分类和版本，后两项按标签精确匹配。

```bash
loci fetch https://react.dev --category 前端 --version v19
loci list --query react --category 前端 --version v19 --json
loci category list --json
loci category add 团队资料 --json
loci category delete 团队资料 --yes --json
```

`loci category` 默认列出分类和库数量。`未分类` 受保护。删除其他分类会将关联库设为 `未分类`，保留版本和正文。在 Web 工作台新建或编辑文档库时，可以选择已有分类、直接输入新分类名，并填写版本。卡片显示这两项信息，顶部分类筛选可与搜索词组合使用。

## 定位文档和小节

```bash
loci tree <lib> --json
loci tree <lib> --parent /guide --depth 2 --json
loci tree <lib> --query router navigation --all --json
loci search "router navigation" --json
loci search "页面离开前如何阻止导航" --library <lib> --content --json
loci search router navigation --library <lib> --path-prefix /guide --tree --json
```

`tree` 默认显示两层。`--parent <path|id>` 从指定目录展开，`--all` 显示完整深度。`--query <kw...>` 筛选关键词并保留命中文档的祖先目录。

`search <queries...>` 可输入多个查询，带空格的单组查询用引号括起。`--library <lib...>` 接受一个或多个库，省略时跨库搜索。普通结果提供 `hits`，每条命中含文档 ID、库 ID、库版本 `libraryVersion`、小节 ID、匹配段落和原文 `url`。有下一页时，在相同查询后加 `--offset <nextOffset> --page-token <nextPageToken>`。若后台更新改变了排序，命令会提示从第一页重新查询。`--tree` 返回 `total` 与按库组织的命中树。

已就绪的本机模型自动参与同一次搜索，关键词与模型分别定位小节，按文档和小节去重。每个模型对每组查询提供最多 10 个候选。组合命中的 `matchesFrom` 列出来源。同一篇文档可以命中多个小节。树形结果中，一个文件有多个命中小节时会返回 `sectionIds`。

`--content` 为当前页的普通搜索结果附上完整小节 Markdown 和标题路径 `headingPath`。也可以把命中的文档 ID 和小节 ID 传给 `loci read <文档 ID> --section <小节 ID> --json`，单独读取或续读。

### 可选本机检索模型

```bash
loci model list --json
loci model install minilm
loci model install bge-m3
loci model cancel bge-m3
```

也可以在本机 Web 的「设置与数据 → 检索模型」安装并查看进度。每个模型可独立安装，允许同时安装两个。安装会下载所选权重、分词器和共享的本机 CPU 推理组件，再为已有文档建索引。需要可用的 npm，支持 Apple Silicon Mac，以及 x64 或 ARM64 的 Windows 和 Linux。已建好索引的文章可立即参与向量搜索，全文搜索在建索引期间照常使用。短文整篇建立一条向量，长文优先按标题和段落切分。MiniLM 每段最多 512 个 token，BGE-M3 每段最多 8,192 个 token。原始 Markdown 完整保存。取消后可再次运行 `model install` 续传或继续建索引。正文更新后，下一次搜索通过后台续建受影响的索引。未安装模型时可直接使用全文搜索。

## 阅读正文

```bash
loci read <targets...> --library <lib> --json
loci read /guide /reference/hooks --library <lib> --max-chars 4000 --json
loci read <doc> --library <lib> --section <id> --json
```

每个位置参数都是文档完整 ID、唯一短 ID 或以 `/` 开始的文件或子树路径。`--library <lib>` 可限定解析范围。多个目标会去重并按目录树顺序返回。每篇默认最多读取 20,000 个 UTF-16 码元；需续读时将该条结果的 `nextOffset` 传给 `--offset <n>`，沿用文档 ID 及原小节。`url` 是可引用的原文地址。

## 创建与编辑

```bash
loci doc create <lib> --title "路由笔记" --path /notes/router --file ./router.md --json
loci doc update <doc> --library <lib> --title "新版路由笔记" --json
loci doc sections <doc> --library <lib> --json
loci doc section <doc> --library <lib> --action add --heading "版本差异" --level 2 --file ./changes.md --operation-id notes-v2 --json
loci doc section <doc> --library <lib> --action update --section <id> --content "更新说明" --json
loci doc section <doc> --library <lib> --action delete --section <id> --json
```

单篇编辑用文档 ID 或唯一短 ID。`create` 必须提供 `--title` 与 `--path`，`create` 和 `update` 可用 `--language <lang>` 标注语言。`--content <md>` 与 `--file <file>` 二选一。小节增删改后重新运行 `sections` 获取最新 ID；重试同一次小节操作时沿用 `--operation-id <id>` 和原始参数。

覆盖整篇或小节正文、删除小节时，CLI 会请求确认。已核对目标的非交互脚本传 `--yes`。Web 中的上述操作同样在提交前确认。

## 删除

```bash
loci delete <lib> --doc <targets...>
loci delete <lib>
```

带 `--doc` 会删除指定文档或子树，省略时会删除整库。命令会请求确认；已核对目标的非交互调用使用 `--yes`。整库和指定页面的抓取见 [页面发现与抓取](/cli/crawling)，清库和覆盖恢复见 [数据备份与恢复](/cli/commands/data)。
