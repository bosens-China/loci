# 数据备份与恢复

CLI 与 Web 设置页使用相同的 ZIP 备份格式。

## 导出

```bash
loci data export
loci data export ./frontend.zip --category 前端 移动端
loci data export ./selected.zip --library <库ID> --json
```

省略路径时，CLI 在当前目录生成带 UTC 时间的文件名。`--json` 返回文件路径和字节数。Web 设置页可以选择全部导出或按分类多选导出。

完整备份包含所有分类（含空分类）、库、文档、指定页面、抓取记录、失败详情、设置和域名策略。按分类或库导出时，归档收录任一条件命中的库及其关联数据。`index.json` 的 `scope` 分别为 `all` 或 `filtered`，并记录各数据文件的记录数、字节数和 SHA-256。

## 导入

```bash
loci data import ./frontend.zip
loci data import ./loci-backup.zip --replace-all --yes --json
```

默认合并导入。库 ID 相同，或来源身份和版本均相同时，先删除旧库及其全部内容，再恢复备份快照和全文索引。旧版只读快照按原服务器地址和远端库 ID 匹配，与同源可写本地库可独立保留。其他本地库、设置与域名策略保留。缺失分类自动创建。旧版 ZIP 中缺失或空白的分类归入 `未分类`，版本补为 `latest`。

`--replace-all`（Web 中的“清空并全量替换”）清空全部本地库后恢复备份。完整备份还会恢复设置和域名策略。范围备份只替换库和分类，保留本机全局设置与域名策略。Agent 的用户规则和 Skill 安装记录单独保存在本机。

交互终端会请求确认，已确认的脚本可加 `--yes`。摘要返回 `mode`、导入库总数 `importedLibraries`、其中覆盖的库数 `replacedLibraries`、文档数 `importedDocuments` 和新增分类数 `categoriesCreated`。

运行时校验归档路径、文件大小、校验和及数据引用，在维护锁和单个 SQLite 事务中恢复。相同文件和模式的并发导入共用一次恢复结果。如果其他抓取或维护正在占用数据库，等待其结束后重试。ZIP 及解压内容各限 512 MiB。

## 清空本地数据

```bash
loci data clear-documents
loci data clear-sources
```

- `clear-documents` 清空正文和全文索引，保留文档库、分类、版本、抓取记录与指定页面。以后更新 GitHub 库时会重新下载快照，即使提交 SHA 相同。旧审查库保留已批准的 URL。手工文档与旧只读快照的正文可以从备份恢复。
- `clear-sources` 删除全部文档库、正文、索引、抓取记录和指定页面，保留分类、设置、域名策略及 Agent 接入。
- Web 的设置页提供这两个操作。确认框显示库数和文档数。CLI 交互确认默认取消，已核对范围的非交互脚本可传 `--yes`。`--json` 输出 `scope`、实际删除的 `libraries` 与 `documents`。进行中的抓取或其他维护会阻止清空，同一清空范围的在途调用共享结果。

导出备份遇到同名文件时也会确认，脚本可以对已核对的目标传 `--yes`。Web 导入在选定 ZIP 后显示文件名和覆盖范围，确认后才恢复。
