# 页面发现与抓取

`loci fetch <urls...>` 从一个或多个 URL 建库或复用已有库。网页按 hostname 与收录路径组合确定来源，GitHub 按 `owner/repo` 确定来源。每个来源可分别保存 `latest`、`v18` 等版本。`fetch` 和 `update` 默认异步执行。每个库由独立的短生命周期进程负责，抓取结束后退出。命令在运行记录可查时返回；`--json` 向 stdout 输出启动结果数组，每项含 `libraryId`、`name`、`runId`、`status`、`reused` 及查询和取消命令。`reused: true` 表示复用了同库、同抓取类型及同目标的运行。后台请求遇到同库的其他抓取时会报告冲突，待当前任务结束后可重新提交。需要前台显示实时进度并等待最终结果时加 `--wait`，可按 `Ctrl+C` 取消。

## 选择收录范围

```bash
loci fetch https://rspress.rs/guide/ --scope /guide --inspect --json
loci fetch https://rspress.rs/guide/ --name rspress --scope /guide --page-limit 100
loci fetch https://rspress.rs/api/cli.html --to rspress --json
```

- `--category <name>` 与 `--version <ver>` 设置文档库分类和版本标签。新分类自动创建，新库默认使用 `未分类` 和 `latest`。更新已有库时保留未显式指定的分类和版本。同一来源按版本区分文档库。`loci list --category <name> --version <ver>` 可精确筛选。
- `--inspect` 探测发现方式、估计页数和路径分布。估计结果取决于站点提供的清单。
- `--scope <path>` 设置网页收录路径，默认为 `/`。`--exclude <pattern>` 用正则排除 URL 路径。`--page-limit <n>` 默认为 1,000。
- `--pages` 仅抓取给定 URL。`--to <library>` 把给定 URL 精确抓取到已有网页库。指定页可超出收录路径，仍需满足同一 hostname 与排除规则。同 URL 的手工文档会保留正文和索引，抓取结果仍显示远端页面是否存在。
- `--mode <mode>` 可选 `auto`、`http`、`browser`。普通网页在 `auto` 下优先利用本机已有能力，缺少浏览器时使用 HTTP。依赖客户端渲染时可先运行 `loci browser install` 再指定 `--mode browser`。

## 内容从哪里发现

| 来源 | 行为 |
| --- | --- |
| 公开 GitHub 仓库 | 从默认分支的提交归档中获取 Markdown/MDX，保留仓库路径；提交未变化时可复用快照。 |
| `llms.txt` | 先检查站点根目录的有效清单，按范围读取列出的页面。 |
| OpenAPI / Swagger | 带接口文档特征的入口可发现同站 JSON 规范，按概览、接口与数据模型生成 Markdown。 |
| 普通站点 | 使用有效 Sitemap 发现页面；缺少可用清单时从入口跟随同站链接。 |

GitHub 直接走仓库流程。GitHub/GitLab Pages 静态站点在检查 `llms.txt` 后使用网页流程。网页发现遵守 hostname、路径范围、排除规则和页数上限。旧版审查库的普通更新仅刷新已收录的 URL 和已登记的指定页面，不发现新链接。需要添加页面时可明确指定 URL。

## 刷新和诊断

```bash
loci update rspress --json
loci update rspress --pages https://rspress.rs/guide/introduction.html --json
loci status rspress --json
loci status --json
loci cancel rspress --json
```

`loci update [libraries...]` 接受一个或多个库，或单独用 `--all` 更新所有可写库。可显式修改 `--name`、`--scope`、`--exclude`、`--page-limit` 和 `--mode`。收窄路径或新增和更改排除规则时，CLI 会在保存配置前请求确认，因为保存可能立即清理旧正文、索引和指定页面。`fetch` 复用已有库时同样适用。已核对影响的非交互脚本可以传 `--yes`。

`status` 每次返回一份快照，轮询直到状态变为 `completed`、`completed_with_errors`、`failed` 或 `cancelled`。指定库会得到该库最近一次记录，尚未抓取时为 `null`；省略库会列出有记录的库。`progress` 包含发现数、处理数、成功数、失败数与当前 URL。`error` 给出运行错误，`failures` 最多列出 20 个失败页的 `url` 和 `message`。`loci cancel <library>` 等待目标抓取释放库锁后返回；抓取已经结束时返回 `cancelled: false` 和当前状态，库尚无抓取记录时状态为 `idle`。部分成功为 `completed_with_errors`，可读已成功提交的内容并按需重试失败页。
