# 页面发现与抓取

Loci 接受任意公开文档页面作为入口。同步时，它会优先使用站点提供的结构化信息，让本地文档尽量保持原站的组织方式。

## 两类文档来源

| 来源类型    | 入口                         | 收录方式                                 |
| ----------- | ---------------------------- | ---------------------------------------- |
| GitHub 仓库 | 公开 `github.com/owner/repo` | 收录默认分支中的 Markdown。              |
| 普通站点    | 任意公开文档页面             | 在站点内部自动选择结构化发现或网页发现。 |

GitHub 仓库直接进入仓库快照流程，不参与普通站点的 `llms.txt`、OpenAPI、Sitemap 或页面链接发现。Web UI 会明确区分这两类来源；CLI 和 Agent 工具可以只提供 URL，由 Loci 自动判断。

首次成功读取入口页后，Loci 会保存页面声明的网站图标 URL；没有声明时尝试站点根目录的 `favicon.ico`。本地文档库卡片会优先显示该图标，加载失败时回退到对应的来源类型图标，不额外下载或缓存图片文件。

## 普通站点发现顺序

| 优先级 | 识别结果                | 收录方式                                     |
| ------ | ----------------------- | -------------------------------------------- |
| 1      | 有效的 `llms.txt`       | 只收录清单列出的页面。                       |
| 2      | OpenAPI 或 Swagger 文档 | 将接口、参数和数据模型整理为 Markdown。      |
| 3      | 普通文档站              | 优先读取 Sitemap，否则跟随页面中的文档链接。 |

例如，站点同时提供 `llms.txt` 和 Sitemap 时，Loci 只使用 `llms.txt`。接口文档没有可用的 OpenAPI 规范时，Loci 会继续按普通网页收录。

## 支持的文档来源

### GitHub 仓库

将公开仓库地址作为入口时，Loci 会保留 Markdown 目录结构，并改写相对文档和图片链接，使链接继续指向对应版本的仓库内容。

当前只支持公开仓库的默认分支。不支持私有仓库、Git LFS、Git clone、子目录范围和 MDX。每次成功同步都会保存仓库当前的 Markdown 快照；同步失败时保留已有内容。

### `llms.txt`

非 GitHub 仓库会优先检查站点根目录的 `/llms.txt`。命中有效清单后，Loci 只收录清单中的同站页面，不再从 Sitemap 或页面链接扩展范围。

### OpenAPI 与 Swagger

输入 Swagger UI、Knife4j、ReDoc、FastAPI `/docs` 或常见 OpenAPI 地址时，Loci 会尝试发现同站规范，并将接口、参数、请求体、响应和数据模型整理为 Markdown。

## 控制收录范围

文档源的入口 URL 决定站点。创建时可以使用以下参数控制收录量：

| 参数                     | 用途                                            |
| ------------------------ | ----------------------------------------------- |
| `--scope <path>`         | 只收录指定路径，例如 `/guide`。                 |
| `--page-limit <number>`  | 限制最多收录的页面数。                          |
| `--exclude-path <regex>` | 排除 URL 路径匹配的页面，例如不需要的语言目录。 |

这些范围同时适用于清单、Sitemap 和页面链接。保存收窄的范围或新增、修改排除规则时，Loci 会在同一事务中立即删除不再匹配的正文和搜索索引；命中排除规则的显式页面目标也会被移除，后续整库同步不再刷新，不会等到下次同步。CLI、Web 和 Server Admin 会在交互式保存前说明这个影响；脚本和 Agent 必须把显式参数或写操作授权视为删除确认。

单个文档源还可以覆盖共享资源设置：

| 参数                             | 用途                                      |
| -------------------------------- | ----------------------------------------- |
| `--http-concurrency <number>`    | 覆盖普通 HTTP 页面并发数。                |
| `--browser-concurrency <number>` | 覆盖浏览器页面并发数。                    |
| `--archive-limit <size>`         | 覆盖 GitHub ZIP 上限，例如 `250mb`。      |
| `--markdown-limit <size>`        | 覆盖 GitHub Markdown 总量，例如 `120mb`。 |

普通站点使用前两项，GitHub 仓库使用后两项。省略时继承 `loci config` 的共享设置。

## 选择页面获取方式

`auto`、`http` 和 `browser` 只控制普通网页如何读取，不代表来源类型或页面发现方式。有效 `llms.txt` 和 OpenAPI 都直接使用 HTTP；GitHub 仓库使用仓库 ZIP 流程。

默认的 `auto` 模式只在本地浏览器已安装时比较第一个普通页面的 HTTP 与浏览器结果；未安装时直接使用 HTTP，不触发安装提示或浏览器页面探测。遇到 HTTP 渲染不完整的页面时，先运行：

```bash
loci browser install
```

也可以在创建或更新文档源时，显式选择 `http` 或 `browser`。

## 理解同步结果

同步会更新仍在范围内的已有页面，并收录新发现的页面。页面明确返回 404 或 410 时，Loci 会移除对应的旧文档。图片、视频和字体等二进制资源不会作为独立文档保存。

需要创建文档源或调整页面上限时，请查看[本地文档库](/cli/commands/local-library)。需要调整并发和重试设置时，请查看[基础命令与运行设置](/cli/commands/basics)。
