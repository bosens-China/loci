# 测试

在任务涉及新增、调整或审查前端测试时使用本规范。

## 放置测试

把测试放在被测模块目录下的 `test/` 子目录：

```text
utils/
├── formatAmount.ts
└── test/
    └── formatAmount.test.ts
```

使用项目现有测试运行器和文件命名约定。项目没有测试基础设施时，在新增依赖前询问用户。

## 选择测试范围

优先测试重要且稳定的逻辑：

- 请求错误标准化。
- 复杂 Hook 和状态流转。
- 业务计算与数据转换。
- 权限判断。
- 路由参数处理。
- 容易造成严重回归的工具函数。

默认不测试：

- 普通文案。
- 纯展示组件。
- 简单布局。
- 快照。
- 容易频繁变化的 UI 细节。

组件承载关键逻辑时，优先把逻辑抽到 Hook 或工具函数后测试。只有用户明确要求，或组件交互本身关键且容易回归时，才增加组件测试。
