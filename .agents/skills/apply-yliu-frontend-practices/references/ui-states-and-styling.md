# UI 状态与样式

在任务涉及异步页面状态、危险操作、组件库选择或样式实现时使用本规范。

## 处理异步状态

- 区分首次加载、后台刷新、加载失败、空数据和正常内容。
- 首次加载使用当前 UI 框架的局部 `Spin`、Skeleton 或等价组件，并保留区块尺寸。
- 后台刷新尽量保留已有内容，只展示轻量加载状态。
- 某个区块的请求只控制该区块；大部分区块已有局部 Loading 时不要再叠加整页 Loading。
- 请求失败时展示错误和必要的重试入口，不要伪装成“暂无数据”。
- 数据为空时使用 Empty、空表格文案或“暂无数据”等明确提示。
- 使用 Skeleton、`min-height`、固定容器或占位结构防止元素塌陷和布局抖动。
- 变更请求进行中时禁用触发按钮，避免重复提交。

推荐渲染顺序：

```tsx
if (loading && !data) return <Skeleton />
if (error && !data) return <ErrorState onRetry={refresh} />
if (!data) return <Empty description="暂无数据" />
return <Spin spinning={loading}>{content}</Spin>
```

## 二次确认危险操作

- 删除、退出登录等危险操作必须二次确认。
- 单条、就近、影响范围清晰的操作优先使用 `Popconfirm` 一类气泡确认。
- 批量、不可逆或需要解释影响的操作使用 Modal。
- 确认按钮使用明确文案，并在请求期间展示 Loading 和禁止重复点击。

## 使用成熟库

- 优先复用项目已经安装且维护良好的库，避免为通用能力手写大量代码。
- 只有现有依赖不能合理解决重复问题时才新增库。
- 调用版本相关 API 前检查当前项目版本和相应官方文档。

## 使用原子样式

- 新项目优先使用 UnoCSS 加 UI 框架。
- 已有 Tailwind、CSS Modules 或其他稳定样式体系时继续沿用，不并行引入 UnoCSS。
- 优先使用原子类、UI 框架属性、主题变量和设计 Token。
- 复杂状态、动画或组件内部结构难以清晰表达时，再编写局部 `style`。
- 避免为覆盖 UI 框架内部样式堆叠脆弱选择器。
