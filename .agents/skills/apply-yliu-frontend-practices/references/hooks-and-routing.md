# Hooks 与路由

在任务涉及逻辑复用、请求执行时机、路由拆分或详情页数据来源时使用本规范。网络 Hook 还要读取请求与反馈规范。

## 优先复用逻辑

- 优先把可复用的业务逻辑、请求流程和状态流转抽成 Hook 或 Composable。
- 只在视觉结构和交互稳定时抽公共组件，避免制造带大量属性的万能组件。
- 一个 Hook 只负责一项清晰能力，并暴露尽可能小的输入和输出。
- 不创建只转发参数、没有减少复杂度的薄包装 Hook。
- 不把一堆互不相关的 Hook 搬进同一个文件冒充封装。

## 控制执行时机

- 禁止在模块作用域、应用初始化或无关页面挂载时启动页面专属请求。
- 禁止因为调用一个公共 Hook 就触发当前页面不需要的全部接口。
- 把页面专属 Hook 放在对应路由组件的子树中。
- 查询请求只在页面可见、路由参数有效且依赖准备完成后执行。
- 使用请求库的 `manual`、`ready`、`enabled` 或等价能力阻止过早请求。
- 依赖变化时优先使用请求库的依赖刷新能力，不额外手写效果监听。
- 参数快速变化时使用取消或忽略旧结果能力，避免旧响应覆盖新页面。

## 让 URL 驱动详情页

- 懒加载路由页面，让页面代码和专属请求只在进入路由后初始化。
- 把资源 ID、父级 ID、分页和筛选等核心状态放入 URL，例如 `/pages/:id`。
- 详情页从 URL 读取资源 ID，验证后请求详情接口。
- 参数未就绪或不合法时不请求，并提供明确反馈。
- 同一组件内 ID 变化时重新请求对应详情。
- 不从 Pinia 等状态库读取上一层详情数据，也不因内存缓存存在而跳过详情请求。
- Pinia 只用于用户信息、权限、全局配置等真正跨页面的状态。
- 不把完整业务对象或敏感数据塞入 URL。
- 保证刷新、分享链接和直接访问详情页时能独立加载正确数据。

React 示例：

```ts
const { id } = useParams()

const { data, loading, error } = useRequest(
  () => getPageDetail(id as string),
  {
    ready: isValidId(id),
    refreshDeps: [id],
  },
)
```
