# 可选云端文档库

## 背景与目标

Loci 保持本地优先的产品定位，并增加可选的云端文档服务。服务器负责维护一组公开文档库，桌面端可以把这些文档下载到本地数据库，让用户继续通过现有桌面浏览和本机 MCP 使用文档。

## 范围与非目标

- 桌面端继续保留现有的本地文档抓取、存储、浏览和 MCP 能力。
- 仓库改造为同时容纳桌面端、Hono 服务端和必要共享代码的 monorepo。
- 服务端部署目标为 Linux，并使用 Docker Compose 编排 API、浏览器抓取服务和持久化数据。
- 服务端负责选择并抓取公开文档、保存文档和执行定时更新。
- 云端文档下载到桌面端后保存在本地数据库，可以脱离服务器继续读取。
- 本地创建或抓取的文档库不得上传到服务器；产品不提供双向同步和冲突合并。
- 普通用户读取云端文档不需要登录；普通用户不能修改服务器上的文档源、抓取规则和计划。
- 本需求不引入普通用户账号、私有文档库或普通用户之间的权限差异。

## 已确认需求与决策

### 云端文档服务

- 服务端使用 Hono 提供 API，并持久化服务器维护的文档及其同步状态。
- 第一版使用 SQLite，并将数据库文件保存在 Docker 持久化卷中；Hono 服务保持单实例运行，不引入 PostgreSQL、Redis 或独立任务队列。
- 当服务端需要多副本、高可用、多进程并发写入或多租户管理时，再评估迁移 PostgreSQL 和分布式任务调度；仅迁移数据库不能替代任务锁。
- 服务器上的文档源、抓取规则、抓取计划和手动同步仅允许管理员管理。
- 普通用户可以读取全部已发布的服务器文档库，并把选择的文档库下载到桌面端。
- 服务端更新文档时不得要求或接收桌面端的本地文档内容。

### 抓取与共享能力

- 桌面端和服务端共同使用 `@loci/core` 中不依赖 Electron 或 Hono 的抓取队列、HTTP 抓取、页面解析、URL 规则、抓取方式判断和计划处理能力。
- 服务端优先使用 HTTP 抓取；自动模式只比较文档库入口页的 HTTP 与浏览器渲染结果，再为整个文档库选择抓取方式，不逐页双通道抓取。
- SPA 文档由 Hono 服务通过 `playwright-core` 连接 Compose 内独立运行的 Browserless Chromium 服务抓取；浏览器服务仅在内部网络开放，并限制访问令牌、并发和资源。
- 浏览器请求需要独立执行 SSRF 与导航防护，阻止私网、回环及链路本地地址，并禁止弹窗、下载、权限申请和越界导航；Node HTTP 抓取的安全检查不能视为浏览器流量的保护。
- 不引入 Crawlee 等第二套抓取框架，继续复用现有共享队列、重试、页面解析和 URL 过滤逻辑。

### Linux 部署

- Docker Compose 至少包含 `server` 与 `browser` 两个服务，以及供 SQLite 使用的持久化卷。
- `server` 运行 Hono API、同步调度和发布逻辑；`browser` 只提供 Chromium 渲染能力，浏览器镜像与连接协议版本必须固定并兼容。
- 浏览器端口不得直接发布到公网。HTTPS 由现有网关承担；没有现有网关时才增加反向代理服务。
- 容器重启后必须保留文档、抓取计划、管理员配置和已发布版本；SQLite 备份必须包含一致的 WAL 状态或使用 SQLite 提供的一致性备份方式。

### 桌面端云端资源

- 桌面端提供云端资源入口，用于查看服务器文档库并将选中的文档库保存到本地数据库。
- 云端文档库在本地作为服务器托管的只读副本使用，不参与本地网页抓取，也不反向写入服务器。
- 用户可以手动检查并拉取服务器上的新版本。
- 用户可以为云端文档库启用“始终与服务器保持同步”。启用后，桌面端在应用启动时检查更新，并在应用持续运行时每天检查一次。

### 管理员入口

- 桌面端保留普通使用入口，并提供管理员登录入口。
- 管理员登录后可以看到服务器文档源、抓取规则、抓取计划、同步操作和同步状态等管理能力。
- 管理员身份只增加服务器管理能力，不改变本地文档的所有权，也不开放本地文档上传。

## 验收标准

- 未登录用户可以查看服务器公开文档库，并将选中的文档库完整保存到桌面端本地数据库。
- 下载完成的云端文档可以通过现有桌面浏览和本机 MCP 正常读取。
- 云端文档库启用自动同步后，桌面端会在启动时以及持续运行期间每天检查服务器更新。
- 普通用户无法创建、修改、删除或同步服务器文档源，也无法修改服务器抓取计划。
- 管理员登录后可以管理服务器文档源及其抓取规则和计划，并能手动触发同步和查看结果。
- 桌面端本地文档不会因登录、下载云端文档或执行自动同步而上传到服务器。
- 服务端不可用或没有新版本时，桌面端已经保存的云端文档仍可读取。
- Linux 主机可以通过 Docker Compose 启动服务；重建容器后，持久化卷中的服务端数据仍然存在。
- 普通 HTML 文档和依赖客户端渲染的 SPA 文档都可以被服务端同步和发布，自动模式不会为每个页面重复执行双通道抓取。
- 浏览器抓取不能访问私网、回环或链路本地目标，Browserless 服务不能从公网直接访问。

## 文档与兼容性影响

- 现行 PRD 中“数据仅保存在本机”和“不设计远程同步”的边界将在本需求完成收口时改为“本地优先、可选只读云端文档服务”。
- README 需要补充本地模式、云端资源、管理员入口和服务端部署方式。
- Agent 使用 Skill 继续读取桌面端本地 MCP；云端文档成功下载后与本地文档使用相同的读取方式。
- 服务端公开 API、管理员 API、下载数据格式和兼容策略以 [Loci Server 文档](../../../apps/server/README.md) 为权威入口。
