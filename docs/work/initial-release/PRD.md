# 本地文档知识库初始版本

## 背景与目标

常用技术文档分散在 Vite、Vue、React 等不同网站，人工逐站搜索效率低。本项目要提供一个 Electron 本地应用，从用户给出的公开文档页面发现并抓取同站页面，将内容转换为 Markdown 存入 SQLite，再通过树形浏览、预览和全文搜索帮助用户检查本地知识库。

本版本优先完成界面和本地数据准备。数据结构应能被未来的本机 MCP 使用，但本版本不开发 MCP。

## 范围与非目标

### 范围

- 管理本地文档源及其抓取配置。
- 从用户提供的任意公开页面开始发现同站文档。
- 自动判断文档源应使用 HTTP 直取还是浏览器渲染。
- 将网页转换为 Markdown 并存入本地 SQLite。
- 根据页面 URL 动态生成文档树。
- 支持手动更新、可选的定时更新、重试和抓取进度查看。
- 支持树形浏览、Markdown 预览和 SQLite FTS5 全文搜索。
- 关闭主窗口后驻留托盘，显式退出后才完全停止应用。

### 非目标

- 不开发 MCP 服务。
- 不开发服务器下发知识库或用户提交文档源。
- 不实现代理池和自动 IP 轮换。
- 不保存原始 HTML、页面截图、图片二进制或历史内容版本。
- 不实现向量、Embedding 或语义检索。
- 不抓取需要登录或不公开的页面。

## 已确认需求与决策

### 文档源与第一个页面

- 用户添加文档源时提供的 URL 统一称为“第一个页面”，不要求它是网站首页。例如 `https://electron-vite.org/guide/assets` 可以直接作为第一个页面。
- 文档源以第一个页面完成跳转后的 hostname 为抓取边界，只抓取相同 hostname 下的页面，默认不包含子域名。
- 文档源保存抓取方式、页面数量上限和定时配置等站点级配置。
- 用户可以手动触发更新，也可以手动切换抓取方式或重新执行抓取方式检测。

### URL 发现与地图树

- 首次抓取使用 Sitemap 和页面内链接发现候选 URL；Sitemap 不可用时仍可依靠页面链接递归发现。
- 后续更新重新抓取当前文档源已经保存的全部 URL，并从 Sitemap 和页面链接中发现新 URL。
- 新发现的 URL 经过标准化和去重后加入当前抓取队列。
- URL 标准化时移除 Fragment 和全部 Query 参数。
- 同一文档源内的标准化 URL 必须唯一，避免循环和重复抓取。
- 每个文档源默认最多发现 1,000 个唯一 URL，用户可以修改该上限。
- 达到上限后停止加入新 URL，但继续完成已入队页面和已存页面的更新；界面提示已达到页面上限。
- 不单独存储树结构。界面根据页面 URL 的路径片段动态生成目录树，页面标题作为叶节点名称。

### 抓取方式检测

- 自动模式只检测第一个页面：HTTP 直取和 Electron 隐藏浏览器同时抓取该页面，并使用同一转换流程生成 Markdown。
- 比较前统一清理正文并消除格式、空白和少量动态内容差异，不比较原始 HTML。
- HTTP 与浏览器结果正文相似度不低于 90%、浏览器正文没有多出 10% 以上，并且标题和代码块没有明显缺失时，文档源选择 HTTP 直取；否则选择浏览器渲染。
- 检测结果作用于整个文档源。后续页面不再执行双通道检测，也不因内容异常自动回退到另一种抓取方式。
- 存储和界面使用 `http` 与 `browser` 表达实际抓取方式，不使用无法由该检测准确证明的 SPA/SSR 技术架构标签。

### HTTP 与浏览器抓取

- HTTP 使用运行时原生网络能力抓取公开 HTML 页面。
- 浏览器抓取使用隔离的隐藏 Electron `BrowserWindow`，等待页面加载完成后读取渲染结果。
- 隐藏窗口禁用 Node 集成，启用上下文隔离和沙箱，并禁止弹窗、下载、权限申请及无关导航。
- 每个文档源的 HTTP 默认并发为 9，浏览器默认并发为 2。
- 不额外控制请求间隔。
- 每次抓取尝试的超时时间为 30 秒。
- 首次请求失败后最多重试 3 次，即单个 URL 最多尝试 4 次。
- 网络错误、超时、HTTP 408、429 和 5xx 参与重试；其他 4xx 默认不重试；429 优先遵守 `Retry-After`。
- 更新抓取失败时保留上一次成功的 Markdown 和抓取时间；新页面失败时不创建文档记录。
- 页面明确返回 404 或 410 时删除对应页面记录和全文搜索索引；仅从 Sitemap 或链接中消失时不删除。

### 页面转换与最小存储

每个抓取成功的页面只维护以下产品字段：

- `title`：从解析后页面的 `document.title` 提取。
- `url`：标准化后的页面 URL。
- `crawled_at`：最近一次成功抓取时间。
- `markdown`：网页转换后的 Markdown 内容。
- `language`：读取 `document.documentElement.lang`，保留 `zh-CN`、`en-US` 等语言标签；缺失时使用 `und`，不要求用户选择或推断正文语言。
- `fetch_mode`：实际使用的 `http` 或 `browser`。

数据库可以增加主键和文档源外键作为内部关联字段，但不增加原始 HTML、内容版本、页面层级等产品数据。

SQLite FTS5 索引页面标题和 Markdown 正文。全文索引属于搜索基础设施，不作为额外页面产品字段。

### 更新、队列与调度

- SQLite 保存文档源、成功页面和必要的抓取运行状态；运行时队列负责并发、超时和重试。
- 同一文档源同一时间只运行一个抓取任务，避免定时任务与手动更新相互覆盖。
- 定时抓取默认关闭，仅在用户配置并启用后运行。
- 应用主窗口关闭后继续驻留托盘，已启用的定时任务继续运行。
- 用户从托盘显式退出时完全结束应用及调度器。

### 本地数据与未来边界

- SQLite 数据库保存在 Electron 的用户数据目录中。
- 本版本只维护本地数据，不设计远程同步表或供应商抽象。
- 未来本机 MCP 直接消费已准备好的本地文档数据和全文搜索能力，不影响本版本的数据采集流程。
- 未来服务器下发能力单独设计数据包格式、许可信息和校验机制，不提前写入当前实现。

## 验收标准

- 用户可以用任意公开文档页创建文档源，而不必先找到网站首页。
- 第一个页面会同时执行 HTTP 与浏览器抓取，并按已确认规则为文档源选定抓取方式。
- 抓取不会越过第一个页面跳转后的 hostname，也不会因 Fragment、Query 或重复链接反复入队。
- 默认最多发现 1,000 个唯一 URL，用户修改上限后新任务使用新上限；触顶时界面有明确提示。
- 已存页面更新时会重新提取链接，新发现的同站 URL 能加入队列并在成功后进入知识库。
- 每个成功页面只展示并维护标题、URL、抓取时间、Markdown、语言和抓取方式六项产品数据。
- 页面语言来自 HTML `lang`，缺失时显示为 `und`，创建文档源不要求选择语言。
- HTTP 和浏览器分别按每个文档源 9 和 2 的默认并发运行；单次尝试 30 秒超时，失败后最多重试 3 次。
- 更新失败不会覆盖旧内容；404 或 410 页面会从文档和搜索结果中删除。
- 用户可以从 URL 树浏览页面、预览 Markdown，并通过标题或正文全文搜索。
- 定时抓取默认关闭；启用后应用隐藏到托盘仍可执行，显式退出后停止。
