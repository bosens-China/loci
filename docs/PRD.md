# Loci 产品 PRD

## 产品定位

- 当前决策：Loci 是面向 AI Agent 的本地文档知识库。用户提供公开文档页面后，应用发现同站页面，把网页转换或直接保存为 Markdown，并通过共享数据库提供 Web UI、CLI 和本机 MCP 访问。产品不再提供 Electron 桌面安装包。
- 为什么：常用技术文档分散在不同站点，本地统一收录可以减少重复查找，并让人和 Agent 共享同一份可检查的数据。
- 边界 / 非目标：本地文档不上传；可选服务端只维护公开文档库的只读快照。不提供多用户私有文档、登录态抓取、验证码或 Cloudflare 挑战绕过、代理池、原始 HTML、页面截图、历史版本、向量或语义检索。
- 权威入口：[README](../README.md)、[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)。

## CLI 产品入口

- 当前决策：Loci CLI 通过 npm 分发，是安装、升级和高级管理入口；它与后台服务和 Web UI 共享本地数据库及领域实现，覆盖文档源、知识库、云端公开库、远程 Server 管理、数据维护、诊断和 MCP 核心能力。
- 当前决策：CLI 面向终端用户，命令说明、交互和反馈使用中文；除专门用于复制的 MCP 客户端配置片段、Agent 专用的 `loci mcp call` 以及 `loci task follow --format jsonl` 外，常规命令输出只承诺适合人阅读，不提供稳定 JSON 契约。AI Agent 优先使用当前会话中的 Loci MCP；没有 MCP 工具，或当前 Host 不能同时提供 MCP 原生 Progress 与 Cancellation 时，可以在用户授权安装 npm CLI 后改用 CLI 降级。普通命令前台完成后退出，不隐式启动后台任务。
- 当前决策：根命令默认显示总帮助，`loci agent` 例外，在交互终端中进入推荐接入向导。具体命令优先使用位置参数和安全默认值减少输入：新建文档源只需提供第一个页面 URL，名称自动生成，抓取方式、页面上限和收录范围按“显式参数、CLI 安全偏好、产品基础默认值”的顺序解析，并发与 GitHub 大小覆盖留空时继承全局设置；更新命令传入选项时只修改显式字段，在交互终端中完全省略选项时进入逐项编辑。省略有歧义的资源时在交互终端中选择；删除、覆盖、清空、客户端写入和管理员凭据不设置可导致误操作的隐式默认。
- 当前决策：Agent 客户端集成统一归入 `loci agent`：根命令一次交互选择 Agent 和 Skill 作用域，预览后依次配置 stdio MCP、安装 Skill 和写入全局规则；`connect`、`print-config`、`rules` 和 `skills` 子菜单在 TTY 缺参时也交互补全。旧 `agent configure` 与 `agent config` 已按破坏性升级移除，不保留兼容入口。Agent、CI 和其他非交互调用必须传完整参数，写操作必须显式 `--yes`，不读取人类交互偏好。`loci mcp` 只保留工具直调和 stdio。
- 当前决策：CLI 将安全且可逆的交互偏好保存在共享 SQLite 中：本地创建记住抓取方式、页面上限、收录路径层级和首次同步选择；Admin 按规范化 Server 地址记住账号、创建配置、更新计划和上次批量同步勾选；资源选择、数据目录和 MCP 客户端配置记住最近成功值。单个候选直接使用或默认勾选，多个候选高亮最近值；显式参数优先，失效偏好回退到当前状态或产品默认值。密码、Token、搜索词、删除目标和危险确认不保存。
- 当前决策：`loci source add` 创建后默认执行一次前台同步；`--no-sync` 只保存配置，`--background` 把首次同步提交到 SQLite 持久队列、确保按需 worker 已启动后退出，两者互斥并在参数解析阶段拒绝同时使用。按需 worker 不监听 HTTP，通过跨进程 single-flight 认领队列并在空闲后退出；结果通过持久任务和抓取记录审查。
- 当前决策：`loci task list/status/follow/cancel` 提供持久任务的列表、状态、逐页跟随和幂等取消；任务使用稳定 ID，逐页完成事件带单调 sequence。`status`、`follow` 和 `cancel` 在 TTY 省略任务 ID 时从最近任务中选择，非交互调用必须显式提供 ID。`task follow` 的 `Ctrl+C` 或 `SIGTERM` 只解除跟随，显式 `task cancel` 才取消 pending 或 running 任务。
- 当前决策：持久任务租约过期后按最后请求收口：已经请求取消的任务直接进入 `cancelled`；未请求取消且中断少于三次的任务回到可领取状态，连续三次中断后停止自动重试并进入 `failed`。维护锁竞争等尚未开始业务写入的错误回到待执行状态，不消耗进程中断恢复机会。
- 当前决策：`loci ui` 在当前 CLI 进程只启动 Web 静态资源、本机 API 和随机回环端口，先打印普通本机地址，再默认尝试打开一次系统浏览器；不在 Web 进程内运行抓取 worker、调度器或云端检查。浏览器启动失败只提示手动访问；收到 `SIGINT` 或 `SIGTERM` 时关闭 HTTP，已经提交的任务继续由独立 worker 执行。`--no-open` 只跳过浏览器尝试。
- 当前决策：Web UI 使用 Browser History 提供可刷新、可分享的页面地址；文档工作区以 `source`、`doc` 和 `q` 查询参数表达当前来源、文档与搜索词。旧 `/sources`、`/library` 和 `document` 参数继续重定向到规范地址，未知路径回到概览页。
- 当前决策：CLI 另行提供当前用户的无 HTTP 登录自启动 worker，承载持久任务、定时调度和云端副本每日检查，不承载 Web 或 MCP。定时抓取和云端每日自动同步统一视为持久后台能力；CLI 或 Web 开启时先确保常驻 worker 可用再保存，不等待 Web 退出交接，关闭能力不自动停止 worker。`loci service start` 保留为手动恢复和提前准备入口；`status`、`stop`、`restart`、`logs`、`disable` 和 `run` 分别提供状态、停止、重启、日志、停用和前台调试入口。Web 与 worker 可以同时运行，同一数据目录只允许一个 worker 认领任务。HTTP 抓取无需浏览器；SPA 抓取使用用户显式安装的 Playwright Chromium headless shell。CLI 与本机 Web 复用 Runtime 浏览器管理服务、缓存目录和当前 Playwright registry 解析出的 headless shell，提供真实状态、安装、卸载与操作进度，不要求额外安装完整 Chromium；同一进程重复请求复用当前操作，跨进程文件锁阻止并发修改，活动抓取期间拒绝卸载。
- 当前决策：CLI 管理员交互会话每次读取账号和隐藏密码；脚本化的列表、创建、更新、删除、批量同步、任务查询和取消命令只从 `LOCI_ADMIN_USERNAME` 与 `LOCI_ADMIN_PASSWORD` 环境变量读取凭据。密码与 Token 均只保存在当前进程内存中，命令结束后清除。
- 当前决策：CLI 数据维护支持导出与覆盖导入、仅清空全部文档并保留文档源，以及清空全部文档源及其关联数据。覆盖和清空操作默认要求确认并使用维护锁，清空文档源不删除应用设置或远程 Server 内容。导入恢复的定时抓取或云端每日同步立即进入统一后台需求判定：CLI 与 Web 都在导入完成后立即确保常驻 worker 可用；服务激活失败不回滚已经恢复的数据。
- 当前决策：省略导出路径时使用包含 UTC 毫秒时间的备份文件名，并以独占创建避免静默覆盖；显式路径代表用户已选定目标，文件存在时直接覆盖，不再二次确认。
- 为什么：npm CLI 可以统一跨平台分发服务与 Web UI；共享运行时和持久队列避免形成第二套产品语义；用户级服务使定时和异步工作不再依赖终端或浏览器存活。
- 边界 / 非目标：除 MCP 配置片段与 `loci mcp call` 外，CLI 不提供机器可读输出兼容承诺；不自动下载浏览器，不开放局域网访问，也不新增普通用户账号、私有云端文档或登录态抓取。
- 权威入口：[CLI 安装与使用](../apps/docs/docs/cli/getting-started.mdx)。

## 文档源与页面发现

- 当前决策：用户可以从任意公开文档页创建文档源，该 URL 统一称为“第一个页面”，不要求是网站首页。
- 当前决策：添加文档源时先填写 URL；名称为空且未被用户修改时根据域名自动填入，用户仍可自由编辑。
- 当前决策：网页文档源以第一个页面完成跳转后的 hostname 为边界，默认不包含子域名；本地网页库按规范化 hostname 与收录路径共同识别，同域同路径复用、同域不同路径可拆成独立逻辑文档库。公开 GitHub 仓库按规范化的 `owner/repo` 标识区分，因此同一 `github.com` 下可以维护多个仓库，但同一仓库不能重复创建。
- 当前决策：编辑时切换来源类型、hostname 或 GitHub 仓库会在保存事务中立即清空旧正文与全文索引；收窄范围或新增、修改排除规则会在同一事务中裁剪不再匹配的内容，命中排除规则的显式页面目标也会被移除并停止后续刷新。交互式 CLI、Web 与 Server Admin 必须在保存前显示危险确认。
- 当前决策：文档源默认收录整个 hostname，用户可以选择第一个页面的某级路径作为范围，并可配置一个默认关闭、最多 500 字符的排除路径正则；正则只匹配 URL 的 `pathname`。hostname、收录路径和排除规则共同约束已有页面、`llms.txt`、Sitemap、OpenAPI、页面链接和重定向结果；规则命中入口或格式无效时拒绝保存，新增排除规则时立即删除命中的已有页面及全文索引。本阶段不自动识别或排除多语言目录。
- 当前决策：每次更新优先读取站点根目录的 `llms.txt`；存在有效范围内链接时以该清单作为权威发现来源。未命中时，明确位于 `*.github.io` 或 `*.gitlab.io` 的静态 Pages 直接进入网页流程；其他 URL 命中 Swagger UI、Knife4j、ReDoc、FastAPI `/docs` 或常见规范路径特征时，并发探测同 hostname 的 OpenAPI 3、Swagger 2 和分组配置 JSON，命中后将规范作为权威来源，否则进入普通网页流程。普通网页存在有效 Sitemap 时，将其作为权威的新页面清单，不再从页面链接扩展；Sitemap 请求失败、格式无效、为空或没有范围内 URL 时，才从页面链接递归发现。普通网页按入口、当前 Sitemap、历史 URL、页面链接的顺序入队，首次同步与重新同步共用同一个页面上限。
- 当前决策：文档来源顶层区分普通站点与 GitHub 仓库。Web UI 明确选择来源类型，并采用基础设置与高级设置 Tabs 分页呈现：基础页仅展示 URL、自动生成的名称及收录范围；高级页按计划容量、抓取过滤、并发或体积限制分类展示，并在存在自定义项时在 Tab 上提示数量徽标；CLI、MCP 和兼容 API 未显式提供类型时根据 URL 推断。符合 `github.com/<owner>/<repo>` 的公开仓库 URL 直接进入 GitHub 仓库流程，自动规范化为仓库首页并读取默认分支，不参与普通站点的 `llms.txt`、OpenAPI、Sitemap 或页面链接发现。
- 当前决策：URL 入队前移除 Fragment 和全部 Query，完成标准化与去重；排除规则命中的候选不入队也不占页面额度。仅末尾斜杠不同的两个候选各抓取一次并各占一个页面额度，转换后的 Markdown 完全相同时只保存一份并清理旧重复 URL，不同时分别保存。普通网页不支持使用 Fragment 区分页面的 Hash Router 文档站；能够发现同站 OpenAPI JSON 的接口阅读页不受此限制。每个文档源默认最多入队 1,000 个页面 URL，用户可以修改上限。
- 当前决策：文档源分别保存顶层来源类型、站点发现工作流、最近一次同步解析出的发现路径、页面获取方式、页面上限和定时计划。普通站点额外保存收录范围、排除路径正则及可选的 HTTP 与浏览器并发覆盖值；GitHub 仓库额外保存可选的 ZIP 与 Markdown 总量覆盖值、默认分支和成功提交 SHA。首次成功读取入口页后保存网站图标 URL。缩小网页收录范围或新增排除规则时立即删除范围外页面及其全文索引。
- 为什么：URL 优先和名称默认值降低配置门槛；`llms.txt`、OpenAPI 与 Sitemap 权威清单可以避免不必要的页面渲染、导航递归和多语言扩散；hostname、路径范围、去重和数量上限共同避免误抓外站、无关内容、循环和失控扩张。
- 边界 / 非目标：达到上限后不再加入任何候选 URL，历史页面也不绕过上限；继续完成已经入队的页面。除用户主动缩小范围、配置排除规则或确认斜杠重复外，页面仅从发现来源中消失时不自动删除；不支持 `llms-full.txt`、跨 hostname 清单链接或自动多语言过滤。
- 权威入口：[共享 API 类型](../packages/shared/src/api.ts)。

## 页面获取方式与可靠性

- 当前决策：来源类型、站点发现路径与页面获取方式是三个独立概念。GitHub 仓库使用仓库快照流程；普通站点内部自动解析为 `llms.txt`、OpenAPI 或普通页面；只有普通页面需要在 HTTP 与浏览器之间选择。产品界面和结构化 API 不再用“抓取方式”混称这三个层次。

- 当前决策：有效的 `llms.txt` 优先于网页抓取方式检测；清单页面通过 HTTP 直接保存 Markdown，只允许无损规范化，明确返回 HTML 时不保存为 Markdown。
- 当前决策：OpenAPI 探测位于有效 `llms.txt` 和 GitHub/GitLab Pages 静态域名判断之后、普通网页读取之前。只在入口 URL 具有常见接口文档特征时并发请求入口、`/openapi.json`、`/v3/api-docs/swagger-config`、`/v3/api-docs`、`/swagger-resources` 和 `/v2/api-docs`；只有 JSON 通过 OpenAPI、Swagger 或分组配置结构校验才算命中，全部未命中时静默继续网页流程。
- 当前决策：命中的 OpenAPI 3 或 Swagger 2 JSON 按真实规范 URL 转换为 Markdown，保留标题、版本、说明、服务地址、接口、参数、请求体、响应、认证方案和数据模型；分组配置中的同 hostname 规范分别保存。转换完成后不再发现 Sitemap、页面链接或启动浏览器。本阶段不解析 YAML 规范，也不下载描述中的图片。
- 当前决策：GitHub 仓库通过 GitHub API 读取默认分支与提交 SHA，再把该提交 ZIP 流式写入临时文件；不执行 Git clone，也不把整个仓库展开到磁盘。ZIP 逐项读取 `.md`，文件名直接作为标题，仓库相对路径作为知识库目录，不从 H1 或 frontmatter 推导标题。
- 当前决策：GitHub Markdown 使用 AST 改写相对图片、链接和引用定义；图片指向固定提交的 Raw URL，链接指向固定提交的 Blob URL，代码块与绝对 URL 保持不变。图片不下载到本地，原始 HTML、MDX 和 Vue 组件属性不改写。
- 当前决策：未采用 `llms.txt` 时，自动模式只在当前运行环境已提供浏览器能力时，对第一个页面同时执行 HTTP 直取和隔离的隐藏浏览器渲染，并比较统一转换后的 Markdown；结果足够接近且浏览器结果没有明显增益时使用 HTTP，否则使用浏览器。本地 Chromium headless shell 未安装时，`auto` 不启动浏览器、不提示安装并直接使用 HTTP；本机 Web 新建表单在状态明确为未安装时默认选择 HTTP，CLI 不额外执行浏览器状态命令。
- 当前决策：自动检测或能力降级结果作用于整个文档源。用户可以手动指定或重新选择抓取方式，后续页面不逐页双通道检测，也不自动回退；显式选择 `browser` 时仍在缺少运行时的交互入口提示安装，非交互入口返回明确错误。
- 当前决策：全局 HTTP 与浏览器默认并发分别为 9 和 5，允许在设置中修改；文档源可分别提供 1 至 32 的可选覆盖值，留空时继承对应全局值。
- 当前决策：有效 `llms.txt` 列出的页面、有效 Sitemap 命中的普通网页，以及明确位于 `*.github.io` 或 `*.gitlab.io` 的 GitHub Pages 与 GitLab Pages HTTP 页面，按当次页面上限整批并发，不应用普通站点的并发覆盖、批次间隔或暂停等待；Sitemap 的 HTTP 与浏览器抓取遵循同一整批策略，两类 Pages 的自定义域名均不自动推断，HTTP 429 仍按通用规则重试。
- 当前决策：单次抓取尝试 30 秒超时，失败后最多重试 3 次。网络错误、超时、HTTP 408、429 和 5xx 可重试，429 优先遵守 `Retry-After`，但单次等待最多 60 秒；等待使用可取消的 Node 定时器并随请求信号立即停止。
- 当前决策：GitHub ZIP 默认下载上限为 200 MB，所收录 Markdown 默认总量上限为 100 MB，单文件最多 5 MB，ZIP 最多 100,000 个条目；全局大小默认值可修改，单仓库可覆盖。ZIP 下载连接等待最多 30 秒，连续 60 秒无数据时中止，并拒绝路径穿越、Markdown 软链接、条目大小不一致和超限内容。
- 当前决策：GitHub 成功同步以完整快照事务性替换旧文档和全文索引，因此仓库已删除或移动的 Markdown 会同步删除；下载、解析或安全校验失败时保留旧快照。提交 SHA 未变化时跳过 ZIP 下载；超限失败记录提交、限制类型和当时上限，同一提交在对应上限提高前不重复下载。
- 当前决策：更新失败保留旧 Markdown 和抓取时间；新页面失败不创建记录；明确返回 404 或 410 时删除页面及其全文索引。
- 当前决策：每次本地抓取持久化来源、任务 ID、运行 ID、状态、聚合计数、逐页完成事件和有界的页面级失败结构；逐页事件按任务 sequence 断点续读，相同页面终态幂等去重。CLI 通过 `source history` 列出运行，通过 `source run-details` 查看失败 URL、原因、状态码和可重试性，不保存无界原始控制台日志。
- 为什么：优先选择结构化且更轻量的 HTTP 来源，同时保证没有 `llms.txt` 或 OpenAPI 的客户端渲染文档站能够被完整收录；失败保护避免一次异常破坏已有知识库。
- 边界 / 非目标：浏览器窗口禁用 Node 集成并启用上下文隔离和沙箱，禁止弹窗、下载、权限申请及无关导航；只抓取无需登录即可读取的公开内容，不保存或注入登录态，不处理验证码、Cloudflare 挑战及其他反爬机制；GitHub 不支持私有仓库、身份认证、非默认分支、子目录范围、Git LFS 或仓库历史版本；不额外控制请求间隔。

## 本地内容与知识库浏览

- 当前决策：每个成功页面维护标题、标准化 URL、最近成功抓取时间、Markdown、语言和实际抓取方式；GitHub 文档还维护仓库相对路径。HTML 页面读取 `lang`，直接获取的 Markdown 和其他缺少语言标签的页面使用 `und`。`llms.txt` 页面优先保留有意义的清单名称；清单只提供 `Untitled` 或“无标题”占位名时，依次使用 Markdown 正文首个标题和 URL 文件名，避免把占位名写入知识库。
- 当前决策：SQLite 保存文档源与页面，FTS5 索引标题和 Markdown 正文。不保存独立树结构；网页根据 URL 路径、GitHub 仓库根据相对文件路径动态生成目录树。
- 当前决策：本地文档源列表和云端公开目录同时展示页面数与内容大小。内容大小按该文档源已保存 Markdown 正文的 UTF-8 字节数求和；同一云端 revision 在下载前后使用相同原始值，并自动显示为 `B`、`KB`、`MB`、`GB` 等单位。
- 当前决策：知识库页面提供 URL 树、Markdown 预览和正文关键词过滤。过滤结果保留命中页面的祖先层级并自动展开，清空关键词后恢复完整树。
- 当前决策：文档树侧边栏拥有独立滚动区域，不带动正文预览；产品不提供独立的全文搜索页面。
- 当前决策：知识库工作区以来源、URL 树和阅读器三栏呈现；来源栏与 URL 树栏可在当前浏览器会话中通过分隔条调整宽度，并始终为阅读器保留最小可用区域。来源选择同步更新 URL 状态；来源卡片在固定高度的底部信息行内切换来源元数据与选中操作，切换选中项不改变卡片高度。文档树仅在 SQLite 中按来源读取元数据，阅读器仅按选中文档 ID 读取正文。首次进入来源或原选中文档不存在时自动选中首篇，当前浏览器会话内重新进入已访问来源时保持上次选择，并明确呈现加载、失败与空结果状态。
- 为什么：最小字段足以支持本地浏览和 Agent 阅读；由 URL 派生树可以避免维护重复层级数据；统一的内容大小让用户无需打开数据库即可判断本地文档规模。
- 边界 / 非目标：内容大小不包含 JSON 传输包装、SQLite 文件、FTS 索引、元数据、空闲空间或压缩网络流量。数据库可以增加主键和文档源外键作为内部关联字段，但不扩展新的页面产品字段。

## 更新、调度与应用生命周期

- 当前决策：用户可以手动更新文档源；CLI 前台/后台、Web、stdio MCP 和定时器都先提交同一种 SQLite 持久任务。同一来源通过唯一约束、lease 和资源锁复用活动任务及最终结果，不启动第二次抓取；不同来源保持独立并行。
- 当前决策：抓取结果先暂存，只有任务成功且未取消时才事务性提交文档、全文索引和成功 revision。取消信号贯穿 HTTP、浏览器、GitHub 元数据、ZIP 下载与遍历；失败或取消保留旧内容并允许重试。
- 当前决策：Web 统一轮询共享 SQLite 中由写事务维护的轻量资源 revision；来源、文档、持久任务或设置变化时，只重新读取对应 Query，文档变化同时刷新列表与当前正文。revision 通过数据库触发器覆盖 CLI、MCP、worker 和 Web 的跨进程写入，不传输完整业务数据，也不建立第二套进程内事件源。
- 当前决策：定时抓取默认关闭，仅在用户配置并启用后运行。文档源页面使用“文档源”和“定时更新”两个 Tab，后者集中列出已设置计划的文档源并提供空状态和编辑入口。
- 当前决策：关闭浏览器页面不会停止仍在终端运行的 `loci ui`；终止该命令只关闭 Web HTTP，不取消或接管已经提交的任务。Web 通过轮询轻量资源 revision 刷新跨进程状态，不依赖进程内 SSE；Server Admin 的远端列表在活动任务期间高频、空闲期间低频刷新。用户通过 `loci service stop/disable` 停止或停用常驻 worker。
- 当前决策：CLI 和 Web UI 可以列出和修改本地文档源计划。CLI 推荐用 `off` 关闭本地或 Server 计划，继续接受旧 `manual`；用户级常驻 worker 持久化每个计划的下一次执行时间，恢复后把同一计划错过的多个时间点合并为一次补跑，并在启动时和持续运行期间每日检查云端副本。状态与诊断区分常驻 worker 和按需 worker；没有持久需求时显示无需运行，存在需求但没有常驻宿主时提示 `loci service start`。`loci schedule run` 作为隐藏兼容入口保留，前台调试使用 `loci service run`；内部 `--managed` 参数不进入普通帮助。
- 为什么：集中管理计划便于发现和修改自动任务；持久调度不再依赖浏览器或前台终端，并能明确恢复语义。
- 边界 / 非目标：不为定时更新新增侧边栏菜单；手动任务与定时任务不得相互覆盖。

## 应用版本更新

- 当前决策：CLI 以 npm 的 `@boses/cli` 最新稳定版本为更新来源。交互终端每天首次运行时，在独立进程中最多检查 5 秒并缓存结果，不阻塞当前命令；用户可通过 `loci update` 前台立即检查。MCP stdio、`loci mcp call` 与其他非交互调用不检查也不输出更新提示。
- 为什么：CLI 的短生命周期不能被网络请求拖慢，后台检查和缓存让更新提示不阻塞正常命令。
- 边界 / 非目标：不提供桌面自动更新器、常驻更新守护进程、更新频道、预发布版本检测或非交互终端提示。
- 权威入口：[CLI 安装与使用](../apps/cli/README.md)、[项目说明](../README.md)。

## MCP 与 Agent 使用

- 当前决策：产品只向 Agent 暴露一个名为 `loci` 的逻辑 MCP，并统一由客户端按需拉起 `loci mcp stdio`。不提供常驻或独立 HTTP MCP，不设置固定 MCP 端口；同一个客户端只注册一个 `loci` 入口。
- 当前决策：CLI stdio、直接工具调用、无 HTTP worker 和 Web UI 复用同一个工具注册器、工具 Schema、领域实现和本地数据库。每个 stdio 进程自行启动轻量 worker；Web 进程只承载当前会话的 HTTP，按需和常驻 worker 承载任务。持久队列、资源锁和 worker 锁负责跨进程复用，不同 Agent 可以各自拉起 stdio 进程。产品公开命名统一使用 `Loci`、`loci_*` 和 `Loci*`。
- 当前决策：运行时通过协议无关的工具注册器定义十八项 Loci 工具；MCP Server 将定义注册到协议层，`loci mcp call <tool> --input <json>` 则在当前 CLI 进程直接校验并执行同一项定义。两者共享工具名、Zod 输入 Schema、输出 Schema、annotations、默认值和 handler；直调成功时 stdout 只输出 MCP `structuredContent` 对应的 JSON，诊断写入 stderr，未知工具、无效 JSON 和 Schema 错误使用非零退出码。直调不配置或启动 MCP，也不读取普通 CLI 交互偏好；异步工具在保留 MCP 返回语义的同时，由直调入口等待已启动任务安全收口后再关闭短进程。
- 当前决策：CLI、运行时与本机 Web 共用一份 Agent 客户端能力目录和全局接入服务。`loci agent setup/status/remove` 与 Web 的 Agent 页面统一管理 MCP、Loci 官方 Skill 和全局规则；Codex、Cursor、VS Code、Claude Code 与 Google Antigravity 均可完整自动接入。原有 MCP、Skill、规则细粒度命令继续保留。其他客户端仅提供 Cursor `mcpServers` 风格的通用 stdio 配置，不纳入一键接入。产品面向个人开发者，不提供仅面向企业许可证或付费 API Key 用户的 Gemini CLI 快捷入口。所有片段都是具体客户端约定，不宣称为 MCP 协议统一配置格式。
- 当前决策：一键配置默认优先调用客户端官方命令；命令缺失、超时、执行异常或非零退出时回退到用户级配置文件，没有命令入口的 Antigravity 直接回退。回退按客户端官方结构只新增或替换名为 `loci` 的服务：Codex 使用 `~/.codex/config.toml` 的 `[mcp_servers.loci]`，Cursor 使用 `~/.cursor/mcp.json` 的 `mcpServers.loci`，VS Code 使用默认用户 Profile `mcp.json` 的 `servers.loci`，Claude Code 使用 `~/.claude.json` 的 `mcpServers.loci`，Antigravity 使用 `~/.gemini/config/mcp_config.json` 的 `mcpServers.loci`。文件不存在时创建；已有 JSON/JSONC 或 TOML 保留其他设置与注释；无法安全解析、结构冲突或重复定义时拒绝写入。命令与文件回退共享客户端级 single-flight、跨进程锁和原子替换。安全移除只删除仍符合 Loci 标准配置的 `loci` MCP、由 Loci 台账确认所有权的 Skill 和 Loci 规则管理区块；用户修改或结构冲突的内容保留并提示人工处理。
- 当前决策：MCP 使用“文档库”表示一个网站知识库，使用“文件”表示单个 Markdown 页面；提供本地文档库的来源规模检查、添加、指定页面抓取、配置更新、批量同步、同步状态、同步失败分页、分页列表、目录、批量读取、关键词搜索和删除，以及云端公开目录查询和快照拉取，并提供 Agent URL 审查的开始、读取、提交和取消，共十八个工具。
- 当前决策：MCP 新增网页库使用共享产品基础值：`auto`、1,000 页、根路径，以及继承全局并发/大小设置；`page_limit`、`scope_path`、`exclude_path` 等是 Agent 可选覆盖，不强制每次传入。规模或路径不明时可调用只读检查，它只读取 `llms.txt`、Sitemap、OpenAPI 或 GitHub 元数据，返回估算可信度和路径分布；无法廉价判断时返回 `unknown`，不完整预抓取。配置更新不隐式同步，但收窄范围或新增排除规则会删除不再匹配的本地文件。
- 当前决策：本地网页库持久化同 hostname 的显式页面目标。`loci_fetch_pages` 只抓传入 URL，不执行站点发现或跟随链接；目标可越过 `scope_path`，但不能跨 hostname 或绕过 `exclude_path`。不存在的正文插入，已有正文按内容更新，临时失败保留旧内容，404/410 删除旧正文并保留 `missing` 目标；整库同步额外刷新全部显式目标。`loci_add_library` 的 `discovery_mode=selected` 可在首次建库时只登记 `url` 与 `urls`。`auto` 文档源首批只探测一次抓取模式并持久化结果。
- 当前决策：本地网页库可持久化 `discovery_mode=agent_review` 和自然语言 `review_goal`。首次建库或 Agent 显式发起审查同步后，Loci 先执行 hostname、范围、排除和标准化硬校验，再按最多 50 项返回包含 `title`、`url`、`title_source` 与可选来源页面的候选批次；Agent 只提交排除 URL，并以 `approve_remaining=true` 明确批准其余项。抓取获批页面产生的新候选继续分批审查。运行与决定持久化，等待状态为 `awaiting_review`，不占用 worker、不默认放行，支持恢复、幂等重试和取消。任何活动审查都先以 `run_id` 读取 URL Review 状态，即使外层同步状态为 `syncing`；内层为 `discovering` 时显式恢复发现，为 `awaiting_review` 时提交当前批次。同一来源由活动运行唯一约束与文档源跨进程锁 single-flight，不同来源可并行。最终正文、来源解析结果与审查终态在同一 SQLite 事务中提交，取消和完成竞争时只有一个终态可以生效。
- 当前决策：审查模式仅用于本地网页库，不用于 GitHub 或云端副本。无 Agent 的 Web、普通 CLI、计划任务、worker 和 `loci_sync_libraries` 只精确刷新已收录 URL，不执行任何新 URL 发现；404/410 删除旧正文，网络、超时、408、429、5xx 和浏览器临时失败保留旧正文。默认 `site` 和显式 `selected` 模式行为不变。MCP 与 Agent 经 `loci mcp call` 直调完全复用相同工具、Schema、数据库运行和抓取实现。
- 当前决策：CLI、Web、MCP 和 Server 共享文档源业务字段的产品基础默认值、取值边界、`null` 继承含义和 GitHub 创建/更新规范化；领域层负责最终校验。显式参数优先，CLI 安全偏好只覆盖普通 CLI 的基础值，MCP 与 `loci mcp call` 都不读取 CLI 偏好。各入口不要求一一对应：普通 CLI 保留提示、确认和前台/后台控制，Agent 工具保留批量、分页、结构化输出、等待开关和专用检索流程。
- 当前决策：MCP 搜索使用 SQLite 传统检索，不引入嵌入模型；每组查询依次尝试全部词全文命中、任意词全文命中、标题或 URL 路径包含，并公开实际检索层级。搜索支持 URL 路径前缀过滤，标题、路径和与建库入口接近程度仅作为轻量重排信号。
- 当前决策：MCP 将文档可用性与同步状态拆分。同步响应仅携带失败总数、原因统计和最多五条样例；完整失败通过持久 `run_id` 分页读取。`library_id` 继续用于实时进度，不新增重复的同步 ID。
- 当前决策：有效 `llms.txt` 是权威清单，清单内页面的 404/410 只记录失败并跳过，不尝试同名 HTML 回退。网页 `auto` 抓取方式仍只根据首次普通页面的 HTTP 与浏览器结果选择，后续页面不因正文偏短重新判定。
- 当前决策：Agent 先查询本地文档库；本地缺失时只读查询云端公开目录，用户确认后才拉取匹配快照；没有云端匹配或用户不选择拉取时，再确认官方来源并由用户授权首次抓取。云端查询不修改状态，云端拉取、首次抓取和主动同步都需要用户确认。
- 当前决策：Agent 已知一个当前库缺失的官方页面 URL 时，可以说明该 URL 并单独请求加入或刷新授权；授权后用显式页面工具写入，再从 Loci 重新读取。页面级授权不继承首次建库、云端拉取或整库同步授权，Agent 也不能因为正文中出现新链接而自动扩大目标集合。
- 当前决策：0 页本地库和云端候选不视为可用文档；空本地库可在授权后重试同步，云端无可用候选、查询或拉取失败、拉取后仍无文件时，再单独确认官方入口并创建本地抓取库。云端同域副本不阻止这个本地回退；已有本地内容在云端不可访问时继续可用并提示新鲜度。
- 当前决策：CLI 与本机 Web 可以配置和移除 Agent 的用户级全局规则。Codex 写入 `~/.codex/AGENTS.md`，并优先更新已存在的 `AGENTS.override.md`；Cursor 写入只在本机生效的 `~/.cursor/rules/loci.mdc`；VS Code 写入 `~/.copilot/instructions/loci.instructions.md`；Claude Code 写入 `~/.claude/CLAUDE.md`；Google Antigravity 写入 `~/.gemini/GEMINI.md`。Loci 不读取、修改或同步 Cursor 云端 User Rules，也不通过 Cursor 内部数据库或未公开 API 回写规则。项目根目录和子目录仍可使用 `AGENTS.md`。
- 当前决策：全局规则统一使用 `<!-- loci:start -->` 和 `<!-- loci:end -->` 管理区块。重复配置只替换该区块，保留用户其他内容；标记残缺、重复或顺序错误时拒绝写入。Cursor 使用专用 `.mdc` 文件并要求合法 frontmatter 与 `alwaysApply: true`；移除受管区块后只剩 Loci 标准 frontmatter 时删除该文件，存在用户附加内容时继续保留。Codex 每次写入都会检查 `~/.agents/skills/context7-mcp/SKILL.md`、`~/.codex/skills/context7-mcp/SKILL.md`、具有完整标记边界的 Context7 全局规则，以及旧版 `<!-- loci-context7:start -->` 与 `<!-- loci-context7:end -->` 组合区块；Context7 晚于 Loci 安装，或已生成组合规则后又写入新 Context7 区块时，再次执行写入会去重并收敛为当前“Loci 优先、Context7 兜底”的单一组合规则。Cursor 检测到本机 Context7 Rule 或 Skill 时只在 Loci 文件中写入相同的协调说明，不修改 Context7 文件。Loci 不常驻监听第三方安装；发现无边界、边界不完整、重复或冲突的 Context7 命令时拒绝修改。文件更新采用原子替换和客户端级跨进程锁，同一客户端的并发调用幂等复用，不同客户端可以独立执行。
- 当前决策：全局规则提供可独立执行的 Loci MCP 使用规范，不依赖、不安装也不绑定 Skill。Agent 先判断任务是否依赖开发者技术文档事实；库、框架、SDK、API、CLI、配置、迁移、版本差异、安装过程和技术专属错误进入 Loci 流程，普通重构、业务逻辑调试、通用编程概念和不依赖外部技术当前行为的代码审查不进入。已安装的 Skill 只补充同一工作流，Loci 不修改、删除或覆盖用户安装的第三方 Skill。
- 当前决策：新闻与时效事件、价格、人物或公司信息、购物、旅行、法律、医疗以及普通网页内容等非技术文档任务直接使用适合该领域的网页或专业来源，不把 Loci 作为通用网页搜索的前置步骤；仅仅提到软件、公司或网页不足以进入 Loci 流程。技术文档范围内除非用户明确指定来源，Agent 按 Loci 本地库、Loci 云端公开目录、用户确认后的官方文档抓取顺序执行。
- 当前决策：Loci 已有文档能够回答时停止检索；本地或云端未命中本身不构成 Context7 兜底条件，Agent 必须先提供官方文档抓取选项。只有技术文档范围内的问题在 Loci 不可用、无法确认官方入口且用户没有指定可用来源、用户拒绝官方抓取、已经提供官方抓取选项后所有已授权获取路径仍失败或没有文件，或者合理检索后证据仍不足时，组合模板才把未解决的概念交给 Context7、定向网页检索或其他文档来源；切换前说明具体原因。用户明确指定来源时尊重当前请求。
- 当前决策：添加与同步默认异步启动并返回状态；Agent 可以轮询，也可以显式等待完成并接收进度通知。部分页面失败必须作为结构化结果返回，不掩盖已成功内容。
- 当前决策：显式等待抓取时，MCP 只使用当前 SDK 原生 Progress 和请求 Cancellation，不按具体 Agent 或 Host 维护兼容分支，也不手写 MCP Tasks 或自定义兼容协议。每个完成页面通过 Progress 报告标题、URL、成功或失败和聚合计数；取消本次调用新建的任务会请求停止底层抓取，取消一个复用已有 single-flight 任务的调用只解除当前跟随。
- 当前决策：目录使用稳定派生 ID 和渐进展开；文件使用数据库 ID。搜索返回最佳匹配段落、小节与来源，读取支持按小节和偏移量续读。
- 当前决策：全部工具提供输出 Schema，并同时返回可读文本和结构化内容。
- 当前决策：`use-loci` Skill 由 Agent 先探测当前会话的工具能力。普通发现、读取和短操作在存在 Loci MCP 工具时直接走 MCP；长时间抓取还要求 Host 同时向 Agent 暴露 MCP 原生 Progress 和 Cancellation，缺少任一能力时在任务启动前渐进加载 CLI 参考并改用 `loci mcp call --progress` 与 `loci task`。CLI 缺失时先取得用户明确同意再全局安装。安装授权与云端拉取、官网抓取、抓取配置更新、主动同步和删除授权彼此独立；不通过 `npx` 绕过拒绝，不配置 MCP、不启动 stdio、不要求新会话，也不使用普通 CLI 命令复制第二套文档检索流程。
- 为什么：渐进目录、定位搜索和按需读取可以控制上下文规模；SDK 原生进度和取消保持 MCP 标准语义，Skill 与 CLI 降级让 Agent 工具能力不足时仍可观察和停止长任务。
- 边界 / 非目标：Agent 工具不提供显式目标的永久删除命令；页面返回 404/410 时可以按同步语义移除过期正文。CLI stdio 与直接工具调用都不作为后台常驻服务。
- 权威入口：[数据备份与清理](../apps/docs/docs/cli/commands/data.mdx)、[Agent 全局规则](../apps/docs/docs/agent/global-rules.mdx)、[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)、[共享客户端目录](../packages/shared/src/mcp-clients.ts)。

## 文档浏览、后台任务与数据迁移

- 当前决策：本地与云端文档先展示文档库摘要卡片，进入具体库后才按需读取目录和正文。本机 HTTP、Server 公开 API、CLI 和 MCP 复用稳定目录节点、父节点/深度读取与正文 offset/最大字符数边界；云端按需阅读不创建本地副本。
- 当前决策：本机和 Server 后台任务以规范化 hostname 作为一级展示和调度边界。同 hostname 共享串行队列、并发和批次间隔，不同 hostname 并发；人工启动只暂停同 hostname 的其他活动任务。规则支持固定或 min-max 间隔，并由运行任务在下一批次实时读取。
- 当前决策：任务持久化批次日期、优先级、正文大小、检查点和控制请求。暂停/恢复复用原任务；结束提交已抓取内容并保存剩余 URL；取消丢弃本次内容，首次任务取消且库仍为空时删库，已有成功内容保留。Web、CLI 和 MCP 提供单任务及全局/hostname 控制，所有人工变更要求确认或破坏性工具标记。
- 当前决策：Web 全局通知任务成功、部分结束和失败；任务项显示可读耗时、正文大小、估算剩余时间和错误悬停详情。操作日志按日期、类别、级别和 hostname 查询，并覆盖本地任务、文档库、设置、维护及云端管理动作。
- 当前决策：备份使用 ZIP 容器，`index.json` 记录版本、记录数、字节数和 SHA-256，各稳定数据域拆分 JSON。导入验证路径、清单、限制、校验和及引用后在维护锁和 SQLite 事务中替换；Web 与 CLI 使用同一协议。
- 当前决策：管理员可以将明确选择的本地库以压缩二进制归档发布到 Server。创建新库或覆盖目标必须显式选择；稳定发布 ID、校验和、唯一约束和事务保证重复请求复用且失败保留旧 revision。跨库文档移动同样使用持久操作 ID和事务，并可显式删除空原库。
- 权威入口：[后台服务与 Web UI](../apps/docs/docs/cli/commands/service.mdx)、[数据备份与清理](../apps/docs/docs/cli/commands/data.mdx)、[MCP 工具参考](../apps/docs/docs/agent/mcp-tools.mdx)。

## Skills 管理

- 当前决策：产品通过 CLI 的 `loci agent skills add/list/remove/clear` 管理 Loci 官方内置 Skills，并通过 CLI 全局接入命令与 `loci ui` 的回环 HTTP 入口统一管理全局 Skill。项目路径和项目级 Skill 写入不暴露给浏览器；远端 Server、公开 Web、MCP 与 `loci mcp call` 均不提供 Agent 文件写入能力。
- 当前决策：CLI 的 `add`、`list`、`remove` 和 `clear` 在交互终端中补充 Agent 目标和项目级/全局作用域；`remove` 省略名称时操作内置 `use-loci`。非交互调用必须显式传入 `--agent` 以及 `--project <path>` 或 `--global`，写操作还必须传 `--yes`。`--project` 与 `--global` 互斥。
- 当前决策：用户可以选择通用、Codex、Cursor、Claude Code、VS Code、Antigravity 或全部客户端。路径按客户端官方用户级和项目级目录解析，多个客户端落到同一物理目录时自动去重。
- 当前决策：更新整目录替换，不做文件合并。新内容先在同父目录暂存并校验，再通过旧目录备份和原子重命名切换；失败恢复旧目录。删除先移入隔离目录，SQLite 提交成功后才清理。只有台账与 `.loci-skill.json` 同时确认所有权时才能替换或删除，不接管第三方目录。
- 当前决策：同一目标使用进程内 single-flight 和跨进程文件锁；并发入口等待正在执行的短事务并复查最终状态，不同目标可以并行。SQLite 台账属于机器本地文件状态，不进入知识库备份导入导出。
- 当前决策：`.agents/skills/use-loci` 是内置 Skill 的唯一内容源，不维护生成的 TypeScript 副本或第二份 public 目录。CLI 由 tsdown 将完整目录复制到 npm 包的 `dist/resources`，Runtime 递归读取真实文件并统一执行摘要、安装、更新和事务。
- 当前决策：`use-loci` 的 Markdown 内容采用两级渐进结构：`SKILL.md` 保存职责、通道路由和公共文档流程，`references/cli.md` 保存无 MCP 或缺少原生 Progress/Cancellation 时的 CLI 检测、安装确认、逐页输出和任务取消方式；`agents/openai.yaml` 继续作为客户端元数据随完整目录分发。
- 为什么：项目级默认值让 Skill 跟随当前仓库，减少无意影响其他项目；显式 `--global` 和双重所有权校验降低误删风险；共享事务防止并发损坏。
- 边界 / 非目标：不实现第三方 Skill 市场、Git/npm 下载、自动更新、Server 下发、任意目标目录或手工目录接管。
- 权威入口：[使用 Loci Skill](../apps/docs/docs/agent/skill.mdx)。

## 设置与本地数据

- 当前决策：`loci ui` 是唯一本机图形入口，只在前台启动随机回环 HTTP；终止命令关闭 HTTP，不影响独立 worker。产品不分发 Electron 桌面应用，也不在 Web 内维护第二套抓取、调度或云端同步实现。
- 当前决策：仓库开发脚本默认使用 `.loci-dev` 下的隔离数据、缓存和模拟用户目录，Agent 接入写入也不会触碰真实用户文件；只有显式运行 `pnpm dev:user` 才复用正式 Loci 数据、缓存与真实用户目录，并在终端提示 Web 写操作会直接修改对应数据和 Agent 文件。两种模式共享同一套 Web、API、Worker 和启动实现。
- 当前决策：Web 设置页、CLI `config`、后台服务和备份协议共用 `AppSettings`、`DEFAULT_APP_SETTINGS` 与 `APP_SETTINGS_LIMITS`；最终由运行时数据库校验并保存同一份 SQLite 设置。各界面不得自行缩小、放大或重新定义取值边界。
- 当前决策：`LOCI_SERVER_URL` 是进程级 Server 地址覆盖；生效时 CLI 明确标注覆盖并拒绝把 `config set server-url` 伪装成当前有效配置。自定义 `LOCI_DATA_DIR` 的按需任务可以启动 detached worker，但注销和重启恢复不由 Loci 自动保证；长期运行应由外部服务管理器托管 `loci service run`。`LOCI_CACHE_DIR` 是进程级的浏览器缓存目录覆盖，不写入持久设置；所有 CLI、MCP 和 worker 进程必须使用同一个值，单次命令的临时覆盖不代表已配置后续长期进程。
- 当前决策：MCP 只使用 stdio，不配置网络端口。主题支持自动、浅色和深色；自动模式跟随系统。Web UI 通过共享 `AppSettings` 持久化主题选择，并使用 Ant Design 默认浅色/深色主题和默认 token；UnoCSS 仅用于布局与响应式辅助，不定义项目配色、字体或组件视觉主题。
- 当前决策：SQLite 数据库位于后台服务与 CLI 共同解析的标准 Loci 数据目录；Web UI、普通 CLI、`loci mcp call` 和 stdio MCP 直接复用同一份数据。SQLite 使用 WAL 与忙等待支持跨进程访问；同一文档源同步使用资源文件租约与持久运行记录，云端快照使用来源级租约，维护操作使用全库排他租约，计划宿主使用单独租约。
- 为什么：单一图形入口、共享边界与单一数据源可以防止 Web、CLI、后台服务和 Agent 结果不一致。
- 边界 / 非目标：本地库不会自动上传；只有管理员明确确认的“发布到服务器”会上传所选库的公开正文。云端副本仍只允许服务器到本地客户端的单向同步，不提供自动双向同步和冲突合并。

## 可选云端文档库

- 当前决策：仓库提供可选的单实例 Hono 服务，通过 SQLite 持久化公开文档库、抓取计划和发布快照；生产 Docker Compose 编排服务端和持久化卷，发布镜像内置与 `playwright-core` 同版本的 Chromium headless shell，不要求额外部署浏览器容器。
- 当前决策：普通用户无需登录即可浏览服务器公开目录、按需读取目录与正文或下载完整快照。Web、CLI 和 MCP 把明确拉取的快照事务性保存到共享本地数据库，下载后复用本地文档目录、阅读器、全文索引和 MCP，可以离线浏览；来源列表和当前来源标题持续标记“云端副本”及自动或手动更新状态，不为每篇文档重复添加标签。
- 当前决策：公开目录提供当前发布快照的页面数和下载后将保存的 Markdown 内容大小。Web 与 CLI 按 1024 进制显示 `B`、`KB`、`MB`、`GB` 等人类可读单位，公开 API 与 MCP 结构化输出保留原始字节整数。
- 当前决策：Server 不发布或公开 0 页快照；客户端过滤旧 Server 返回的 0 页目录项，并在空快照、网络失败或不兼容响应时保留已有本地云端副本，只有通过校验的非空快照才能事务性替换本地内容。
- 当前决策：云端副本记录规范化的来源后端地址和服务端文档库 ID，只能从原后端更新。切换后端后旧副本继续保留，但停止手动和自动同步；切回原地址后可以恢复同步。
- 当前决策：用户可以从 Web 或 CLI 手动更新云端副本；用户级常驻 worker 启动时检查一次，并在持续运行期间每天检查。自动同步开关保存在共享数据库中；CLI 或 Web 开启开关以及 `cloud pull --auto-sync` 都在保存前立即确保常驻 worker 可用，不依赖 Web 会话退出。显式停用常驻 worker 期间不执行，恢复后继续检查。
- 当前决策：服务器文档源保存第一个页面、路径收录范围、页面上限和计划；同一 hostname 可以按不同范围建立多个文档库，同一 `hostname + scopePath` 不允许重复。旧数据库迁移后已有文档库范围为 `/`，缩小范围时立即删除范围外页面。
- 当前决策：服务器文档源、全局抓取策略、hostname 覆盖、计划和同步任务只允许管理员管理。Server 默认最多同时运行 3 个不同 hostname 的任务，同 hostname 始终串行；全局策略同时提供 HTTP/浏览器页面并发和批次间隔默认值，hostname 非空字段优先覆盖。降低任务并发不终止运行任务，页面并发与间隔从下一批次生效。全局策略使用 SQLite 修订号避免并发管理员静默覆盖，相同内容重试幂等复用。任务、进度、优先级、控制请求、检查点、owner 和租约持久化到 SQLite，同一数据库上的多个 Server 进程通过活动任务唯一约束复用同一文档库任务；租约过期后失败收口并允许重试。暂停、恢复、结束和取消均幂等，取消不会提交本次内容。
- 当前决策：云端 Server 管理同时提供 CLI、本机 Web 和 MCP 入口，并复用同一个 Runtime Admin 客户端和远程 API。三者保持相同的文档库、任务、hostname 规则和发布能力；Web 偏向自动刷新与直接反馈，CLI 偏向脚本，MCP 使用清晰的 Server 前缀和破坏性注解。Web 顶部工作区命名为“Server 管理”，菜单按概览、内容管理、任务与策略、审计与诊断分组；概览聚合现有远程接口，公开目录预览保持只读。Admin 创建普通站点或 GitHub 仓库后立即提交首次同步；配置创建成功但同步提交失败时保留配置并明确警告。CLI/MCP 从 `LOCI_ADMIN_USERNAME` 与 `LOCI_ADMIN_PASSWORD` 建立进程内会话；Web 登录密码只用于一次本机请求，Token 不返回浏览器、不写 SQLite。修改目标 Server 地址时清除旧会话。本机 Web 只绑定 `127.0.0.1`、校验 Host，并对写请求校验 Origin。Server 把认证后成功的管理写请求追加到 SQLite 审计记录，只保存管理员、方法、路径、状态和时间，不保存正文、密码或 Token。管理员登录后，Web 可以诊断 Server 的本地 Chromium、Browserless 或未配置状态，并只显示脱敏端点；运行中的 Server 不提供浏览器安装或卸载，部署修复通过镜像构建或环境变量完成。
- 当前决策：后台服务、CLI 和服务端复用 `@loci/core` 的页面发现、URL 规则、HTTP 与浏览器抓取编排、GitHub ZIP 解析和重试能力。本机 LocalRuntime 使用本地 Playwright Chromium；服务端默认通过 `playwright-core` 启动镜像内的 Chromium headless shell，也可显式配置远程 Browserless。Server HTTP 抓取从 DNS 校验到实际 socket 连接复用同一组公网地址以关闭 rebinding 窗口；浏览器导航继续做应用层检查，生产部署还必须在每个实际发起目标连接的执行环境通过网络策略阻断私网、loopback、link-local 和 metadata egress；本地 Chromium 模式覆盖 Loci Server 容器，远程 Browserless 模式同时覆盖 Browserless 执行环境。
- 为什么：可选服务器可以集中维护公共技术文档，同时保留本地优先、离线可读和 Agent 只访问本机数据的使用方式；目录中的内容大小让用户能在下载前判断正文规模并与下载后的本地数据直接比较；单向同步避免引入账号体系、所有权和冲突合并复杂度。
- 边界 / 非目标：内容大小不表示 SQLite 文件占用、JSON 快照实际字节数或压缩后的网络流量；不提供普通用户账号、私有服务器文档、多租户权限、客户端内容上传、双向同步、Redis 或跨主机集群调度；浏览器服务不直接暴露公网，也不处理登录态、验证码、Cloudflare 挑战及其他反爬绕过能力。
