# Loci 产品 PRD

## 产品定位

- 当前决策：Loci 是面向 AI Agent 的本地文档知识库。用户提供公开文档页面后，应用发现同站页面，把网页转换或直接保存为 Markdown，并通过共享数据库提供桌面端、CLI 和本机 MCP 访问。
- 为什么：常用技术文档分散在不同站点，本地统一收录可以减少重复查找，并让人和 Agent 共享同一份可检查的数据。
- 边界 / 非目标：本地文档不上传；可选服务端只维护公开文档库的只读快照。不提供多用户私有文档、登录态抓取、验证码或 Cloudflare 挑战绕过、代理池、原始 HTML、页面截图、历史版本、向量或语义检索。
- 权威入口：[README](../README.md)、[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)。

## CLI 产品入口

- 当前决策：Loci CLI 作为通过 npm 分发的独立产品运行，不依赖 Electron、桌面窗口或桌面进程；它与桌面端共享本地数据库和领域实现，覆盖文档源、知识库、云端公开库、远程 Server 管理、数据维护、诊断和 MCP 核心能力。
- 当前决策：CLI 面向终端用户，命令说明、交互和反馈使用中文；除专门用于复制的 MCP 客户端配置片段外，常规命令输出只承诺适合人阅读，不提供稳定 JSON 契约。AI Agent 使用 Loci MCP。普通命令前台完成后退出，不隐式启动后台任务。
- 当前决策：根命令默认显示总帮助。具体命令优先使用位置参数和安全默认值减少输入：新建文档源只需提供第一个页面 URL，名称、抓取方式、页面上限、收录范围和并发采用产品默认值；更新时只修改显式提供的字段。省略有歧义的资源时在交互终端中选择；删除、覆盖、清空、客户端写入和管理员凭据不设置可导致误操作的隐式默认。
- 当前决策：CLI 不执行本地定时计划或云端自动同步，也不复制主题、窗口、托盘和开机启动等桌面生命周期能力。HTTP 抓取无需浏览器；SPA 抓取使用用户显式安装的 Playwright Chromium headless shell。
- 当前决策：CLI 管理员会话每次交互式读取账号和隐藏密码，密码与 Token 只保存在当前进程内存中，退出后必须重新登录。
- 当前决策：CLI 数据维护支持导出与覆盖导入、仅清空全部文档并保留文档源，以及清空全部文档源及其关联数据。覆盖和清空操作默认要求确认并使用维护锁，清空文档源不删除应用设置或远程 Server 内容。
- 当前决策：省略导出路径时使用包含 UTC 毫秒时间的备份文件名，并以独占创建避免静默覆盖；显式路径代表用户已选定目标，文件存在时直接覆盖，不再二次确认。
- 为什么：独立 CLI 让无法安装桌面端的环境仍能使用核心能力；共享实现和数据避免形成第二套产品语义；显式前台运行使进程生命周期和资源消耗可预期。
- 边界 / 非目标：CLI 不提供机器可读输出兼容承诺，不自动下载浏览器，不维护本地常驻守护进程，也不新增普通用户账号、私有云端文档或登录态抓取。
- 权威入口：[CLI 安装与使用](../apps/docs/docs/cli/getting-started.mdx)。

## 文档源与页面发现

- 当前决策：用户可以从任意公开文档页创建文档源，该 URL 统一称为“第一个页面”，不要求是网站首页。
- 当前决策：添加文档源时先填写 URL；名称为空且未被用户修改时根据域名自动填入，用户仍可自由编辑。
- 当前决策：文档源以第一个页面完成跳转后的 hostname 为边界，默认不包含子域名；相同 hostname 只维护一个文档源。
- 当前决策：文档源默认收录整个 hostname，用户可以选择第一个页面的某级路径作为范围；该范围同时约束已有页面、`llms.txt`、Sitemap、页面链接和重定向结果，并按路径段边界匹配同名 HTML、`.md` 与 `.mdx` 路径。
- 当前决策：每次更新优先读取站点根目录的 `llms.txt`；存在有效范围内链接时以该清单作为权威发现来源，否则通过 Sitemap 和页面链接递归发现。后续更新同时刷新范围内的已保存页面并继续发现新页面。
- 当前决策：URL 入队前移除 Fragment 和全部 Query，完成标准化与去重。使用 Fragment 区分页面的 Hash Router 文档站不在支持范围内。每个文档源默认最多发现 1,000 个唯一 URL，用户可以修改上限。
- 当前决策：文档源保存收录范围、抓取方式、页面上限、可选的 HTTP 与浏览器并发覆盖值和定时计划；首次成功读取入口页后保存网站图标 URL。缩小收录范围时立即删除范围外页面及其全文索引。
- 为什么：URL 优先和名称默认值降低配置门槛；`llms.txt` 可以避免不必要的页面渲染与导航递归；hostname、路径范围、去重和数量上限共同避免误抓外站、无关内容、循环和失控扩张。
- 边界 / 非目标：达到上限后不再加入新 URL，但继续完成已入队页面和已有页面更新；除用户主动缩小范围外，页面仅从发现来源中消失时不自动删除；不支持 `llms-full.txt` 或跨 hostname 清单链接。
- 权威入口：[共享 API 类型](../apps/desktop/src/shared/api.ts)。

## 抓取方式与可靠性

- 当前决策：有效的 `llms.txt` 优先于网页抓取方式检测；清单页面通过 HTTP 直接保存 Markdown，只允许无损规范化，明确返回 HTML 时不保存为 Markdown。
- 当前决策：未采用 `llms.txt` 时，自动模式仅对第一个页面同时执行 HTTP 直取和隔离的隐藏浏览器渲染，并比较统一转换后的 Markdown；结果足够接近且浏览器结果没有明显增益时使用 HTTP，否则使用浏览器。
- 当前决策：自动检测结果作用于整个文档源。用户可以手动指定或重新选择抓取方式，后续页面不逐页双通道检测，也不自动回退。
- 当前决策：全局 HTTP 与浏览器默认并发分别为 9 和 5，允许在设置中修改；文档源可分别提供 1 至 32 的可选覆盖值，留空时继承对应全局值。
- 当前决策：单次抓取尝试 30 秒超时，失败后最多重试 3 次。网络错误、超时、HTTP 408、429 和 5xx 可重试，429 优先遵守 `Retry-After`。
- 当前决策：更新失败保留旧 Markdown 和抓取时间；新页面失败不创建记录；明确返回 404 或 410 时删除页面及其全文索引。
- 为什么：优先选择更轻量的 HTTP 路径，同时保证依赖客户端渲染的文档站能够被完整收录；失败保护避免一次异常破坏已有知识库。
- 边界 / 非目标：浏览器窗口禁用 Node 集成并启用上下文隔离和沙箱，禁止弹窗、下载、权限申请及无关导航；只抓取无需登录即可读取的公开内容，不保存或注入登录态，不处理验证码、Cloudflare 挑战及其他反爬机制；不额外控制请求间隔。

## 本地内容与知识库浏览

- 当前决策：每个成功页面维护标题、标准化 URL、最近成功抓取时间、Markdown、语言和实际抓取方式；HTML 页面读取 `lang`，直接获取的 Markdown 和其他缺少语言标签的页面使用 `und`。
- 当前决策：SQLite 保存文档源与页面，FTS5 索引标题和 Markdown 正文。不保存独立树结构，界面根据 URL 路径动态生成目录树。
- 当前决策：本地文档源列表和云端公开目录同时展示页面数与内容大小。内容大小按该文档源已保存 Markdown 正文的 UTF-8 字节数求和；同一云端 revision 在下载前后使用相同原始值，并自动显示为 `B`、`KB`、`MB`、`GB` 等单位。
- 当前决策：知识库页面提供 URL 树、Markdown 预览和正文关键词过滤。过滤结果保留命中页面的祖先层级并自动展开，清空关键词后恢复完整树。
- 当前决策：文档树侧边栏拥有独立滚动区域，不带动正文预览；产品不提供独立的全文搜索页面。
- 为什么：最小字段足以支持本地浏览和 Agent 阅读；由 URL 派生树可以避免维护重复层级数据；统一的内容大小让用户无需打开数据库即可判断本地文档规模。
- 边界 / 非目标：内容大小不包含 JSON 传输包装、SQLite 文件、FTS 索引、元数据、空闲空间或压缩网络流量。数据库可以增加主键和文档源外键作为内部关联字段，但不扩展新的页面产品字段。

## 更新、调度与应用生命周期

- 当前决策：用户可以手动更新文档源；同一文档源同一时间只运行一个抓取任务，并通过实时进度和节点关系图查看状态。
- 当前决策：定时抓取默认关闭，仅在用户配置并启用后运行。文档源页面使用“文档源”和“定时更新”两个 Tab，后者集中列出已设置计划的文档源并提供空状态和编辑入口。
- 当前决策：关闭主窗口后应用驻留托盘，已启用的定时任务继续运行；从托盘显式退出时停止应用和调度器。
- 当前决策：CLI 只执行用户显式发起的前台任务，保留桌面端保存的计划字段但不创建或运行本地计划，也不执行云端自动同步。
- 为什么：集中管理计划便于发现和修改自动任务；驻留托盘保证定时更新不依赖主窗口保持打开。
- 边界 / 非目标：不为定时更新新增侧边栏菜单；手动任务与定时任务不得相互覆盖。

## 应用版本更新

- 当前决策：CLI 以 npm 的 `@boses/cli` 最新稳定版本为更新来源。交互终端每天首次运行时，在独立进程中最多检查 5 秒并缓存结果，不阻塞当前命令；用户可通过 `loci update` 前台立即检查。MCP stdio 与非交互调用不检查也不输出更新提示。
- 当前决策：桌面端启动后每天在主进程后台检查一次 GitHub Releases，并只识别 `loci-v*` 的正式桌面发布，避免将 CLI 发布误报为桌面更新。用户可在“系统设置 → 关于 Loci”手动检查，并打开对应 Release 下载页面。
- 当前决策：桌面端只负责检测与跳转下载，不自动下载、覆盖安装或重启应用。macOS 未签名版本提示用户手动安装 DMG，并按系统 Gatekeeper 提示确认打开。
- 为什么：CLI 的短生命周期不能被网络请求拖慢；桌面端需要区分同仓库的两个发布通道。手动安装同时适配当前开源、未签名的跨平台发布方式。
- 边界 / 非目标：不提供常驻更新守护进程、自动安装、增量更新、预发布版本检测或非交互终端提示。
- 权威入口：[CLI 安装与使用](../apps/cli/README.md)、[项目说明](../README.md)。

## MCP 与 Agent 使用

- 当前决策：产品只向 Agent 暴露一个名为 `loci` 的逻辑 MCP。只安装桌面端时使用随 Electron 主进程启动、仅绑定 `127.0.0.1` 的 Streamable HTTP；只安装 CLI 时由 Agent 按需拉起 `loci mcp stdio`；两者同时安装时优先 CLI stdio，桌面 HTTP 作为回退。
- 当前决策：桌面端和 CLI 复用同一个 MCP Server、工具 Schema 和本地数据库。不同 Agent 可以各自拉起 stdio 进程，但不能在同一客户端中同时注册重复的 CLI 与桌面工具。产品公开命名统一使用 `Loci`、`loci_*` 和 `Loci*`。
- 当前决策：CLI 对已内置客户端提供一键写入，并可输出不修改客户端文件的 Cursor `mcpServers` 风格 stdio 或 HTTP 配置，供 Kimi Code 等兼容该结构的本机客户端复制使用；该片段是客户端约定，不宣称为 MCP 协议统一配置格式。
- 当前决策：MCP 使用“文档库”表示一个网站知识库，使用“文件”表示单个 Markdown 页面；提供本地文档库的添加、批量同步、同步状态、分页列表、目录、批量读取、关键词搜索和删除，以及云端公开目录查询和快照拉取，共十个工具。
- 当前决策：Agent 先查询本地文档库；本地缺失时只读查询云端公开目录，用户确认后才拉取匹配快照；没有云端匹配或用户不选择拉取时，再确认官方来源并由用户授权首次抓取。云端查询不修改状态，云端拉取、首次抓取和主动同步都需要用户确认。
- 当前决策：添加与同步默认异步启动并返回状态；Agent 可以轮询，也可以显式等待完成并接收进度通知。部分页面失败必须作为结构化结果返回，不掩盖已成功内容。
- 当前决策：目录使用稳定派生 ID 和渐进展开；文件使用数据库 ID。搜索返回最佳匹配段落、小节与来源，读取支持按小节和偏移量续读。
- 当前决策：全部工具提供输出 Schema，并同时返回可读文本和结构化内容。
- 为什么：渐进目录、定位搜索和按需读取可以控制上下文规模；异步任务避免长时间阻塞 Agent 调用。
- 边界 / 非目标：MCP 不允许单独删除同步文件，只允许永久删除整个文档库；HTTP transport 的非本机 Host 或 Origin 不得访问。CLI stdio 不作为后台常驻服务。
- 权威入口：[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)、[共享 API 类型](../apps/desktop/src/shared/api.ts)。

## 设置与本地数据

- 当前决策：设置页分别保存 HTTP MCP 端口、HTTP 默认并发、浏览器默认并发和主题。每个区块独立异步保存并提供局部反馈，不阻塞其他设置。
- 当前决策：HTTP MCP 默认端口为 `37373`，允许范围为 1024 至 65535；切换前验证端口可用，失败时保留原服务和原设置。CLI stdio 不使用端口。
- 当前决策：主题支持自动、浅色和深色；自动模式跟随系统并响应变化，保存后立即应用并在重启后保留。
- 当前决策：SQLite 数据库位于桌面端与 CLI 共同解析的标准 Loci 数据目录；桌面界面、CLI 和两种 MCP transport 直接复用同一份数据。SQLite 使用 WAL 与忙等待支持跨进程访问，同一文档源同步和维护操作由跨进程锁仲裁。
- 为什么：局部保存缩短可感知等待时间，也避免无关设置互相阻塞；单一数据源防止桌面端与 Agent 结果不一致。
- 边界 / 非目标：本地创建和抓取的文档库不会上传；云端副本只允许服务器到本地客户端的单向同步，不提供双向同步和冲突合并。

## 可选云端文档库

- 当前决策：仓库提供可选的单实例 Hono 服务，通过 SQLite 持久化公开文档库、抓取计划和发布快照；Docker Compose 同时编排服务端、仅内网开放的 Browserless Chromium 和持久化卷。
- 当前决策：普通用户无需登录即可浏览服务器公开目录并下载完整快照。桌面端、CLI 和 MCP 把快照事务性保存到共享本地数据库，下载后可以离线浏览并通过本机 MCP 读取。
- 当前决策：公开目录提供当前发布快照的页面数和下载后将保存的 Markdown 内容大小。CLI 与桌面端按 1024 进制显示 `B`、`KB`、`MB`、`GB` 等人类可读单位，公开 API 与 MCP 结构化输出保留原始字节整数。
- 当前决策：云端副本记录规范化的来源后端地址和服务端文档库 ID，只能从原后端更新。切换后端后旧副本继续保留，但停止手动和自动同步；切回原地址后可以恢复同步。
- 当前决策：用户可以手动更新云端副本；桌面端还可以启用自动同步，在应用启动时和持续运行期间每天检查一次。CLI 只执行显式手动更新，并保留桌面端保存的自动同步标记。
- 当前决策：服务器文档源、抓取规则、计划和同步任务只允许管理员管理。桌面端令牌只保存在 Electron 主进程内存中；CLI 管理员 Token 只保存在当前交互进程内存中，两者退出后都不保留凭据。
- 当前决策：桌面端、CLI 和服务端复用 `@loci/core` 的页面发现、URL 规则、HTTP 与浏览器抓取编排和重试能力。桌面端使用隔离 Electron 浏览器，CLI 使用本地 Playwright Chromium，服务端通过 `playwright-core` 连接 Browserless，并对 HTTP 与浏览器导航执行 SSRF 防护。
- 为什么：可选服务器可以集中维护公共技术文档，同时保留本地优先、离线可读和 Agent 只访问本机数据的使用方式；目录中的内容大小让用户能在下载前判断正文规模并与下载后的本地数据直接比较；单向同步避免引入账号体系、所有权和冲突合并复杂度。
- 边界 / 非目标：内容大小不表示 SQLite 文件占用、JSON 快照实际字节数或压缩后的网络流量；不提供普通用户账号、私有服务器文档、多租户权限、客户端内容上传、双向同步或多实例服务端；浏览器服务不直接暴露公网，也不处理登录态、验证码、Cloudflare 挑战及其他反爬绕过能力。
- 权威入口：[Loci Server 部署与 API](../apps/server/README.md)、[共享 API 类型](../apps/desktop/src/shared/api.ts)。
