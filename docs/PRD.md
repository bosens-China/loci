# Loci 产品 PRD

## 产品与数据边界

Loci 为开发者和 Agent 保存可在本机复查的技术文档。用户从任意公开文档页或公开 GitHub 仓库开始收录，得到含来源 URL 的 Markdown，在离线时仍可浏览、检索和编辑。采集范围为无需登录即可读取的内容。产品不提供登录态、验证码处理、原始 HTML 归档或历史版本检索。

CLI 是 npm 分发入口，包含本机 Web UI 和 `use-loci` Skill。CLI 直接调用本地 Runtime，Web UI 经回环 HTTP 调用同一 Runtime。两者共享 SQLite 文档库、FTS5 索引、库级锁和设置。Agent 使用用户环境中的 CLI 与 JSON 输出。用户数据保存在本机。参见 [项目说明](../README.md) 和 [本机 HTTP 契约](../packages/runtime/HTTP_API.md)。

## 抓取执行与状态

- `loci fetch` 和 `loci update` 默认按库启动或复用抓取，运行记录可查后返回。每个后台进程在抓取结束时退出。`--wait` 在前台等待，进度写入 stderr。用 `loci cancel <lib>` 可单独取消某个库。`loci ui` 默认监听 `127.0.0.1:4520`，打印地址并打开浏览器。可选择其他端口或跳过打开浏览器。关闭浏览器标签页后终端仍可运行；终止 UI 进程会关闭 HTTP 并取消它负责的抓取。回环接口检查 Host，并验证浏览器写请求的 Origin。
- 同库同类型、同目标的后台抓取复用在途工作。其他后台抓取请求在库被占用期间得到明确冲突，可在当前任务结束后重试。库锁协调精确页面抓取、整库更新和内容修改；不同库可独立运行。SQLite 保存最近进度、当前 URL、计数、起止时间和失败原因，其他 CLI 或 UI 进程可读取。持有者异常退出时，查询会将中断的运行收口为失败。用户可重新发起更新。
- 完全成功、部分成功、失败和取消分别可见。普通整库抓取在提交时更新正文、索引、来源解析结果与运行记录。全部失败或在提交前取消时保留旧正文；部分失败仍可读取成功提交的内容。正常网页更新会处理明确的 404/410 和已确认的重复 URL，临时网络失败保留旧正文。
- `loci upgrade` 检查 npm 上的 CLI 版本；`loci update <lib>` 刷新文档库。交互终端与 Web 可利用缓存提示可用的新版本。共享缓存的 CLI 和 Web 复用同一次在途检查，Web 在检查完成后刷新提示。参见 [基础命令与运行设置](../apps/docs/docs/cli/commands/basics.mdx)。

## 文档来源与收录范围

- 网页库按规范化 hostname 和收录路径识别，公开 GitHub 仓库按 `owner/repo` 识别。同一来源与版本复用已有库，其他版本独立保存。新库默认使用 `未分类` 和 `latest`。更新已有库只修改显式指定的分类和版本。网页默认 `auto`、根路径和 1,000 页，可指定收录路径、排除路径正则及页数上限。排除正则匹配 URL pathname。切换来源身份、缩小收录范围或增加排除规则可能在保存时一并清除旧正文、索引或指定页面目标。
- 公开 GitHub 仓库读取默认分支和提交 SHA，按提交 ZIP 采集 Markdown/MDX，保留相对目录。Markdown 的相对文档链接和图片指向对应提交，MDX 保留源文。SHA 未变时可跳过下载，完整成功的快照原子替换旧文档。ZIP 与 Markdown 总量分别有可配置的大小上限，条目路径及展开大小在读取时校验。
- 普通站点优先使用有效的同站 `llms.txt` 清单。对有特征的接口文档入口尝试 OpenAPI 3 或 Swagger 2 JSON，使用实际规范 URL 生成概览、按 tag 组织的接口和共享模型，成功提交时替换旧快照。GitHub/GitLab Pages 静态域名在检查清单后直接进入网页流程。
- 普通网页优先按有效 Sitemap 发现，无法使用时按页面链接扩展。发现受 hostname、路径、排除规则和页数约束。URL 规范化去除 query 和 fragment，不能用片段区分多个独立页面。对普通网页，`auto` 在具备浏览器能力时比较入口页的 HTTP 与渲染结果，缺少浏览器时使用 HTTP。有效的清单、规范和仓库快照直接走 HTTP。
- 只读探测可返回发现方式、规模估计和路径分布。已知页面可精确抓取，无需递归发现。网页库中的显式页面可以越过收录路径，仍须同 hostname 且符合排除规则。整库更新可再次刷新这些页面。旧版审查库的普通更新只刷新已收录的 URL 和已登记的指定页面。参见 [页面发现与抓取](../apps/docs/docs/cli/crawling.mdx)。

## 查询、阅读与编辑

- 文档记录保留标题、来源 URL、Markdown、语言和抓取元数据。网页按 URL 路径组成树，仓库和 OpenAPI 文档按逻辑路径组成树。目录按父节点和深度展开。关键词筛选保留匹配分支及其祖先，并给出目录命中数和总数。
- 全文搜索可跨库或限定多个库和路径前缀。每组查询依次尝试全词、任一词及元数据子串匹配，多组结果合并去重。结果可返回文档 ID、小节、匹配段落或按库分组的目录树。
- 读取支持一个或多个文档 ID、唯一短 ID、文件路径及子树路径。目标按树序去重，支持按小节读取和按字符偏移续读。正文带可引用的原文 URL。
- 可写库支持创建和更新文档，以及按标题小节增删改。整库和指定页面抓取都保留手工文档的正文与索引。结构变更后须重新读取小节 ID。同一次小节修改可沿用操作 ID 和原始参数安全重试，包括请求携带文档版本时。删除可以指定文档或子树，也可以显式删除整库。正文修改与索引在事务中保持一致。
- Web UI 从库列表进入目录与阅读器，支持筛选、选择并预览多个文件、编辑正文及管理小节。本机 Agent、无头浏览器、设置与数据分别有独立入口。参见 [本地文档库](../apps/docs/docs/cli/commands/local-library.mdx)。

## Agent、Skill 与全局规则

1. 使用 `loci list --json` 选择与项目版本匹配的库。
2. 用 `loci tree <lib> --query <kw...> --json` 或 `loci search <queries...> --library <lib> --tree --json` 定位。可省略目录筛选词、搜索范围或树形输出。
3. 用 `loci read <targets...> --library <lib> --json` 核对正文，引用原文 URL。
4. 缺库时核实官方 URL，确认来源与范围后运行 `loci fetch <url>`；已有库过时时运行 `loci update <lib>`。已有同一授权可直接使用。
5. 轮询 `loci status <lib> --json` 至终态，从 `error` 和 `failures` 查看具体原因，抓取完成后回到定位与阅读。省略库可查询所有有记录的库。
6. 用户要求时编辑文档或小节；删除、刻意覆盖、可能裁剪已有内容的配置修改须明确授权。只需版本亮点时可查官方发布说明，资料不足时可选用其他合适的文档来源。

`loci setup [client]` 与 Web 的 Agent 接入页共用用户级升级流程。接入时自动备份已有本地修改或外部安装的 Skill，再安装当前版本。外部链接的源目录保留，接入结果提供备份路径。同步会合并完整成对的 Loci 规则区块、清理可识别的旧版 Loci MCP 条目，并保留个人规则和其他 MCP 服务。重复接入应无变化。文件不可读或规则边界不明确时报告具体路径和原因。参见 [接入 Agent](../apps/docs/docs/agent/overview.mdx)。

Codex、Cursor、VS Code、Claude Code、Antigravity 和 Pi 使用各自的目标路径。规则可单独写入，Codex 和 Cursor 可按现有配置加入 Context7 兜底说明。Pi 接入遵循其配置目录和全局规则查找顺序，移除专用 Skill 时保留通用安装。

`loci skills` 管理项目或全局的内置 Skill。默认 `universal`、当前项目，可显式选择客户端与作用域。安装记录和所有权标记确认目标，安装、替换与删除由文件锁和台账保护。`.agents/skills/use-loci` 是发布包复制的唯一内容源。Skill 保留查询流程和授权边界，CLI 参数与示例由官网维护。站点构建生成 `llms.txt` 和逐页 Markdown 供 Agent 按需读取。参见 [使用 Skill](../apps/docs/docs/agent/skill.mdx) 和 [配置全局规则](../apps/docs/docs/agent/global-rules.mdx)。

## 配置、浏览器与备份

- 本地设置涵盖主题、HTTP 和浏览器并发、重试、批次间隔及 GitHub 大小限制，域名策略可以单独保存。界面和 CLI 使用共享的校验边界。浏览器管理共用本机缓存，提供安装、真实启动状态检查和卸载。`LOCI_DATA_DIR` 和 `LOCI_CACHE_DIR` 分别选择数据与缓存位置。
- 开发入口 `pnpm dev` 使用隔离数据、缓存与模拟用户目录，`pnpm dev:user` 使用真实用户文件。开发 Web 和 API 默认分别监听回环端口 12333 和 12334。
- 导出生成包含索引与分域 JSON 的 ZIP。导出可选择全部、分类或文档库。导入前校验文件路径、大小、SHA-256、记录数与引用，在维护锁和单个事务中匹配旧库，先删除再恢复全部关联内容，保留其他库。除库 ID 外，可写库按来源和版本匹配，旧版只读快照按原服务器地址和远端库 ID 匹配。云端仅保留旧备份的本地恢复能力。全量替换清空所有本地库；完整备份还可恢复域名策略和设置。机器本地的 Skill 台账及客户端规则独立管理。参见 [数据备份与恢复](../apps/docs/docs/cli/commands/data.mdx)。
- CLI 和 Web 提供两种清空范围，并复用同一维护锁及事务。仅清空文档保留文档库与收录目标，可重新抓取同一 GitHub 提交。清空全部库还清理抓取记录。两者保留分类和全局设置。确认前显示当前库数和文档数，CLI 可以用 `--yes` 明确授权非交互执行。
- 删除小节、覆盖正文、导入备份和会裁剪已有内容的收录设置变更在交互入口确认。CLI 导出覆盖同名备份、移除域名策略时也需要确认。交互默认取消，已获授权的非交互调用使用 `--yes`。
