# Loci 产品 PRD

## 产品定位

- 当前决策：Loci 是面向 AI Agent 的本地文档知识库。用户提供公开文档页面后，应用发现同站页面，把网页转换或直接保存为 Markdown，并通过共享数据库提供桌面端、CLI 和本机 MCP 访问。
- 为什么：常用技术文档分散在不同站点，本地统一收录可以减少重复查找，并让人和 Agent 共享同一份可检查的数据。
- 边界 / 非目标：本地文档不上传；可选服务端只维护公开文档库的只读快照。不提供多用户私有文档、登录态抓取、验证码或 Cloudflare 挑战绕过、代理池、原始 HTML、页面截图、历史版本、向量或语义检索。
- 权威入口：[README](../README.md)、[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)。

## CLI 产品入口

- 当前决策：Loci CLI 作为通过 npm 分发的独立产品运行，不依赖 Electron、桌面窗口或桌面进程；它与桌面端共享本地数据库和领域实现，覆盖文档源、知识库、云端公开库、远程 Server 管理、数据维护、诊断和 MCP 核心能力。
- 当前决策：CLI 面向终端用户，命令说明、交互和反馈使用中文；除专门用于复制的 MCP 客户端配置片段外，常规命令输出只承诺适合人阅读，不提供稳定 JSON 契约。AI Agent 使用 Loci MCP。普通命令前台完成后退出，不隐式启动后台任务。
- 当前决策：根命令默认显示总帮助。具体命令优先使用位置参数和安全默认值减少输入：新建文档源只需提供第一个页面 URL，名称自动生成，抓取方式、页面上限和收录范围按“显式参数、CLI 安全偏好、产品基础默认值”的顺序解析，并发与 GitHub 大小覆盖留空时继承全局设置；更新时只修改显式提供的字段。省略有歧义的资源时在交互终端中选择；删除、覆盖、清空、客户端写入和管理员凭据不设置可导致误操作的隐式默认。
- 当前决策：CLI 将安全且可逆的交互偏好保存在共享 SQLite 中：本地创建记住抓取方式、页面上限、收录路径层级和首次同步选择；Admin 按规范化 Server 地址记住账号、创建配置、更新计划和上次批量同步勾选；资源选择、数据目录和 MCP 客户端配置记住最近成功值。单个候选直接使用或默认勾选，多个候选高亮最近值；显式参数优先，失效偏好回退到当前状态或产品默认值。密码、Token、搜索词、删除目标和危险确认不保存。
- 当前决策：`loci source add` 创建后默认执行一次前台同步；`--no-sync` 只保存配置，`--background` 使用一次性分离子进程同步并在完成后自然退出。显式后台模式不建立长期守护进程，结果通过持久抓取记录审查。
- 当前决策：CLI 不维护隐藏守护进程。用户可以显式运行 `loci schedule run`，以前台常驻方式执行本地计划和云端副本自动同步，退出后停止；CLI 不复制主题、窗口、托盘和开机启动等桌面生命周期能力。HTTP 抓取无需浏览器；SPA 抓取使用用户显式安装的 Playwright Chromium headless shell。
- 当前决策：CLI 管理员交互会话每次读取账号和隐藏密码；脚本化的列表、创建、更新、删除、批量同步、任务查询和取消命令只从 `LOCI_ADMIN_USERNAME` 与 `LOCI_ADMIN_PASSWORD` 环境变量读取凭据。密码与 Token 均只保存在当前进程内存中，命令结束后清除。
- 当前决策：CLI 数据维护支持导出与覆盖导入、仅清空全部文档并保留文档源，以及清空全部文档源及其关联数据。覆盖和清空操作默认要求确认并使用维护锁，清空文档源不删除应用设置或远程 Server 内容。
- 当前决策：省略导出路径时使用包含 UTC 毫秒时间的备份文件名，并以独占创建避免静默覆盖；显式路径代表用户已选定目标，文件存在时直接覆盖，不再二次确认。
- 为什么：独立 CLI 让无法安装桌面端的环境仍能使用核心能力；共享实现和数据避免形成第二套产品语义；显式前台运行使进程生命周期和资源消耗可预期。
- 边界 / 非目标：CLI 不提供机器可读输出兼容承诺，不自动下载浏览器，不维护本地常驻守护进程，也不新增普通用户账号、私有云端文档或登录态抓取。
- 权威入口：[CLI 安装与使用](../apps/docs/docs/cli/getting-started.mdx)。

## 文档源与页面发现

- 当前决策：用户可以从任意公开文档页创建文档源，该 URL 统一称为“第一个页面”，不要求是网站首页。
- 当前决策：添加文档源时先填写 URL；名称为空且未被用户修改时根据域名自动填入，用户仍可自由编辑。
- 当前决策：网页文档源以第一个页面完成跳转后的 hostname 为边界，默认不包含子域名；本地网页库按规范化 hostname 与收录路径共同识别，同域同路径复用、同域不同路径可拆成独立逻辑文档库。公开 GitHub 仓库按规范化的 `owner/repo` 标识区分，因此同一 `github.com` 下可以维护多个仓库，但同一仓库不能重复创建。
- 当前决策：文档源默认收录整个 hostname，用户可以选择第一个页面的某级路径作为范围；该范围同时约束已有页面、`llms.txt`、Sitemap、页面链接和重定向结果，并按路径段边界匹配同名 HTML、`.md` 与 `.mdx` 路径。
- 当前决策：每次更新优先读取站点根目录的 `llms.txt`；存在有效范围内链接时以该清单作为权威发现来源。未命中时，明确位于 `*.github.io` 或 `*.gitlab.io` 的静态 Pages 直接进入网页流程；其他 URL 命中 Swagger UI、Knife4j、ReDoc、FastAPI `/docs` 或常见规范路径特征时，并发探测同 hostname 的 OpenAPI 3、Swagger 2 和分组配置 JSON，命中后将规范作为权威来源，否则通过 Sitemap 和页面链接递归发现。后续更新刷新所采用发现来源的文档。
- 当前决策：符合 `github.com/<owner>/<repo>` 的公开仓库 URL 在网页发现前进入 GitHub 仓库流程，自动规范化为仓库首页并读取默认分支；不要求用户选择文档类型、抓取方式或分支。
- 当前决策：URL 入队前移除 Fragment 和全部 Query，完成标准化与去重。普通网页不支持使用 Fragment 区分页面的 Hash Router 文档站；能够发现同站 OpenAPI JSON 的接口阅读页不受此限制。每个文档源默认最多发现 1,000 个唯一 URL，用户可以修改上限。
- 当前决策：文档源保存类型、收录范围、抓取方式、页面上限、可选的 HTTP 与浏览器并发覆盖值和定时计划；GitHub 仓库额外保存可选的 ZIP 与 Markdown 总量覆盖值、默认分支和成功提交 SHA。首次成功读取入口页后保存网站图标 URL。缩小网页收录范围时立即删除范围外页面及其全文索引。
- 为什么：URL 优先和名称默认值降低配置门槛；`llms.txt` 与 OpenAPI 可以避免不必要的页面渲染与导航递归；hostname、路径范围、去重和数量上限共同避免误抓外站、无关内容、循环和失控扩张。
- 边界 / 非目标：达到上限后不再加入新 URL，但继续完成已入队页面和已有页面更新；除用户主动缩小范围外，页面仅从发现来源中消失时不自动删除；不支持 `llms-full.txt` 或跨 hostname 清单链接。
- 权威入口：[共享 API 类型](../apps/desktop/src/shared/api.ts)。

## 抓取方式与可靠性

- 当前决策：有效的 `llms.txt` 优先于网页抓取方式检测；清单页面通过 HTTP 直接保存 Markdown，只允许无损规范化，明确返回 HTML 时不保存为 Markdown。
- 当前决策：OpenAPI 探测位于有效 `llms.txt` 和 GitHub/GitLab Pages 静态域名判断之后、普通网页读取之前。只在入口 URL 具有常见接口文档特征时并发请求入口、`/openapi.json`、`/v3/api-docs/swagger-config`、`/v3/api-docs`、`/swagger-resources` 和 `/v2/api-docs`；只有 JSON 通过 OpenAPI、Swagger 或分组配置结构校验才算命中，全部未命中时静默继续网页流程。
- 当前决策：命中的 OpenAPI 3 或 Swagger 2 JSON 按真实规范 URL 转换为 Markdown，保留标题、版本、说明、服务地址、接口、参数、请求体、响应、认证方案和数据模型；分组配置中的同 hostname 规范分别保存。转换完成后不再发现 Sitemap、页面链接或启动浏览器。本阶段不解析 YAML 规范，也不下载描述中的图片。
- 当前决策：GitHub 仓库通过 GitHub API 读取默认分支与提交 SHA，再把该提交 ZIP 流式写入临时文件；不执行 Git clone，也不把整个仓库展开到磁盘。ZIP 逐项读取 `.md`，文件名直接作为标题，仓库相对路径作为知识库目录，不从 H1 或 frontmatter 推导标题。
- 当前决策：GitHub Markdown 使用 AST 改写相对图片、链接和引用定义；图片指向固定提交的 Raw URL，链接指向固定提交的 Blob URL，代码块与绝对 URL 保持不变。图片不下载到本地，原始 HTML、MDX 和 Vue 组件属性不改写。
- 当前决策：未采用 `llms.txt` 时，自动模式仅对第一个页面同时执行 HTTP 直取和隔离的隐藏浏览器渲染，并比较统一转换后的 Markdown；结果足够接近且浏览器结果没有明显增益时使用 HTTP，否则使用浏览器。
- 当前决策：自动检测结果作用于整个文档源。用户可以手动指定或重新选择抓取方式，后续页面不逐页双通道检测，也不自动回退。
- 当前决策：全局 HTTP 与浏览器默认并发分别为 9 和 5，允许在设置中修改；文档源可分别提供 1 至 32 的可选覆盖值，留空时继承对应全局值。
- 当前决策：有效 `llms.txt` 列出的页面，以及明确位于 `*.github.io` 或 `*.gitlab.io` 的 GitHub Pages 与 GitLab Pages HTTP 页面，按当次页面上限整批并发，不应用普通站点的并发覆盖、批次间隔或暂停等待；两类 Pages 的自定义域名均不自动推断，HTTP 429 仍按通用规则重试。
- 当前决策：单次抓取尝试 30 秒超时，失败后最多重试 3 次。网络错误、超时、HTTP 408、429 和 5xx 可重试，429 优先遵守 `Retry-After`。
- 当前决策：GitHub ZIP 默认下载上限为 200 MB，所收录 Markdown 默认总量上限为 100 MB，单文件最多 5 MB，ZIP 最多 100,000 个条目；全局大小默认值可修改，单仓库可覆盖。ZIP 下载连接等待最多 30 秒，连续 60 秒无数据时中止，并拒绝路径穿越、Markdown 软链接、条目大小不一致和超限内容。
- 当前决策：GitHub 成功同步以完整快照事务性替换旧文档和全文索引，因此仓库已删除或移动的 Markdown 会同步删除；下载、解析或安全校验失败时保留旧快照。提交 SHA 未变化时跳过 ZIP 下载；超限失败记录提交、限制类型和当时上限，同一提交在对应上限提高前不重复下载。
- 当前决策：更新失败保留旧 Markdown 和抓取时间；新页面失败不创建记录；明确返回 404 或 410 时删除页面及其全文索引。
- 当前决策：每次本地抓取持久化来源、运行 ID、状态、聚合计数和有界的页面级失败结构；CLI 通过 `source runs` 列出运行，通过 `source logs` 查看失败 URL、原因、状态码和可重试性，不保存无界原始控制台日志。
- 为什么：优先选择结构化且更轻量的 HTTP 来源，同时保证没有 `llms.txt` 或 OpenAPI 的客户端渲染文档站能够被完整收录；失败保护避免一次异常破坏已有知识库。
- 边界 / 非目标：浏览器窗口禁用 Node 集成并启用上下文隔离和沙箱，禁止弹窗、下载、权限申请及无关导航；只抓取无需登录即可读取的公开内容，不保存或注入登录态，不处理验证码、Cloudflare 挑战及其他反爬机制；GitHub 不支持私有仓库、身份认证、非默认分支、子目录范围、Git LFS 或仓库历史版本；不额外控制请求间隔。

## 本地内容与知识库浏览

- 当前决策：每个成功页面维护标题、标准化 URL、最近成功抓取时间、Markdown、语言和实际抓取方式；GitHub 文档还维护仓库相对路径。HTML 页面读取 `lang`，直接获取的 Markdown 和其他缺少语言标签的页面使用 `und`。
- 当前决策：SQLite 保存文档源与页面，FTS5 索引标题和 Markdown 正文。不保存独立树结构；网页根据 URL 路径、GitHub 仓库根据相对文件路径动态生成目录树。
- 当前决策：本地文档源列表和云端公开目录同时展示页面数与内容大小。内容大小按该文档源已保存 Markdown 正文的 UTF-8 字节数求和；同一云端 revision 在下载前后使用相同原始值，并自动显示为 `B`、`KB`、`MB`、`GB` 等单位。
- 当前决策：知识库页面提供 URL 树、Markdown 预览和正文关键词过滤。过滤结果保留命中页面的祖先层级并自动展开，清空关键词后恢复完整树。
- 当前决策：文档树侧边栏拥有独立滚动区域，不带动正文预览；产品不提供独立的全文搜索页面。
- 为什么：最小字段足以支持本地浏览和 Agent 阅读；由 URL 派生树可以避免维护重复层级数据；统一的内容大小让用户无需打开数据库即可判断本地文档规模。
- 边界 / 非目标：内容大小不包含 JSON 传输包装、SQLite 文件、FTS 索引、元数据、空闲空间或压缩网络流量。数据库可以增加主键和文档源外键作为内部关联字段，但不扩展新的页面产品字段。

## 更新、调度与应用生命周期

- 当前决策：用户可以手动更新文档源；同一进程的重复调用复用同一个 Promise 和最新进度，桌面、CLI、MCP 或定时任务跨进程重复调用时复用持久抓取记录，不启动第二次抓取。不同文档源保持独立并行，并通过实时进度和节点关系图查看状态。
- 当前决策：抓取结果先暂存，只有任务成功且未取消时才事务性提交文档、全文索引和成功 revision。取消信号贯穿 HTTP、浏览器、GitHub 元数据、ZIP 下载与遍历；失败或取消保留旧内容并允许重试。
- 当前决策：定时抓取默认关闭，仅在用户配置并启用后运行。文档源页面使用“文档源”和“定时更新”两个 Tab，后者集中列出已设置计划的文档源并提供空状态和编辑入口。
- 当前决策：关闭主窗口后应用驻留托盘，已启用的定时任务继续运行；从托盘显式退出时停止应用和调度器。
- 当前决策：CLI 可以列出和修改本地文档源计划，并通过用户显式启动的 `loci schedule run` 执行本地 Cron 与云端副本每日自动同步；该进程以前台常驻方式运行，退出后不残留后台服务。桌面端与 CLI 计划运行器使用同一跨进程锁，同一数据目录只允许一个计划宿主。
- 为什么：集中管理计划便于发现和修改自动任务；桌面端驻留托盘保证定时更新不依赖主窗口保持打开；CLI 的显式前台宿主适配无桌面环境，同时保持生命周期可见。
- 边界 / 非目标：不为定时更新新增侧边栏菜单；手动任务与定时任务不得相互覆盖。

## 应用版本更新

- 当前决策：CLI 以 npm 的 `@boses/cli` 最新稳定版本为更新来源。交互终端每天首次运行时，在独立进程中最多检查 5 秒并缓存结果，不阻塞当前命令；用户可通过 `loci update` 前台立即检查。MCP stdio 与非交互调用不检查也不输出更新提示。
- 当前决策：桌面端启动后每天在主进程后台检查一次 GitHub Releases，并只识别 `loci-v*` 的正式桌面发布，避免将同仓库的 CLI 与 Server 发布误报为桌面更新。用户可在“系统设置 → 关于 Loci”手动检查。
- 当前决策：Windows NSIS 与 Linux AppImage 发现新版后自动下载，重复检查复用进行中的检查或下载，并在用户正常退出应用时安装；设置页显示检查、下载进度、等待安装和失败状态，自动更新失败时允许打开对应 Release 手动下载。
- 当前决策：macOS 不启用自动更新器，继续提示用户打开对应 Release 手动安装 DMG；未签名版本按系统 Gatekeeper 提示确认打开。
- 为什么：CLI 的短生命周期不能被网络请求拖慢；桌面端需要区分同仓库的多个发布通道。electron-builder 已原生覆盖 Windows NSIS 和 Linux AppImage 的更新元数据与安装流程，macOS 当前未签名发布仍保留明确的手动路径。
- 边界 / 非目标：不提供常驻更新守护进程、更新频道、预发布版本检测、macOS 自动安装或非交互终端提示。
- 权威入口：[桌面应用快速上手](../apps/docs/docs/desktop/getting-started.mdx)、[CLI 安装与使用](../apps/cli/README.md)、[项目说明](../README.md)。

## MCP 与 Agent 使用

- 当前决策：产品只向 Agent 暴露一个名为 `loci` 的逻辑 MCP。桌面设置页的一键配置和复制片段始终使用随 Electron 主进程启动、仅绑定 `127.0.0.1` 的 Streamable HTTP；CLI 自动配置默认由 Agent 按需拉起 `loci mcp stdio`，也允许用户显式选择 HTTP。两者同时安装时仍只在同一客户端注册其中一个入口。
- 当前决策：桌面端和 CLI 复用同一个 MCP Server、工具 Schema 和本地数据库。不同 Agent 可以各自拉起 stdio 进程，但不能在同一客户端中同时注册重复的 CLI 与桌面工具。产品公开命名统一使用 `Loci`、`loci_*` 和 `Loci*`。
- 当前决策：桌面端、CLI 和运行时共用一份 MCP 客户端能力目录。Codex、Cursor、VS Code、Claude Code 和 Google Antigravity 都支持一键写入与按客户端复制 MCP 配置；其他客户端保留 Cursor `mcpServers` 风格的通用 stdio 或 HTTP 配置。产品面向个人开发者，不提供仅面向企业许可证或付费 API Key 用户的 Gemini CLI 快捷入口。所有片段都是具体客户端约定，不宣称为 MCP 协议统一配置格式。
- 当前决策：一键配置默认优先调用客户端官方命令；命令缺失、超时、执行异常或非零退出时回退到用户级配置文件，没有命令入口的 Antigravity 直接回退。回退按客户端官方结构只新增或替换名为 `loci` 的服务：Codex 使用 `~/.codex/config.toml` 的 `[mcp_servers.loci]`，Cursor 使用 `~/.cursor/mcp.json` 的 `mcpServers.loci`，VS Code 使用默认用户 Profile `mcp.json` 的 `servers.loci`，Claude Code 使用 `~/.claude.json` 的 `mcpServers.loci`，Antigravity 使用 `~/.gemini/config/mcp_config.json` 的 `mcpServers.loci`。文件不存在时创建；已有 JSON/JSONC 或 TOML 保留其他设置与注释；无法安全解析、结构冲突或重复定义时拒绝写入。命令与文件回退共享客户端级 single-flight、跨进程锁和原子替换。
- 当前决策：MCP 使用“文档库”表示一个网站知识库，使用“文件”表示单个 Markdown 页面；提供本地文档库的添加、批量同步、同步状态、同步失败分页、分页列表、目录、批量读取、关键词搜索和删除，以及云端公开目录查询和快照拉取，共十一个工具。
- 当前决策：MCP 新增网页库使用共享产品基础值：`auto`、1000 页、根路径，以及继承全局并发/大小设置；同时允许 Agent 按任务覆盖抓取方式、页面上限、收录路径、HTTP/浏览器并发和 GitHub ZIP/Markdown 大小上限。网页库按域名与规范化收录路径共同复用，同域不同路径可建立独立逻辑文档库。
- 当前决策：CLI、桌面、MCP 和 Server 共享文档源业务字段的产品基础默认值、取值边界、`null` 继承含义和 GitHub 创建/更新规范化；领域层负责最终校验。显式参数优先，CLI 安全偏好只覆盖 CLI 的基础值，MCP 不读取 CLI 偏好。各入口不要求一一对应：CLI 保留提示、确认和前台/后台控制，MCP 保留批量、分页、结构化输出、等待开关和 Agent 专用检索流程。
- 当前决策：MCP 搜索使用 SQLite 传统检索，不引入嵌入模型；每组查询依次尝试全部词全文命中、任意词全文命中、标题或 URL 路径包含，并公开实际检索层级。搜索支持 URL 路径前缀过滤，标题、路径和与建库入口接近程度仅作为轻量重排信号。
- 当前决策：MCP 将文档可用性与同步状态拆分。同步响应仅携带失败总数、原因统计和最多五条样例；完整失败通过持久 `run_id` 分页读取。`library_id` 继续用于实时进度，不新增重复的同步 ID。
- 当前决策：有效 `llms.txt` 是权威清单，清单内页面的 404/410 只记录失败并跳过，不尝试同名 HTML 回退。网页 `auto` 抓取方式仍只根据首次普通页面的 HTTP 与浏览器结果选择，后续页面不因正文偏短重新判定。
- 当前决策：Agent 先查询本地文档库；本地缺失时只读查询云端公开目录，用户确认后才拉取匹配快照；没有云端匹配或用户不选择拉取时，再确认官方来源并由用户授权首次抓取。云端查询不修改状态，云端拉取、首次抓取和主动同步都需要用户确认。
- 当前决策：0 页本地库和云端候选不视为可用文档；空本地库可在授权后重试同步，云端无可用候选、查询或拉取失败、拉取后仍无文件时，再单独确认官方入口并创建本地抓取库。云端同域副本不阻止这个本地回退；已有本地内容在云端不可访问时继续可用并提示新鲜度。
- 当前决策：桌面端和 CLI 可以配置 Agent 的用户级全局规则。Codex 写入 `~/.codex/AGENTS.md`，并优先更新已存在的 `AGENTS.override.md`；VS Code 写入 `~/.copilot/instructions/loci.instructions.md`；Claude Code 写入 `~/.claude/CLAUDE.md`；Google Antigravity 写入 `~/.gemini/GEMINI.md`。Cursor 没有官方稳定的用户级文件路径，因此只提供可复制规则，并引导用户粘贴到 `Customize → Rules → User Rules`；项目根目录和子目录仍可使用 `AGENTS.md`。
- 当前决策：全局规则统一使用 `<!-- loci:start -->` 和 `<!-- loci:end -->` 管理区块。重复配置只替换该区块，保留用户其他内容；标记残缺、重复或顺序错误时拒绝写入。Codex 每次写入都会检查 `~/.agents/skills/context7-mcp/SKILL.md`、`~/.codex/skills/context7-mcp/SKILL.md`、具有完整标记边界的 Context7 全局规则，以及旧版 `<!-- loci-context7:start -->` 与 `<!-- loci-context7:end -->` 组合区块；Context7 晚于 Loci 安装，或已生成组合规则后又写入新 Context7 区块时，再次执行写入会去重并收敛为当前“Loci 优先、Context7 兜底”的单一组合规则。Loci 不常驻监听第三方安装；发现无边界、边界不完整、重复或冲突的 Context7 命令时拒绝修改。文件更新采用原子替换和客户端级跨进程锁，同一客户端的并发调用幂等复用，不同客户端可以独立执行。
- 当前决策：全局规则提供可独立执行的 Loci MCP 使用规范，不依赖、不安装也不绑定 Skill。Agent 先判断任务是否依赖开发者技术文档事实；库、框架、SDK、API、CLI、配置、迁移、版本差异、安装过程和技术专属错误进入 Loci 流程，普通重构、业务逻辑调试、通用编程概念和不依赖外部技术当前行为的代码审查不进入。已安装的 Skill 只补充同一工作流，Loci 不修改、删除或覆盖用户安装的第三方 Skill。
- 当前决策：新闻与时效事件、价格、人物或公司信息、购物、旅行、法律、医疗以及普通网页内容等非技术文档任务直接使用适合该领域的网页或专业来源，不把 Loci 作为通用网页搜索的前置步骤；仅仅提到软件、公司或网页不足以进入 Loci 流程。技术文档范围内除非用户明确指定来源，Agent 按 Loci 本地库、Loci 云端公开目录、用户确认后的官方文档抓取顺序执行。
- 当前决策：Loci 已有文档能够回答时停止检索；本地或云端未命中本身不构成 Context7 兜底条件，Agent 必须先提供官方文档抓取选项。只有技术文档范围内的问题在 Loci 不可用、无法确认官方入口且用户没有指定可用来源、用户拒绝官方抓取、已经提供官方抓取选项后所有已授权获取路径仍失败或没有文件，或者合理检索后证据仍不足时，组合模板才把未解决的概念交给 Context7、定向网页检索或其他文档来源；切换前说明具体原因。用户明确指定来源时尊重当前请求。
- 当前决策：添加与同步默认异步启动并返回状态；Agent 可以轮询，也可以显式等待完成并接收进度通知。部分页面失败必须作为结构化结果返回，不掩盖已成功内容。
- 当前决策：目录使用稳定派生 ID 和渐进展开；文件使用数据库 ID。搜索返回最佳匹配段落、小节与来源，读取支持按小节和偏移量续读。
- 当前决策：全部工具提供输出 Schema，并同时返回可读文本和结构化内容。
- 为什么：渐进目录、定位搜索和按需读取可以控制上下文规模；异步任务避免长时间阻塞 Agent 调用。
- 边界 / 非目标：MCP 不允许单独删除同步文件，只允许永久删除整个文档库；HTTP transport 的非本机 Host 或 Origin 不得访问。CLI stdio 不作为后台常驻服务。
- 权威入口：[MCP 与数据管理](../apps/docs/docs/cli/commands/integrations.mdx)、[Agent 全局规则](../apps/docs/docs/agent/global-rules.mdx)、[Codex 全局接入](../apps/docs/docs/agent/codex.mdx)、[Agent 使用 Skill](../.agents/skills/use-loci/SKILL.md)、[共享客户端目录](../packages/shared/src/mcp-clients.ts)。

## 设置与本地数据

- 当前决策：设置页分别保存 HTTP MCP 端口、HTTP 默认并发、浏览器默认并发、GitHub ZIP 与 Markdown 默认大小和主题。每个区块独立异步保存并提供局部反馈，不阻塞其他设置。
- 当前决策：HTTP MCP 默认端口为 `37373`，允许范围为 1024 至 65535；切换前验证端口可用，失败时保留原服务和原设置。CLI stdio 不使用端口。
- 当前决策：主题支持自动、浅色和深色；自动模式跟随系统并响应变化，保存后立即应用并在重启后保留。
- 当前决策：SQLite 数据库位于桌面端与 CLI 共同解析的标准 Loci 数据目录；桌面界面、CLI 和两种 MCP transport 直接复用同一份数据。SQLite 使用 WAL 与忙等待支持跨进程访问；同一文档源同步使用资源文件租约与持久运行记录，云端快照使用来源级租约，维护操作使用全库排他租约，计划宿主使用单独租约。
- 为什么：局部保存缩短可感知等待时间，也避免无关设置互相阻塞；单一数据源防止桌面端与 Agent 结果不一致。
- 边界 / 非目标：本地创建和抓取的文档库不会上传；云端副本只允许服务器到本地客户端的单向同步，不提供双向同步和冲突合并。

## 可选云端文档库

- 当前决策：仓库提供可选的单实例 Hono 服务，通过 SQLite 持久化公开文档库、抓取计划和发布快照；Docker Compose 同时编排服务端、仅内网开放的 Browserless Chromium 和持久化卷。
- 当前决策：普通用户无需登录即可浏览服务器公开目录并下载完整快照。桌面端、CLI 和 MCP 把快照事务性保存到共享本地数据库，下载后可以离线浏览并通过本机 MCP 读取。
- 当前决策：公开目录提供当前发布快照的页面数和下载后将保存的 Markdown 内容大小。CLI 与桌面端按 1024 进制显示 `B`、`KB`、`MB`、`GB` 等人类可读单位，公开 API 与 MCP 结构化输出保留原始字节整数。
- 当前决策：Server 不发布或公开 0 页快照；客户端过滤旧 Server 返回的 0 页目录项，并在空快照、网络失败或不兼容响应时保留已有本地云端副本，只有通过校验的非空快照才能事务性替换本地内容。
- 当前决策：云端副本记录规范化的来源后端地址和服务端文档库 ID，只能从原后端更新。切换后端后旧副本继续保留，但停止手动和自动同步；切回原地址后可以恢复同步。
- 当前决策：用户可以手动更新云端副本；桌面端计划宿主在应用启动时和持续运行期间每天检查一次，CLI 计划宿主启动时和持续运行期间每天检查一次。自动同步开关由桌面端与 CLI 共享，未运行计划宿主时不执行。
- 当前决策：服务器文档源保存第一个页面、路径收录范围、页面上限和计划；同一 hostname 可以按不同范围建立多个文档库，同一 `hostname + scopePath` 不允许重复。旧数据库迁移后已有文档库范围为 `/`，缩小范围时立即删除范围外页面。
- 当前决策：服务器文档源、抓取规则、计划和同步任务只允许管理员管理。管理员可以选择多个或全部文档库同步；Server 统一排队并最多同时运行 3 个文档库。任务、进度、owner 和租约持久化到 SQLite，同一数据库上的多个 Server 进程通过活动任务唯一约束复用同一文档库任务；租约过期后失败收口并允许重试。取消幂等且不会提交工作文档、成功 revision 或公开快照。
- 当前决策：桌面端令牌只保存在 Electron 主进程内存中；CLI 交互与脚本化管理员 Token 只保存在当前进程内存中，两者退出后都不保留凭据。
- 当前决策：桌面端、CLI 和服务端复用 `@loci/core` 的页面发现、URL 规则、HTTP 与浏览器抓取编排、GitHub ZIP 解析和重试能力。桌面端使用隔离 Electron 浏览器，CLI 使用本地 Playwright Chromium，服务端通过 `playwright-core` 连接 Browserless，并对 HTTP 与浏览器导航执行 SSRF 防护。
- 为什么：可选服务器可以集中维护公共技术文档，同时保留本地优先、离线可读和 Agent 只访问本机数据的使用方式；目录中的内容大小让用户能在下载前判断正文规模并与下载后的本地数据直接比较；单向同步避免引入账号体系、所有权和冲突合并复杂度。
- 边界 / 非目标：内容大小不表示 SQLite 文件占用、JSON 快照实际字节数或压缩后的网络流量；不提供普通用户账号、私有服务器文档、多租户权限、客户端内容上传、双向同步、Redis 或跨主机集群调度；浏览器服务不直接暴露公网，也不处理登录态、验证码、Cloudflare 挑战及其他反爬绕过能力。
- 权威入口：[Loci Server 部署与 API](../apps/server/README.md)、[共享 API 类型](../apps/desktop/src/shared/api.ts)。
