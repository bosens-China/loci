# Loci 产品 PRD

## 产品定位

- 当前决策：Loci 是面向 AI Agent 的本地文档知识库。用户提供公开文档页面后，应用发现同站页面、转换为 Markdown，并提供桌面浏览和本机 MCP 访问。
- 为什么：常用技术文档分散在不同站点，本地统一收录可以减少重复查找，并让人和 Agent 共享同一份可检查的数据。
- 边界 / 非目标：数据仅保存在本机；不提供远程同步、多用户权限、登录态抓取、代理池、原始 HTML、页面截图、历史版本、向量或语义检索。
- 权威入口：[README](../README.md)、[Agent 使用 Skill](../skills/use-loci/SKILL.md)。

## 文档源与页面发现

- 当前决策：用户可以从任意公开文档页创建文档源，该 URL 统一称为“第一个页面”，不要求是网站首页。
- 当前决策：文档源以第一个页面完成跳转后的 hostname 为边界，默认不包含子域名；相同 hostname 只维护一个文档源。
- 当前决策：首次抓取通过 Sitemap 和页面内链接发现 URL；后续更新同时刷新已保存页面并继续发现新页面。Sitemap 不可用时仍可依靠链接递归发现。
- 当前决策：URL 入队前移除 Fragment 和全部 Query，完成标准化与去重。每个文档源默认最多发现 1,000 个唯一 URL，用户可以修改上限。
- 当前决策：文档源保存抓取方式、页面上限、可选的 HTTP 与浏览器并发覆盖值和定时计划；首次成功读取入口页后保存网站图标 URL。
- 为什么：允许从具体页面开始能降低配置门槛；hostname 边界、去重和数量上限可以避免误抓外站、循环和失控扩张。
- 边界 / 非目标：达到上限后不再加入新 URL，但继续完成已入队页面和已有页面更新；页面仅从 Sitemap 或链接中消失时不自动删除。

## 抓取方式与可靠性

- 当前决策：自动模式仅对第一个页面同时执行 HTTP 直取和隔离的隐藏浏览器渲染，并比较统一转换后的 Markdown；结果足够接近且浏览器结果没有明显增益时使用 HTTP，否则使用浏览器。
- 当前决策：自动检测结果作用于整个文档源。用户可以手动指定或重新选择抓取方式，后续页面不逐页双通道检测，也不自动回退。
- 当前决策：全局 HTTP 与浏览器默认并发分别为 9 和 2，允许在设置中修改；文档源可分别提供 1 至 32 的可选覆盖值，留空时继承对应全局值。
- 当前决策：单次抓取尝试 30 秒超时，失败后最多重试 3 次。网络错误、超时、HTTP 408、429 和 5xx 可重试，429 优先遵守 `Retry-After`。
- 当前决策：更新失败保留旧 Markdown 和抓取时间；新页面失败不创建记录；明确返回 404 或 410 时删除页面及其全文索引。
- 为什么：优先选择更轻量的 HTTP 路径，同时保证依赖客户端渲染的文档站能够被完整收录；失败保护避免一次异常破坏已有知识库。
- 边界 / 非目标：浏览器窗口禁用 Node 集成并启用上下文隔离和沙箱，禁止弹窗、下载、权限申请及无关导航；不额外控制请求间隔。

## 本地内容与知识库浏览

- 当前决策：每个成功页面维护标题、标准化 URL、最近成功抓取时间、Markdown、HTML `lang` 和实际抓取方式；缺少语言标签时使用 `und`。
- 当前决策：SQLite 保存文档源与页面，FTS5 索引标题和 Markdown 正文。不保存独立树结构，界面根据 URL 路径动态生成目录树。
- 当前决策：知识库页面提供 URL 树、Markdown 预览和正文关键词过滤。过滤结果保留命中页面的祖先层级并自动展开，清空关键词后恢复完整树。
- 当前决策：文档树侧边栏拥有独立滚动区域，不带动正文预览；产品不提供独立的全文搜索页面。
- 为什么：最小字段足以支持本地浏览和 Agent 阅读；由 URL 派生树可以避免维护重复层级数据。
- 边界 / 非目标：数据库可以增加主键和文档源外键作为内部关联字段，但不扩展新的页面产品字段。

## 更新、调度与应用生命周期

- 当前决策：用户可以手动更新文档源；同一文档源同一时间只运行一个抓取任务，并通过实时进度和节点关系图查看状态。
- 当前决策：定时抓取默认关闭，仅在用户配置并启用后运行。文档源页面使用“文档源”和“定时更新”两个 Tab，后者集中列出已设置计划的文档源并提供空状态和编辑入口。
- 当前决策：关闭主窗口后应用驻留托盘，已启用的定时任务继续运行；从托盘显式退出时停止应用和调度器。
- 为什么：集中管理计划便于发现和修改自动任务；驻留托盘保证定时更新不依赖主窗口保持打开。
- 边界 / 非目标：不为定时更新新增侧边栏菜单；手动任务与定时任务不得相互覆盖。

## MCP 与 Agent 使用

- 当前决策：MCP 使用 Streamable HTTP，随 Electron 主进程启动且仅绑定 `127.0.0.1`。产品公开命名统一使用 `Loci`、`loci_*` 和 `Loci*`。
- 当前决策：MCP 使用“文档库”表示一个网站知识库，使用“文件”表示单个 Markdown 页面；提供添加、批量同步、同步状态、分页列表、目录、批量读取、关键词搜索和删除文档库八个工具。
- 当前决策：添加与同步默认异步启动并返回状态；Agent 可以轮询，也可以显式等待完成并接收进度通知。部分页面失败必须作为结构化结果返回，不掩盖已成功内容。
- 当前决策：目录使用稳定派生 ID 和渐进展开；文件使用数据库 ID。搜索返回最佳匹配段落、小节与来源，读取支持按小节和偏移量续读。
- 当前决策：全部工具提供输出 Schema，并同时返回可读文本和结构化内容。
- 为什么：渐进目录、定位搜索和按需读取可以控制上下文规模；异步任务避免长时间阻塞 Agent 调用。
- 边界 / 非目标：MCP 不允许单独删除同步文件，只允许永久删除整个文档库；非本机 Host 或 Origin 不得访问。
- 权威入口：[Agent 使用 Skill](../skills/use-loci/SKILL.md)、[共享 API 类型](../src/shared/api.ts)。

## 设置与本地数据

- 当前决策：设置页分别保存 MCP 端口、HTTP 默认并发、浏览器默认并发和主题。每个区块独立异步保存并提供局部反馈，不阻塞其他设置。
- 当前决策：MCP 默认端口为 `37373`，允许范围为 1024 至 65535；切换前验证端口可用，失败时保留原服务和原设置。
- 当前决策：主题支持自动、浅色和深色；自动模式跟随系统并响应变化，保存后立即应用并在重启后保留。
- 当前决策：SQLite 数据库位于 Electron 用户数据目录，本机 MCP 与桌面界面直接复用同一份数据和抓取任务。
- 为什么：局部保存缩短可感知等待时间，也避免无关设置互相阻塞；单一数据源防止桌面端与 Agent 结果不一致。
- 边界 / 非目标：当前版本不设计远程同步表、供应商抽象或服务器数据包格式。
